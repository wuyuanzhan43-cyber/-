  **配置步骤**（以 GPIO 外部中断为例）：
  1. **开 GPIO 时钟**（`__HAL_RCC_GPIOA_CLK_ENABLE` 等），配置 GPIO 为**输入**。
  2. **配置 EXTI**：把 GPIO 映射到 EXTI 线（`SYSCFG_EXTICR`）、选**触发边沿**（上升/下降/双沿）、使能该类 EXTI 触发。
  3. **配置 NVIC**：使能对应**中断号**（`HAL_NVIC_EnableIRQ`）、设置**优先级分组**（抢占/子优先）与优先级。
  4. **写 ISR**：`EXTIx_IRQHandler` 里判断线、**清标志**（`EXTI->PR`/`HAL_GPIO_EXTI_IRQHandler`）、做处理（短、可重入）。
  **要点**：**优先级分组**统一设置（抢占决定嵌套）；**进入 ISR 清标志**否则反复触发；中断里**短、不阻塞**；优先级数值小=高。
why: |
  中断让 MCU"**事件驱动、不轮询**"，提高响应与效率。配置 **EXTI（边沿触发）+ NVIC（优先级/使能）+ ISR（处理）** 是基本功。
  重点：**优先级分组**（抢占/子优先，关系到**中断嵌套**）、**清中断标志**（否则死循环/反复触发）、**ISR 短且可重入**（把重活丢主循环/任务），以及**防抖动**（按键需消抖）。

## 深读

### 场景：按键中断“不触发” / “反复触发”

> 你用 GPIO 外部中断做按键，结果要么**按键没反应**，要么**进中断后出不来、一直触发**。问题出在哪？

**中断链路就是排查路线**：`GPIO 事件 → EXTI(边沿) → NVIC(使能/优先级) → 向量表 → ISR`。**每一环都可能是断点**。

### 一、排查链条（现象 → 定位 → 原因 → 改法）

**现象 A：完全不触发（按键没反应）**
1. 查 GPIO：是不是**输入**、有没有**开时钟**、复用/模式对不对？
2. 查 EXTI：GPIO 有没有**映射到 EXTI 线**（`SYSCFG_EXTICR`）、**触发边沿**对不对（上升/下降/双沿）？
3. 查 NVIC：**中断有没有使能**（`HAL_NVIC_EnableIRQ`）、中断号对不对？
4. 查 ISR：中断服务函数**路径对不对**（`EXTIx_IRQHandler`）、是不是用了正确的线？

**现象 B：反复触发（进中断出不来）**
1. 查**清标志**：进入 ISR 后有没有清 `EXTI->PR` / 调 `HAL_GPIO_EXTI_IRQHandler`？**没清标志 → 中断一直挂起 → 反复触发/死循环**。
2. 查边沿：如果电平一直是触发态（如按住），可能持续触发 → 看是否需要**消抖**或改成**下降沿**。

> **记住优先级**：配置顺序里 **开着时钟 → GPIO→EXTI→NVIC→写 ISR→清标志**，任何一环漏了都出问题。

### 二、体系推导 / 记忆链（把相关点串成一条线）

```
GPIO 输入(按键/传感器)
  → EXTI(边沿检测: 上升/下降/双沿，SYSCFG 映射线)
  → NVIC(使能中断号 + 优先级分组: 抢占/子优先)
  → 向量表(中断号 ↔ handler)
  → ISR: 判断是哪条线 → 清标志(EXTI->PR) → 短处理 → 返回
```

一条链把 **GPIO 复用、EXTI 边沿、SYSCFG、NVIC 优先级、向量表、清标志、短 ISR** 全串起来。

### 三、时序 / 状态机（中断的“状态迁移”）

```
[主循环/任务] --[按键边沿]--> EXTI 置位挂起 -> NVIC 判优先级
  -> 若可抢占：保存当前上下文，跳到 ISR
  -> ISR: 清标志 + 处理 -> 返回
  -> 恢复上下文，回到被打断处
```

- **嵌套**：ISR 期间更高**抢占优先级**到来 → 再次保存上下文、进更高 ISR（嵌套），处理完逐层返回。
- **同级/子优先**：不嵌套，只按顺序。

### 四、数据结构 / 布局（优先级分组）

- **优先级分组（`NVIC_PriorityGroupConfig`）**：把优先级位分成**抢占优先级 + 子优先级**（如 `4/4` = 4 位抢占 + 4 位子优先）。
- **抢占优先级**：决定**能否嵌套打断**（数值小=高）。
- **子优先级**：同抢占级下多个中断同时到时的**处理顺序**（不嵌套）。
- **数据分布**：`EXTI->PR`（挂起标志寄存器，置位表示该线有事件）、`EXTI->IMR`（中断屏蔽）、`EXTI->RTSR/FTSR`（上升/下降沿触发选择）。

### 五、工程踩坑与改法

- **坑：忘清中断标志** → 反复触发/死循环 → ISR 里先清 `EXTI->PR`（或调 HAL 的 `EXTI_IRQHandler`）。
- **坑：优先级分组不一致** → 嵌套行为乱（有的地方配了不同分组）→ 初始化**统一**设分组。
- **坑：ISR 里做重活/阻塞**（打印、延时、解析）→ 丢事件、实时差 → **只做短、原子、可重入**，重活丢主循环/任务。
- **坑：按键抖动**（按下瞬间多次边沿）→ **软件消抖**（连续确认 N 次一致性）或硬件 RC。
- **坑：边沿选错**（上升/下降）→ 触发时机不对 → 按需求选边沿。

### 六、常见追问与满分回答

**Q：中断和轮询的区别？**
A：中断是**事件驱动**（发生才处理、省 CPU、实时好）；轮询是**忙等查询**（一直查、占 CPU、实时差）。高频/波形适合中断，简单低频可轮询。

**Q：EXTI 干什么？**
A：**检测 GPIO 边沿**（上升/下降/双沿）并触发中断，把 GPIO 事件"翻译"成中断。要配好 `SYSCFG` 映射 + 触发边沿 + 使能。

**Q：优先级分组怎么理解？**
A：`NVIC_PriorityGroupConfig` 把优先级位数一分为二：**抢占优先级**（决定能否**嵌套**）+ **子优先级**（同抢占下的**先后**）。数值小=高。

**Q：为什么 ISR 要很短？**
A：ISR 长了会**丢其他中断、增大中断延迟、影响实时性**；且中断上下文**不能阻塞/调度**。所以只做"置标志/读寄存器/发事件"，重活丢主循环/任务。

> 📌 一句话记忆：**中断链路=GPIO→EXTI(边沿)→NVIC(使能/优先级)→向量表→ISR(清标志+短处理)；不触发查 时钟/映射/边沿/使能/ISR，反复触发多为没清标志；抢占决定嵌套，子优先定顺序。**
