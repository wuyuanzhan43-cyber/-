answer: |
  **MCU（如 STM32）32 位地址空间**按区域映射：
  - **Flash**（`0x08000000` 起）：**代码/只读**，掉电不丢，启动从向量表/复位地址取指。
  - **SRAM**（`0x20000000` 起）：**数据/栈/堆**，掉电丢。
  - **外设**（`0x40000000` 起）：**外设寄存器**（GPIO、UART、TIM…），通过地址访问。
  - **系统**（`0xE0000000` 起）：内核外设（NVIC、SysTick、SCB…）。
  **启动**：复位后从 **Flash 起始（向量表）** 读初始 SP/PC，跳到启动代码，把 `.data` 拷到 SRAM、清 `.bss`、设栈。
  **链接脚本/启动文件**：定义**段地址**（代码放 Flash、data/bss/栈堆放 SRAM），配合启动文件做初始化。
  **存储**：**Flash**（可改写、存代码/配置，需擦除/写）、**EEPROM**（少量可擦写）、**SRAM**（RAM）。**ROM/Flash** 掉电保，RAM 易失。
why: |
  **理解地址映射**才能：**启动加载**（从 Flash 取指）、**访问外设寄存器**（按地址读写）、**写链接脚本**（划段）、**安排内存**（代码 Flash/数据 RAM）。
  **0x0800 Flash / 0x2000 SRAM / 0x4000 外设 / 0xE000 内核**是 STM32 常用地址基址，是裸机/固件开发的“内存地图”。搞清它才能定位**启动不了、全局变量初值错、访问外设不对**等问题。

## 深读

### STM32 地址映射（示意）

| 区域 | 基址 | 内容 |
|---|---|---|
| Flash | `0x08000000` | 代码/只读（掉电不丢） |
| SRAM | `0x20000000` | 数据/栈/堆（易失） |
| 外设 | `0x40000000` | GPIO/UART/TIM 等寄存器 |
| 系统 | `0xE0000000` | NVIC/SysTick/SCB（内核） |
| 别名/位带 | `0x22000000`/`0x42000000` | 位带别名（SRAM/外设） |

### 启动与链接脚本

- 复位：读 Flash 起始向量表**初始 SP/PC** → 跳 Reset_Handler。
- 启动文件：**拷贝 .data（Flash→SRAM）**、**清 .bss**、**设栈**，跳到 main。
- **链接脚本（.ld）**：定义 **Flash/RAM 段地址**与段内容（`.text/.rodata` 放 Flash，`.data/.bss` 放 SRAM），提供 `__data_start/__bss_start` 等符号。

### 存储区别

| 存储 | 易失性 | 用途 |
|---|---|---|
| Flash | 非易失（改需擦/写） | 代码、配置、掉电保持 |
| EEPROM | 非易失（可擦写） | 少量配置/参数 |
| SRAM | 易失 | 变量/栈/堆 |

- Flash 写入需**擦除（块）+ 编程**；SRAM 直接读写快。

### 常见坑

- 地址/段没对上（链接脚本）→ 启动失败/全局变量初值错。
- 外设地址访问错（段/偏移）→ 外设不工作。
- 栈/堆溢出（SRAM 用尽）→ 崩。

### 常见追问

- STM32 从哪里启动？——Flash（`0x0800...`）向量表；`BOOT` 可选介质。
- .data 为什么拷到 SRAM？——代码在 Flash，运行时要改的全局变量要有初值，拷到 SRAM。
- 外设怎么访问？——按映射地址读写寄存器（如 `*(volatile uint32_t*)0x40000000`）。
- Flash/SRAM/外设地址？——0x0800/0x2000/0x4000（STM32 常用基址）。

> 📌 一句话记忆：**MCU 内存地图：Flash 0x0800(代码/只读)、SRAM 0x2000(数据/栈)、外设 0x4000(寄存器)、内核 0xE000；启动从 Flash 向量表，链接脚本划段。**
