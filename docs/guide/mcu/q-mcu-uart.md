answer: |
  **MCU 串口（UART/USART）外设**：配置**波特率、数据位/停止位/校验**、使能 **TX/RX**；读写**数据寄存器（DR）**。
  **发送**：写 DR（/发送缓冲）；**接收**：读 DR（接收缓冲）。状态由**状态寄存器**（TXE 发送空、RXNE 接收非空）指示。
  **收发方式**：
  - **轮询**：简单但占 CPU（等发送/接收）。
  - **中断**：TX/RX 中断触发，**接收中断**攒到**环形缓冲**，主循环/任务处理；发送中断逐字节发。
  - **DMA**：批量收发，CPU 几乎不参与（适合大数据/高速），配**完成中断**。
  **波特率**：`波特率 = 总线时钟 / (分频)`；配错→乱码。
  **实战**：接收用**中断/DMA + 环形缓冲**避免丢字节；处理放主循环/任务；注意**短、可重入**（中断里只存字节）。
why: |
  MCU 串口是最常用**调试与通信**口。核心是**波特率/帧格式配置**与**高效收发**：
  - **轮询**收发会**阻塞/丢数据**；用**中断/DMA + 环形缓冲**实现**非阻塞、不丢字节**。
  - 接收中断只“存字节”，**解析/处理放主循环**（短中断、解耦）。
  - **波特率不对→乱码**；**阻塞读→丢数据**。理解这些才能写可靠串口。

## 深读

### 配置要点

```c
// HAL 串口配置示例
huart.Instance = USART1;
huart.Init.BaudRate = 115200;
huart.Init.WordLength = UART_WORDLENGTH_8B;
huart.Init.StopBits = UART_STOPBITS_1;
huart.Init.Parity = UART_PARITY_NONE;
HAL_UART_Init(&huart);
```

- **波特率、字长、停止位、校验** 需与对端一致。
- 收发靠 **DR**（数据寄存器）/ 状态位（TXE/RXNE 等）。

### 三种收发方式

| 方式 | 特点 | 用途 |
|---|---|---|
| 轮询 | 简单、占 CPU | 低频/调试 |
| 中断 | 事件驱动、较省 CPU | 常规收发 |
| DMA | 批量、几乎不占 CPU | 大数据/高速 |

### 中断 + 环形缓冲（推荐）

- **接收中断**：只把字节写入**环形缓冲**（快、可重入），主循环/任务**解析/处理**。
- 避免：在中断里做长时间解析（拖长中断）；一次性阻塞读（丢字节）。
- **发送中断/DMA**：逐字节/批量发送，避免忙等。

### 波特率与乱码

- 波特率由**总线时钟分频**算出；与对端不一致 → 采样错位 → 乱码。
- 更换时钟树/主频后要**重新计算波特率**（否则乱码）。

### 常见追问

- 轮询 vs 中断收发的取舍？——轮询简单占 CPU；中断/DMA 省 CPU、不丢字节。
- 为什么中断里只存字节？——短、可重入；解析放主循环避免拖长中断。
- 为什么用环形缓冲？——固定缓冲、无碎片、单写单读无锁，避免丢数据。
- 波特率为什么乱码？——时钟分频/波特率与对端不一致。
- 帧格式/波特率/电平/流控详见`UART 深入（q-uart-deep）`。

> 📌 一句话记忆：**串口=配波特率/帧格式+DR收发；轮询占CPU、中断/DMA+环形缓冲高效不丢字节；接收中断只存、处理放主循环；波特率不匹配乱码。**
