answer: |
  **量化（Quantization）**：把神经网络模型的**权重**和**激活张量**从 **float32** 映射到 **int8**（8bit 整数），用一组**线性映射参数 + 舍入**去逼近浮点值，从而换取**更小的内存、更低的功耗、更快的推理**（尤其适合 MCU）。

  **核心数学**：每个张量配一对参数 __scale__（缩放）与 __zero_point__（零点偏移），量化与反量化公式：
  - 量化：`q = round(real / scale) + zero_point`（把浮点 `real` 映射到整数 `q`）
  - 反量化：`real = scale * (q - zero_point)`
  - `scale = (real_max - real_min) / (q_max - q_min)`，`zero_point` 对齐到整数上限/下限。

  **校准（calibration）**：`scale/zero_point` 不是拍脑袋定的。**激活**的数值范围在推理前未知，所以要用一组**有代表性的输入数据（校准数据集）**先跑一遍模型，统计**每层激活的实际数值分布**，再用策略选阈值：
  - **min/max 法**：直接取该层激活的最小/最大值做范围（简单，但易被离群点拉大范围、损失精度）。
  - **KL 散度（KL divergence）法**：在多个候选阈值里，选一个让「量化前后的分布差异（KL 散度）」最小者（更准，是 TensorFlow 的经典做法）。

  **精度损失来源**：① 量化**本身有舍入误差**；② 范围取得太大，小值被压扁；③ 某些层（如对数值范围极敏感的 BN/残差）对量化敏感。缓解手段：**量化感知训练（QAT，训练时模拟量化损失）**、**per-channel 量化**、**逐层校准**。

  **per-tensor vs per-channel**：per-tensor 整层共用一组 scale（简单）；per-channel 每个输出通道一组 scale（更准，但稍复杂、算子支持要看平台）。
why: |
  面试官问「为什么用 INT8 不用 float32」要答到**本质**：MCU **算力低、内存小、常跑电池供电**，int8 权重比 float32 **省 4 倍内存**，**乘法运算在部分内核上更快/功耗更低**；代价是**精度损失**，所以要**校准（calibration）**去最小化损失。能说清「scale/zero_point 怎么来、精度损失在哪、怎么缓解（QAT/per-channel/KL）」就是懂量化，而不是只会背「INT8 更省」。

## 深读

### 一、为什么 MCU 上要用量化（本质）

- **内存**：float32 权重 4 字节，int8 只要 1 字节 → **模型体积缩到 1/4**，能塞进 MCU 的几百 KB RAM/Flash。
- **算力/功耗**：int8 的乘加在部分 MCU（尤其带扩展指令的）更快、更省电。
- **代价**：精度损失 → 需要**校准** + 可能用**量化感知训练（QAT）**补偿。

### 二、量化公式怎么理解

假设某层权重在 `[-1.0, 1.0]`，要映射到 int8 的 `[-128, 127]`：

```
scale = (1.0 - (-1.0)) / (127 - (-128)) = 2.0 / 255 ≈ 0.00784
zero_point = -128 - (-1.0 / 0.00784) ≈ 0
q = round(real / scale) + zero_point
```

- `real=0.0` → `q = round(0/0.00784) = 0`
- `real=1.0` → `q = round(127.5) ≈ 127`（上限）
- `real=-1.0` → `q ≈ -128`（下限）

反量化 `real = scale*(q - zero_point)` 能还原到**近似**浮点值，误差来自 `round`。

### 三、校准为什么用 KL 散度（重点）

- **min/max**：简单，但如果激活有**一个极端离群值**，范围被拉得很大，其他值被迫压得很扁 → 精度差。
- **KL 散度**：把量化后的分布和原分布做比对，**挑一个让信息损失最小的阈值**，不是只看最大值。TensorFlow 的经典量化校准就用它。

> 💡 一句话：**min/max 是「用极值定范围」，KL 是「用分布失真最小定范围」，后者在长尾/离群数据下明显更稳。**

### 四、精度损失的来源与缓解（必答）

| 损失来源 | 说明 | 缓解 |
|---|---|---|
| 舍入误差 | `round` 天然有误差 | 接受，或用 QAT 训练补偿 |
| 范围过大 | 离群点拉大范围，小值被压扁 | 用 KL、去掉极端离群、per-channel |
| 敏感层 | BN/残差/某些激活对量化敏感 | 逐层校准、保留浮点（混合精度） |
| 量化感知训练 | 训练时就模拟量化误差，让网络适应 | **QAT** |
| per-channel | 每通道一组 scale，比 per-tensor 准 | 用 per-channel（算子支持时） |

### 五、常见追问与满分回答

**Q：INT8 比 float32 好在哪？**
A：**内存省 4 倍**、部分内核**更快/更省电**，适合低算力小内存的 MCU；代价是精度损失，靠**校准 + 可能 QAT** 弥补。

**Q：scale 和 zero_point 怎么来的？**
A：**scale 由数值范围决定**（`(max-min)/(q_max-q_min)`），**zero_point 对齐整数零**；激活的范围要靠**校准数据集跑一遍统计**，用 **min/max 或 KL 散度** 挑阈值。

**Q：为什么用 KL 散度校准？**
A：min/max 只认极值，离群点会把范围拉大、精度变差；**KL 挑「量化前后分布失真最小」的阈值**，更贴合真实分布。

**Q：量化后精度低了怎么办？**
A：① 用 **KL 校准** 而不是 min/max；② **per-channel**；③ **量化感知训练（QAT）**；④ 对敏感层保留浮点（混合精度）。

**Q：per-tensor 和 per-channel 区别？**
A：per-tensor 整层一组 scale（简单）；per-channel **每输出通道一组**（更准），但算子支持与开销略高。

> 📌 一句话记忆：**量化=用 scale+zero_point 把 float32 映射成 int8；scale 由范围定、激活范围靠校准集统计（min/max 或 KL 散度）；代价是精度损失，靠 QAT / per-channel / 逐层校准补；收益是 4 倍省内存 + 快 + 省电。**
