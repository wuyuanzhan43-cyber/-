## 深读

### 场景：串口“乱码”

> 你用 MCU 串口接一个模块/上位机，收到一堆乱码、偶尔丢字节，或有数据但值不对。怎么定位？

**UART 是异步、无时钟线，全靠“波特率 + 帧格式 + 电平标准”对齐。** 乱码三板斧按顺序查：**波特率、帧格式、电平/接法**。

### 一、排查链条（现象 → 定位 → 原因 → 改法）

**现象 A：全是乱码（每个字符都不对）**
1. **查波特率**：`波特率 = 时钟 / 分频`，两边的**波特率/帧格式**必须一致。波特率不对 → 采样错位 → 乱码。
2. **查帧格式**：数据位（5/7/8）、停止位（1/1.5/2）、校验（无/奇/偶）**两边一致**。
3. **查电平/接法**：`TX↔RX` 交叉？TTL vs RS232(±12V)/RS485(差分) 是否匹配、有没有电平转换；RS485 是否**方向控制**（发完切收）。
4. **查时钟稳定**：系统时钟/分频配错，波特率偏移 → 高波特率更明显。

**现象 B：偶尔丢字节 / 值不对**
1. **查接收方式**：阻塞读（轮询）容易丢 → 用**中断/DMA + 接收缓冲**。
2. **查流控**：对端发太快，没流控（RTS/CTS 或 XON/XOFF）→ 丢数据。
3. **查缓冲区**：缓冲太小/溢出，或没及时取走 → 丢帧。

### 二、体系推导 / 记忆链（把相关点串成一条线）

```
波特率 = 系统时钟 / (分频)
  └─ 决定每位时长；收发必须一致
帧格式：起始(0) + 数据(5~8) + 校验(可选) + 停止(1/1.5/2)
  └─ 决定怎么解析一个字节
电平标准：TTL(3.3/5V短距) | RS232(±12V单端长距,需MAX232) | RS485(差分,多点,半双工,需方向控制)
收发：轮询(占CPU) / 中断(事件驱动) / DMA(批量) + 接收缓冲
```

一条链把 **时钟/分频、波特率、帧格式、电平标准、流控、收发方式/缓冲** 全串起来。

### 三、状态机 / 流程（收一帧的过程）

```
空闲(高) -> 起始位(0) -> 采样 D0..D7(波特率/16,取中间) -> 校验位 -> 停止位 -> 一帧完成
```

- 接收方在**每位中间采样**（避免边沿误差），一旦起始位确认，按波特率采每一比特。
- 波特率/帧格式错 → 采到的时间点对不上 → 数据错。

### 四、参数 / 公式

- **波特率 = 时钟频率 / 分频系数**（如 72MHz 时钟，分频 625 → 115200）。
- 接收采样：**波特率 / 16**，在每位中间取稳定点。
- **换主频/时钟树后要重算波特率**，否则偏移导致乱码。
- 帧率/吞吐：`字节/s ≈ 波特率 / (起始位 + 数据位 + 校验位 + 停止位)`，即**起始+数据+校验+停止**的总位数决定有效吞吐（一帧的总位数）。例如 **115200、8N1**（1 起始 + 8 数据 + 0 校验 + 1 停止 = 10 位）→ 约 **11520 B/s**。

### 五、『流控』讲透：三种选择各会怎样（重点）

**流控是干什么的？** 串口是**异步、无握手**的，发送端按波特率往外发，接收端必须**按同样速率消费**才能接住。如果发送端**发得比接收端处理快**，接收端**RX 缓冲溢出 → 丢字节**。流控就是让**“消费慢的一方”通知“生产快的一方”先停一停**，避免溢出丢数据。本质是**匹配“生产速率”与“消费速率”**。

**三种选择各自会怎样：**

**① 不流控（无）**
- **适用**：简单调试、低频/少量、接收端处理能力足够。
- **会怎样**：数据量大/一次性突发，或接收端忙于别的事没及时取走 → **RX 缓冲溢出 → 丢字节/尾部截断**。
- **表现**：高速大量传输时开始丢数据，往往恰好丢在“某段忙处理”的时候。
- **结论**：**对端持续高速 + 你处理不过来时，无流控必丢数据**；低频/少量则无所谓。

**② 软件流控 XON/XOFF**
- **做法**：接收端缓冲快满发 **XOFF(0x13)** → 发送方**暂停**；缓冲有空间再发 **XON(0x11)** → 恢复。
- **优点**：**不加线**，数据线即可。
- **会怎样 / 坑**：
  - 控制字符**占用数据流**——传输**二进制**时，若数据里正好有 `0x11/0x13`，会被**误认成流控** → **数据截断/错乱**。所以**二进制/任意字节数据不能用 XON/XOFF**，要转义或换 RTS/CTS。
  - 是“**软**”的、有延迟：发 XOFF 时发送方可能已又发了几字节，**缓冲要能吸收**，否则仍会溢出。
  - 速度慢（控制字符走同一条数据线），且要求**协议避开那两个字节**或软件支持。
- **适用**：**文本/ASCII 数据**（不含 `0x11/0x13`）、想省线的场合。

**③ 硬件流控 RTS/CTS**
- **做法**：接收端用 **RTS**（“我可接收”）信号，发送端看 **CTS** 决定是否发；缓冲快满拉低 RTS → 发送端见 CTS 变低停发。
- **优点**：**精确、快、与数据字节无冲突**（专用引脚），适合大量/高速/连续。
- **会怎样 / 坑**：
  - 需要**额外引脚/走线**（RTS/CTS，双向 4 线），**双方都要配置并物理连接**。
  - 一端**没配/不支持/接错** → 可能**一直等 CTS 不发**（卡死/无数据），或**从不等 CTS**（形同虚设、照样丢）。
  - **接反/悬空** → 行为异常（“发不出去”或“丢数据”）。
- **适用**：**大数据量、高速、要求不丢**的可靠通信。

**怎么选（决策表）**

| 场景 | 选 |
|---|---|
| 调试/日志/低频小量 | 无流控（最简） |
| 文本数据、想省线 | XON/XOFF |
| 二进制/大量/高速、不丢 | RTS/CTS |
| 二进制且没法加线 | 转义编码 + 大缓冲 |

**本质**：**流太快/处理太慢 → 缓冲溢出丢数据；流控就是让“慢的一方”喊停，让生产与消费速率匹配。** 三种选择无非在“**省线 vs 精确可靠**”之间取舍：**无流控=最省最简但会丢；XON/XOFF=省线但怕二进制字节冲突、有延迟；RTS/CTS=精确可靠但费线、双方都要支持。**

### 六、数据结构 / 布局（帧与缓冲）

- **帧**：`起始位 + D0..Dx + 校验 + 停止`——**字节布局**由帧格式决定（8N1 等）。
- **接收缓冲**：用**环形缓冲**（固定数组 + 头尾指针），中断里只存字节、主循环解析；**单写单读可无锁**。
- **DMA 缓冲**：批量收发，需**地址/长度对齐 + 完成中断**。

### 七、工程踩坑与改法

- **坑：波特率/帧格式不一致** → 乱码 → 统一；换时钟树后**重算波特率**。
- **坑：TX/RX 没交叉**、或 **TTL 直接接 RS232**（电平不符）→ 不识别/乱码 → 正确接法 + 电平转换（MAX232/RS485 收发器）。
- **坑：阻塞读丢数据** → 用**中断/DMA + 环形缓冲**，中断只存字节。
- **坑：对端太快要流控** → 加 **RTS/CTS** 或 **XON/XOFF**。
- **坑：RS485 半双工没切方向** → 发完必须**切回接收**（DE/RE），否则收不到/冲突。

### 八、常见追问与满分回答

**Q：乱了码先查什么？**
A：先查**波特率**（时钟/分频）、再查**帧格式**（数据/停止/校验位），两边是否一致；再查**电平/接法**（TX/RX 交叉、TTL/RS232/RS485 匹配）；最后查时钟/分频（换主频要重算）。

**Q：波特率怎么算？**
A：`波特率 = 时钟频率 / 分频系数`；收发双方必须一致，否则采样错位乱码。换时钟树/主频后要重新计算。

**Q：为什么丢字节？**
A：接收太慢（轮询/阻塞读）或**对端太快无流控**、**缓冲太小**。改：**中断/DMA + 环形缓冲**，必要时加流控（RTS/CTS）。

**Q：什么时候要用流控？无流控会怎样？**
A：当**发送端可能发得比接收端处理快**时（大量/突发/接收端忙），**无流控 → RX 缓冲溢出丢数据**。所以要**匹配生产与消费速率**：低频少量/处理能力足够可无流控；持续高速/大量则必须流控。

**Q：XON/XOFF 和 RTS/CTS 怎么选？**
A：**省线**选 XON/XOFF（但**别用于二进制**——数据里的 `0x11/0x13` 会被误判成流控、数据被截断；且有延迟）。**精确、大批量/高速/不丢**选 RTS/CTS（费线，双方都要支持并接好）。**二进制且没法加线** → 转义编码 + 大缓冲。

**Q：TTL/RS232/RS485 区别？**
A：TTL=3.3/5V、短距、MCU 直接；RS232=±12V、单端、中距（需 MAX232）；RS485=差分、多点、长距、**半双工**（需方向控制）。**电平/接法不匹配 → 不识别/乱码**。

> 📌 一句话记忆：**乱码先查“波特率(时钟/分频)+帧格式”两边是否一致，再查“TX/RX 交叉+电平(TTL/RS232/RS485)”；丢字节是“发送比接收快→缓冲溢出”，用“中断/DMA+环形缓冲+流控”；流控选型=无(最简但会丢)/XON-XOFF(省线但别用于二进制)/RTS-CTS(精确可靠但费线)；换主频要重算波特率。**

### ★ 参考题解精华

> 本节提炼自一份高质量 **USART/UART 面试题集**，只收录我们上方**尚未讲透/未覆盖**的高价值点；已详讲的部分（流控三选一、TTL/RS232/RS485 电平、乱码/丢字节排查等）用一句交叉引用，不重复。

#### 一、UART vs USART（为什么叫 USART）

| | UART | USART |
|---|---|---|
| **全称** | Universal **Asynchronous** R/T | Universal **Synchronous/Asynchronous** R/T |
| **时钟线** | 无（纯异步） | 同步模式下多一根 **CLK** 线 |
| **同步模式** | 不支持 | 支持（SPI-like 主从同步） |
| **关系** | 只含异步 | **UART 的超集**，异步模式下完全兼容 |

- STM32 全系是 **USART** 外设，但工程里几乎只用它的**异步模式**（当 UART 用）。
- **同步模式基本不用**——SPI 时钟更高、全双工更自然、生态更好，同步串口需求早被 SPI 取代。
- 💡 面试：问“为什么叫 USART 不叫 UART？”→ 因为它是 **UART 超集**，只是我们只跑了它的异步子集。

#### 二、UART 帧格式详述（一张图 + 每段长度 + 帧简写）

```
空闲 | S | D0 | D1 | D2 | D3 | D4 | D5 | D6 | D7 | P | Stop | 空闲/下一帧
      ↑                                                       ↑
    1bit LSB                                       1 / 1.5 / 2bit
       └──────── 数据段 5~9 bit ────────┘
```

| 部分 | 长度 | 作用 |
|---|---|---|
| **起始位 Start** | 1 bit（低） | 通知开始 + **同步**（接收方由下降沿启动接收时钟） |
| **数据位 Data** | 5~9 bit（常见 8） | 有效数据，**LSB 先发、MSB 后发** |
| **校验位 Parity** | 1 bit（可选） | Even / Odd / None |
| **停止位 Stop** | 1 / 1.5 / 2 bit（高） | 强制高电平回空闲；较长停止位给对端更多处理时间 |

- 帧简写：**8N1**（8 数据+无校验+1 停止，最常用）、**8E1**（偶校验）、**8O1**（奇校验）。
- 一句话：**一个起始位(低) + N 个数据位(LSB 先发) + 可选校验位 + 1~2 个停止位(高)**。（我们已有基础结构，这里补**每段长度 + LSB/MSB 顺序 + 帧简写**。）

#### 三、奇偶校验怎么算（Even/Odd 的本质）

- **规则**：对“数据位 + 校验位”整体统计 `1` 的**个数**。
  - **偶校验 Even**：`1` 总个数为**偶数**。
  - **奇校验 Odd**：`1` 总个数为**奇数**。
- 例：传 `0x35 = 0011 0101`，共 4 个 `1` → **偶校验位填 0**、**奇校验位填 1**。
- **局限**：只能发现**奇数个位翻转**——偶数个位同时翻转，`1` 的个数不变，校验不报错。所以校验是**廉价检错**，可靠检错要靠 CRC（见「七」）。
- 收发双方校验配置（无/奇/偶）必须一致，否则一方会认为**每字节都校验错（PE）**。

#### 四、波特率误差与采样（为何“不同版晶振”也能对上）

- **过采样**：接收方用**内部高速时钟**把每 bit 采成 **16×（或 8×）** 个点；起始位下降沿后延时 **0.5 bit** 定位到**位中心**，再每隔 1 bit 在**中心点**采样。
- **容限**：以 16× 过采样、8N1 为例，最后一位的采样点偏移不能超过 ±0.5 bit → 波特率偏差容忍约 **±5%**。MCU 内部 HSI 精度约 1%、外部晶振（HSE）约 ±20ppm，都够用。
- **STM32 波特率公式**（F4，默认 16× 过采样）：`Baud = fCK / (16 × USARTDIV)` → `USARTDIV = fCK / (16 × Baud)`。
  - 例：USART1 挂 APB2 @ **84MHz**，目标 **115200**：`USARTDIV = 84e6/(16×115200) ≈ 45.5729`。
  - 分解：**DIV_Mantissa = 45**；**DIV_Fraction = 0.5729×16 ≈ 9.17 → 取整 9**。实际波特率 ≈ **115225 bps**，**偏差 ≈ 0.02%**。
  - **关键认知**：USARTDIV 是**分数**（12bit 整数 + 4bit 小数，1/16 步进）；**偏差 = (实际−目标)/目标**，确认落在 ±5% 内。
- ⚠️ **换主频/时钟树后必须重算 DIV 的 mantissa/fraction**，否则整体偏移，高波特率先崩。

#### 五、115200 到底能传多少（别再用“字节×10”凑波特率）

- 8N1 一帧 = 1+8+1 = **10 bit**，有效数据 8 bit → 效率 **80%**。
  - `有效字节率 = 115200 / 10 ≈ 11520 B/s`；8E1 一帧 11 bit → `115200 / 11 ≈ 10472 B/s`。
- **别以为 115200 能传 115200/8 ≈ 14.4KB/s**；也别“要 20KB/s 就选 200000 Baud”——8N1 下 200000 Baud 约才 20KB/s。
- 连续高速推荐 **DMA**——否则每个字节一次中断，115200 时中断频率高达 **11.5kHz**，MCU 可能扛不住（这也呼应我们“中断/DMA 取舍”）。

#### 六、错误标志：FE / PE / ORE / NE（怎么触发、怎么清）

| 标志 | 含义 | 触发条件 |
|---|---|---|
| **FE** 帧错误 | 停止位采到低电平 | 波特率不匹配/时钟偏差/噪声把停止位拉低 |
| **PE** 校验错误 | 数据与校验位不匹配 | 噪声翻转数据位/双方校验配置不一致 |
| **ORE** 溢出错误 | 接收数据寄存器被覆盖 | 上一帧没及时读，新帧已到（中断/DMA 被阻塞） |
| **NE** 噪声错误 | 16 次采样多数表决不一致 | EMI，RX 线不稳定 |

- **ORE 最常见也最致命**：整帧丢失且不可恢复，说明系统**实时性不足**；FE/PE 偶发可容忍；**NE 频繁出现**说明布线/环境有问题。
- **清除顺序（硬件强制，不是软件惯例）**：
  - `读 SR → 读 DR` 清 **FE / PE / NE**；
  - **ORE 要再补一次 `读 SR`**（即 **读 SR → 读 DR → 再读一次 SR**，读两次 SR）。
  - 若直接读 DR 而不先读 SR，FE/PE/NE **永远清不掉**，下一字节照样置位。
- 中断里**先查错误标志再处理数据**，避免读到脏数据。

#### 七、错误检测选型：校验和 / CRC8 / CRC16

| | 校验和 | CRC8 | CRC16 |
|---|---|---|---|
| 计算 | 累加 / XOR | 查表 / 移位 | 查表 |
| 长度 | 1B | 1B | 2B |
| 检错 | 极弱 | 中 | 强 |
| 相邻换位 | **不能**（1+2+3=1+3+2） | 能 | 能 |
| 典型 | 简单配置（遥控器） | 传感器短帧（温湿度/IMU） | 关键控制（固件升级/电机） |

- **别把“校验和”和“CRC”混为一谈**：校验和是加减异或；CRC 是**多项式除法**的**循环冗余校验**，数学基础不同，检错能力**差一个数量级**。
- **选型决策**：仅影响显示→CheckSum/CRC8；短暂异常→CRC8；**不可逆损坏→CRC16**；**固件变砖→CRC16 + 多重校验 + 回滚**。**帧长 >8 字节→至少 CRC16**；8-bit MCU / ROM 紧张时避开 CRC16 查表（512B 表太大）。

#### 八、收发方式：轮询 / 中断 / DMA + IDLE（补“DMA+IDLE 流程”）

- 我们已有**三类收发取舍**（见 `q-mcu-uart`、`q-dma`），这里补**DMA 不定长接收的标配流程**：
  1. DMA **循环模式**持续搬字节到 buffer；
  2. UART **IDLE 中断**（一帧结束、RX 线恢复空闲）触发；
  3. 由 **DMA 剩余计数值 NDTR** 反推本次长度：`recv_len = BUF_SIZE − NDTR`；
  4. 处理**环形回绕**（`[last_pos, wptr)` 与 `[0, wptr)` 两段拼接，或真正环形索引）；
  5. 清 IDLE 标志（**读 SR → 读 DR**）→ **重置 DMA 指针**。
- **Buffer 至少 = 最长帧 × 2**（防解析跟不上接收），常取 256/512B。

#### 九、RTO 接收超时 vs IDLE（处理“IDLE 永远不来”）

| | IDLE 中断 | RTO 中断 |
|---|---|---|
| 触发 | 帧间空闲（RX 持续高） | 自定义**超时**（1~65536 bit 时间） |
| 最小间隔 | 1 整帧（10~11 bit） | 可设到 1 bit |
| 受噪声影响 | **大**（噪声拉低 RX→IDLE 不来） | 小 |
| 典型 | 干净总线、帧间明确空闲 | 噪声 / 低速 **Modbus RTU**（帧间隔≥3.5 字符） |

- **问题**：RX 线有持续串扰/接地反弹→永远低电平→**IDLE 永不触发**→DMA 不定长接收**死锁**。
- **RTO 方案**：写 `RTOR`（超时 bit 数）+ 使能 RTO 中断；RTO 触发后做**和 IDLE 一样的事**（取 DMA 剩余→算长度→解析→重置）。
- 最强：**DMA + IDLE + RTO 双保险**（IDLE 正常、RTO 兜底）；并**跳过“连续两次 RTO 收到相同长度”**（= 没新数据）。

#### 十、鲁棒帧解析（FSM 从脏字节流“打捞”有效帧）

- 示例帧：`帧头(0xA5 0x5A) + 长度 + 数据 + CRC8`；用**有限状态机**逐字节打捞。
- **双字节帧头**：单字节（如 0xAA）在数据段出现会产生假帧头；双字节把误判率降到 **1/65536**。
- **字节填充/转义**：数据段遇到 `0xA5 → 0x7D 0x01`、`0x7D → 0x7D 0x00`；接收反向还原（**SLIP/PPP 标准做法**），消除帧头歧义。
- **长度合理性检查**（Length>MAX 或 =0 → 丢弃）、**超时保护**（任状态停留超过 ~3×帧间隔 → 强制回 `STATE_HDR1`）。
- 帧/字段解析的深入题卡见 `q-bitfield-protocol`。
