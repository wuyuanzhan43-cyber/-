answer: |
  三种常见板级总线：
  - **I2C**：两根线（SDA 数据 + SCL 时钟），**半双工**、主从式、支持**一主多从**（7/10 位地址），**速度比 SPI 慢但分档**（标准 100kbps / 快速 400kbps / 高速 3.4Mbps），**挂多个低速外设**（传感器、EEPROM、RTC）很省线。
  - **SPI**：4 根线（SCLK + MOSI + MISO + CS），**全双工**、主从、**一主可多从**（用片选 CS 区分每个从设备），速率高（Mbps 级），适合**高速/大量数据**（Flash、DAC/ADC、显示屏、SD 卡），但线数多。
  - **UART**：**异步串行**，通常 2 根（TX + RX），**无时钟线**（需约定波特率），**点对点**、全双工，速率适中，适合**调试/日志/简单点对点**（串口终端、蓝牙模块、GPS）。
  选型口诀：**大量/高速数据 → SPI；多设备/省线/低速 → I2C；点对点异步/调试 → UART**。
why: |
  三者是“**时钟方式、线数、拓扑、速率、是否全双工**”的不同取舍。I2C 用两根线靠**协议寻址**挂多设备，省线但慢；SPI 用**片选 + 同步时钟**换高吞吐，但要 4 根线且每个从设备一根 CS；UART **无时钟**靠约定波特率、点对点，最简单但同步与多设备受限。
  选对总线能省 PCB 布线、满足速率与实时性，是嵌入式硬件设计的重要一步。

## 深读

### 速查对照表

| 维度 | I2C | SPI | UART |
|---|---|---|---|
| 信号线 | 2（SDA/SCL） | 4（SCLK/MOSI/MISO/CS） | 2（TX/RX） |
| 时钟 | 有（SCL） | 有（SCLK） | **无**（约定波特率） |
| 传输 | 半双工 | 全双工 | 全双工 |
| 拓扑 | 一主多从（寻址） | 一主多从（片选） | **点对点** |
| 多设备 | 支持（地址区分） | 支持（每从一根 CS） | 不支持（需多 UART/复用） |
| 速率 | 100k~3.4Mbps | Mbps~几十 Mbps | 常见 9600~115200（可更高） |
| 典型 | 传感器/EEPROM/RTC | Flash/屏/ADC/SD | 终端/日志/蓝牙/GPS |

### I2C 细节

- **开漏 + 上拉**输出，可集线（一条线挂多个设备）。
- 由**地址（7/10 位）+ 读/写位**寻址；支持多主（仲裁，较少用）。
- 短距离、低速、省线是它的强项。

### SPI 细节

- 全双工：发送与接收同时（MOSI/MISO）。
- 用 **CS（片选）** 拉低选从设备；一个从设备一根 CS。
- **CPOL/CPHA** 决定时序模式（0/1, 2/3），主从必须一致。
- 速率高，但线多、每从一根 CS。

### UART 细节

- **异步**：无时钟线，靠**波特率 + 起始/停止位**同步。
- 通常**点对点**；也可加 RS-485 转成多机半双工。
- 用**流控**（RTS/CTS）防丢包。

### 什么时候选哪个（落题）

- 挂**多颗低速小外设**、PCB 线紧张 → **I2C**。
- 需要**高速、大块数据**（读 Flash、采样、刷屏） → **SPI**。
- **调试/日志/与模块（蓝牙、GPS）点对点** → **UART**。

### 常见追问

- 为什么 I2C 用两根线能挂多个设备，SPI 却要每从一根 CS？——I2C 用**协议地址**区分，SPI 靠**片选**。
- SPI 能多从吗？——能，但一根 CS 一个从，IO 会增多；也可用 SPI 菊花链/共享（需设备支持）。
- UART 为什么需要约定波特率？——没有时钟线，必须双方按同一速率采样，否则错位。
- 什么是全双工/半双工？——全双工可同时收发（SPI/UART），半双工同一时刻只能一个方向（I2C）。

> 📌 一句话记忆：**I2C=2线省线挂多从（慢），SPI=4线全双工高吞吐（多从靠片选），UART=无钟点对点（调试/异步）。**
