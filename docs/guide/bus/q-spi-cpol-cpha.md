answer: |
  SPI 用 **SCLK（时钟）+ MOSI/MISO（数据）+ CS（片选）**。主从通过 **CPOL** 与 **CPHA** 约定时序，共 **4 种模式**：
  - **CPOL（时钟极性）**：空闲时 SCLK 的**电平**（0=低空闲，1=高空闲）。
  - **CPHA（时钟相位）**：数据在**哪个边沿采样**（0=第一个边沿采样，1=第二个边沿采样）。
  四种模式（采样/输出边沿）：
  - **模式0**：CPOL=0, CPHA=0 —— 空闲低，**第一个边沿（上升沿）采样**。
  - **模式1**：CPOL=0, CPHA=1 —— 空闲低，**第二个边沿（下降沿）采样**。
  - **模式2**：CPOL=1, CPHA=0 —— 空闲高，**第一个边沿（下降沿）采样**。
  - **模式3**：CPOL=1, CPHA=1 —— 空闲高，**第二个边沿（上升沿）采样**。
  **主从必须一致**：配置相同模式（很多外设固定某模式，如 `0`/`3`）。CPOL/CPHA 不匹配会导致采样错位、数据乱。
why: |
  主从双方**必须用同一套“何时采样、何时换线”的约定**，否则接收方在错误的边沿采样，或在数据还没稳定时就采样，产生乱码。CPOL 决定空闲电平（也影响第一个边沿方向），CPHA 决定采样边沿。
  嵌入式里常见坑：**SPI 主从 CPOL/CPHA 配置不一致 → 数据错位/乱码**，或读外设（Flash/传感器/屏）时模式设错。理解四模式与“采样边沿/空闲电平”，就能快速对齐主从时序。

## 深读

### 四模式速查

| 模式 | CPOL | CPHA | 空闲电平 | 采样边沿 |
|---|---|---|---|---|
| 0 | 0 | 0 | 低 | 第一个边沿（上升） |
| 1 | 0 | 1 | 低 | 第二个边沿（下降） |
| 2 | 1 | 0 | 高 | 第一个边沿（下降） |
| 3 | 1 | 1 | 高 | 第二个边沿（上升） |

### CPOL（时钟极性）作用

- `CPOL=0`：空闲时 SCLK 为**低**，第一个边沿是**上升沿**。
- `CPOL=1`：空闲时 SCLK 为**高**，第一个边沿是**下降沿**。
- 决定“空闲电平 + 第一个边沿方向”。

### CPHA（时钟相位）作用

- `CPHA=0`：数据在**第一个边沿**被采样。
- `CPHA=1`：数据在**第二个边沿**被采样（数据在第一个边沿变化、第二个边沿采样）。
- 决定“哪个边沿采样数据”。

### 为什么主从不一致会出错

- 若从设备要求模式0（上升沿采样），主设备配成模式1（下降沿采样）→ 采样时刻错开半个位周期 → **错位/乱码**。
- 所以**外设手册都会注明其 SPI 模式**（很多默认模式0或模式3），主设备必须配置一致。

### 嵌入式实践

- 读外设（Flash/传感器/显示屏）先查 databook 的 SPI 模式。
- 配置主控制器（如 STM32 SPI 的 CPOL/CPHA、或 Linux 的 `spi-mode` 设备树属性）。
- 若拿不准，先用**低速 + 示波器/逻辑分析仪**看波形对齐。

### 常见追问

- 模式0 和 模式3 是 CPOL 不同但都是什么对应？——模式0（低空闲，上升采样）、模式3（高空闲，上升采样）——很多设备用其中一种。
- 采样边沿 vs 输出边沿？——CPHA 决定采样边沿；数据通常在另一个边沿变化。
- 怎么快速背？——CPOL 看空闲电平（0低1高），CPHA 看采样边沿（0第一1第二）；主从必须一致。

#### 1. 为什么 SPI 是全双工：移位寄存器环路（「发送必伴随接收」）

SPI 全双工的物理基础是**主机与从机的移位寄存器首尾相连成环**：

```
主机 Shift Reg: [D7 D6 ... D0]         从机 Shift Reg: [d7 d6 ... d0]
     ↓ MOSI ────────────────────────────────→    ↑
     ↑ MISO ←────────────────────────────────    ↓
```

每个 SCK 周期：主机从 MOSI **移出 1 bit**、从 MISO **移入 1 bit**；从机从 MOSI **移入 1 bit**、从 MISO **移出 1 bit**。8 个 SCK 脉冲后，双方的移位寄存器**完全交换**。

关键认知：SPI 里 **「发送」必然伴随「接收」**。

- 主机只想发数据 → 接收缓冲会被从机 MISO 上的**任意电平（垃圾数据）**填满。
- 主机想读数据 → 必须先向发送寄存器写**任意值（dummy byte，常为 `0xFF`）**来**产生时钟**，才能把从机的数据「推」出来。

> 💬 面试金句：**「为什么读 SPI FLASH 要先发一个 0xFF？」——发 0xFF 只为产生时钟，真正要的数据在 MISO 上同步收回；SPI 没有「只读」的事务，收发永远成对。**

#### 2. CS 片选时序与「软件 NSS」（为什么实际项目首选软件 NSS）

- **CS（SS/NSS）低电平有效**：拉低选中从机并启动其内部状态机；拉高则**断开从机并复位**。
- **关键时序**：CS 必须在**命令 + 地址 + 数据**整个期间**连续保持低电平**，中间不能拉高（如 SPI FLASH 的**页编程 / 写使能**命令）；CS 中途抖动会让 FLASH 把命令当错帧丢弃。
- **NSS 管理三种方式（STM32）**：

| 模式 | 配置 | 行为 | 适用 |
|---|---|---|---|
| 软件 NSS | `SSM=1, SSI=1` | SS 作普通 GPIO，软件拉低/拉高 | **首选**（多字节连续 CS 可控） |
| 硬件 NSS 输出 | `SSM=0, SSOE=1` | 硬件自动在帧间拉高 NSS | 仅单主、不满足连续 CS |
| 硬件 NSS 输入 | `SSM=0, SSOE=0` | 外部拉低时**自动变从机** | 多主 / 主从切换 |

- **为什么首选软件 NSS**：硬件 NSS 输出在**帧之间会自动拉高**，无法实现「多字节连续 CS 保持拉低」（FLASH 页编程正需要）；且拉高时机不可控，有些从设备需要 CS 拉高后的特定延时。软件控制 GPIO 可**精细控制时序**，适配任何从设备。

> 💬 面试金句：**面试说「软件 NSS」说明你真做过 SPI 项目；说「硬件 NSS 输出」多半只看过理论——因为硬件 NSS 在帧间强制拉高，做不了 FLASH 页编程这类「整段 CS 必须常低」的事务。**

#### 3. 四模式：哪种常用 + 记忆技巧（补足四模式速查表）

- **Mode 0 与 Mode 3 最常用**：SPI FLASH、多数传感器、LCD 驱动默认支持（一个空闲低、一个空闲高，但都是**上升沿采样**）。
- **记忆技巧**：CPOL 看**空闲电平**（0 低 / 1 高）；CPHA 看**采样边沿**（0 第一边沿 / 1 第二边沿）。
- **示波器定性**：空闲低 + 上升沿采样 → Mode 0；空闲高 + 上升沿采样 → Mode 3。
- **主从必须一致**：从设备数据手册会标注其模式（很多默认 0 或 3），主控制器配成同一模式；拿不准先用**低速 + 逻辑分析仪**看波形对齐。

#### 4. 多从机方案：独立 CS / 菊花链 / 译码器

| 方案 | 接线 | 优点 | 缺点 / 条件 |
|---|---|---|---|
| 独立 SS（星型） | 每从 1 根独立 CS | 各从可独立模式/速率，某从故障不影响总线 | 从多则 GPIO 不够 |
| 菊花链 Daisy-Chain | 1 根 SS，MOSI→MISO 首尾串联 | 只 1 根 SS，形成长移位寄存器 | N 从需 N×8 时钟取回；某从断路整链断；**所有从必须同一模式** |
| 译码器扩展 | 3-8 译码器（74HC138） | 3 GPIO → 8 路独立 CS | 折衷，兼顾引脚与独立控制 |

- 工程选择：**≤3 从 → 独立 SS**（最简稳定）；**4~8 从 → 独立 SS 或译码器**（GPIO 吃紧）；**大量同型号从机（LED 驱动链） → 菊花链**；**不同型号混用 → 绝对避免菊花链**（模式/时序冲突）。

#### 5. SPI 速率为何不能无限提高

三方面限制：

1. **从设备最大时钟（硬天花板）**：datasheet 规定（如 W25Q64 最大 80 MHz），超出则移位/逻辑跟不上 → 数据错乱。
2. **时序余量**：需满足建立/保持/输出有效延迟（`tsu(D)`、`th(D)`、`tV(MISO)`）；频率越高，半个 SCK 周期越短，越难满足。
3. **物理层与 MCU**：PCB 走线传播延迟、多从共线容性负载、高频串扰；MCU 外设时钟常为 APB 一半（STM32F4：APB2 84 MHz → SPI 42 MHz）。

> 💬 工程经验：SPI 速率**不超过从设备最大值的 80%**，留出走线延迟与时钟抖动余量。

#### 6. MSB/LSB 优先与「位序反转」调试陷阱

- **MSB First（默认）**：SPI FLASH、传感器、LCD 驱动；与 I2C / 多数并行总线一致。
- **LSB First**：少数 ADC（MCP3201）、射频（CC2500）、数字电位器（AD5204）。
- **调试陷阱（最隐蔽的 bug）**：MSB/LSB 配错**不报错**，但读到数据**位序反转**（读 `0x48` 实为 `0x12`），「有规律但全错」。**排查：发 `0x01`（仅 1 个 bit 为 1），看返回判断位序。**

#### 7. SPI DMA：双缓冲 + 半传输中断（连续采集）

高频采集（如 10 KHz × 16 bit）**每字节中断 → 中断率过高**，标准方案是 **DMA 双缓冲 + 半传输中断（乒乓）**：

- 缓冲分两半；DMA 循环填充。
- **HT（半传输）中断**：前半段刚写完 → 处理前半段（上一轮），后半段仍在被 DMA 填。
- **TC（传输完成）中断**：后半段写完 → 处理后半段（新数据）；DMA 自动回到缓冲首址。
- 发送 DMA 用 **dummy = `0xFFFF`**（16 bit 帧，全 1 兼容最多从机）；CS 整个采集期保持低，靠定时中断决定帧间隔。

完整 DMA 通用取舍见 **`q-dma`**（DMA vs 中断 vs 轮询、缓存一致性 / 对齐坑）。

> 💬 面试加分：只答「用 DMA」不够，说出「**DMA 半传输中断 + 双缓冲（乒乓）**」才是真做过。

#### 8. Dual-SPI / Quad-SPI（QSPI）与 XIP

| 特性 | 标准 SPI | Dual-SPI | Quad-SPI |
|---|---|---|---|
| I/O 引脚 | 4（+CS） | 4（复用 MOSI/MISO） | 6 |
| 每时钟 bit | 1 | 2 | 4 |
| 吞吐（80 MHz） | ~10 MB/s | ~20 MB/s | ~40 MB/s |
| 典型 | 通用外设 | FLASH 读加速 | FLASH 高速读 + XIP |

- **QSPI 主要对象是 NOR FLASH**，实现 **XIP（Execute In Place，片内执行）**——MCU 直接从外部 FLASH 取指执行，无需先加载到 RAM。
- **STM32F4/F7/H7** 内置 QSPI 控制器，支持**内存映射模式**（把外部 FLASH 映射进 MCU 地址空间）。

> 📌 一句话记忆：**SPI 四模式由 CPOL（空闲电平 0低/1高）+ CPHA（采样边沿 0第一/1第二）决定；主从配置必须一致，否则采样错位乱码。**
