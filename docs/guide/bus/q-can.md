  **CAN（Controller Area Network）**是一种**多主、差分、基于报文标识符仲裁**的串行广播总线，广泛用于**汽车、工业**（要求高可靠、实时、多节点共享）。

  - **物理层**：双绞线 CAN_H/CAN_L，**差分信号**抗干扰，两端各接一个**120Ω 终端电阻**。
  - **多主 + 仲裁**：多个节点可同时发，靠**标识符**逐位仲裁，**标识符数值越小优先级越高**（0 为显性），冲突后高优先级继续发，低优先级退避。

  - **速率**：常见 **125kbps~1Mbps**（高速），与线长成反比（线越长速率越低）。
  - **可靠性**：CRC 校验、错误帧、自动重发、错误检测与故障隔离。

## 深读

### 为什么多主 + 仲裁不冲突

- 总线有两态：**显性（dominant，0）** 与 **隐性（recessive，1）**。
- 多个节点**同时发**时，从最高位开始逐位比较；若某个节点发**隐性(1)**、另一个发**显性(0)**，总线上表现**显性(0)**，则发隐性(1)的节点发现自己被“否决”，判为仲裁失败，**退避**。
- **标识符数值越小 → 位越早为 0（显性）→ 越容易赢 → 优先级越高**。

### 帧与域（简化）

```
[帧起始 SOF][仲裁域 ID+RTR][控制域][数据域(0~8B)][CRC][ACK][EOF]
```

- **仲裁域**：标识符 + 数据/远程帧标志。标识符同时是“寻址”与“优先级”。
- **数据域**：最多 8 字节（经典 CAN）。

### 速率与线长

- 速率越高，位时间越短，受传播延迟限制，**线越长速率越低**（高速 1Mbps 常在数十米内，低速可用于更长）。
- 实践中：车内动力用 **500kbps**，车身舒适/诊断用 **125k~250kbps**。

### 物理层注意

- **差分信号**：CAN_H/CAN_L，抗共模干扰。
- **终端电阻**：总线两端各 **120Ω**，防反射（波形畸变常是缺终端或阻抗不匹配）。
- **双绞线、屏蔽、走线**：影响 EMC 与可靠性。

### 嵌入式中的应用与坑

- **驱动/收发器**：MCU 自带 CAN 控制器（如 STM32 bxCAN/flexCAN）；收发器（如 TJA1050）负责电平。
- **位时序**：采样点、SJW 等配置不当 → 丢帧/错误帧。
- **错误处理**：错误计数、错误状态（主动/被动/总线关闭），总线关闭要重扫/复位。
- **报文/协议**：常配 **CANopen、J1939、UDS（诊断）、DBC** 等上层协议。

### 常见追问

- 为什么 CAN 标识符小优先级高？——仲裁从高位起逐位比较，数值小的位串更早出现 0（显性），赢得仲裁。
- CAN 是多主还是一主多从？——**多主**，任何节点都可发起，靠仲裁解决冲突。
- 终端电阻多大、为什么？——两端各 120Ω，与总线特征阻抗匹配，减少反射。
- 为什么线长和速率成反比？——传播延迟限制，位时间要覆盖往返传播延迟。

> 📌 一句话记忆：**CAN=多主、差分、按标识符逐位仲裁（数值小优先级高）、带检错自动重发；两端各 120Ω 终端电阻，速率与线长成反比。**
