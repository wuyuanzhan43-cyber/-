answer: |
  I2C 是**两线（SDA 数据 + SCL 时钟）同步串行**，时序核心：
  - **空闲**：SDA 与 SCL 都拉**高**（由外部上拉）。
  - **起始 START**：**SCL 为高时 SDA 由高变低**。
  - **数据位**：**SCL 为高时采样 SDA**（数据在 SCL 低时变化，高时稳定被采样）。
  - **停止 STOP**：**SCL 为高时 SDA 由低变高**。
  - **ACK/NACK**：每字节（8 位）后，**从机在 SCL 高时拉低 SDA** 表示 ACK；不拉低为 NACK。
  - **时钟拉伸（clock stretching）**：从机若忙，可**拉低 SCL** 延长时间，主机检测到 SCL 被拉低就等待（慢速从机）。
  - **速率**：标准 100kbps、快速 400kbps、高速 3.4Mbps；受**上拉电阻、线容、时序参数**限制。
  **基本读写流程**：START → 从机地址+读写位 → ACK → 数据字节 → ACK/NACK → ... → STOP。
why: |
  I2C 是**同步、半双工**，靠 **START/STOP 界定帧、SCL 高时采样、ACK 确认、时钟拉伸让从机控制节奏**。理解时序才能：
  - **正确读写**（地址、读/写位、ACK 时机）。
  - **排查故障**：无 ACK（地址不对/设备没上电/总线挂死）、时钟拉伸卡住、SDA/SCL 上拉缺失、速率/线长限制。
  - 知道为何**开漏 + 上拉**（线与），以及**时钟拉伸**会让主机等待。

## 深读

### 波形要点

```
SDA:  ‾\/‾\_‾\/‾\_ ...   (数据在 SCL 低时变, SCL 高时采样)
SCL:  ‾‾‾|‾‾‾|‾ → 高低交替
      START(SCL高,SDA↓)     STOP(SCL高,SDA↑)
```

- **START**：SCL 高时 SDA 高→低。
- **数据**：SCL 低时 SDA 变化，SCL 高时采样。
- **STOP**：SCL 高时 SDA 低→高。

### 读写一个字节

```
START | 从机地址(7bit) + R/W | ACK | 数据(8bit) | ACK/NACK | ... | STOP
```

- **ACK**：接收方在 SCL 高时拉低 SDA。
- **NACK**：主机停止读取/从机忙（读不到最后一个字节可以不 ACK）。

### 时钟拉伸

- 从机拉低 SCL → 主机**暂停**时钟，直到从机释放。
- 用途：慢速从机（如 EEPROM 写、I/O 扩展）需要更多时间。
- 若主机不支持拉伸或从机拉太低，会**卡死/超时**。

### 关键参数与坑

| 项 | 说明 |
|---|---|
| 开漏+上拉 | SDA/SCL 需外部上拉（线与） |
| 速率 | 100k/400k/3.4M，受上拉/线容限制 |
| 时钟拉伸 | 从机拉低 SCL 扩时，主机需支持 |
| 无 ACK | 地址错/设备没上电/总线被拉低挂死 |
| 时序参数 | 建立/保持/上升下降时间，超高速要求严格 |

### ★ 深入：Repeated START 与「不接上拉的后果」

**Repeated START（重复起始，Sr）**：在 START 之后、STOP 之前**再次发 START**，不释放总线。

```
START → 写地址 → ACK → 写数据 → ACK → Sr → 读地址 → ACK → 读数据 → NACK → STOP
                                            ↑ 不用 STOP
```

- **用途**：**写后读**（先写寄存器地址、不释放总线直接读数据——绝大多数传感器/存储器都是这个流程）；或**更换通信方向**（主发送→主接收）。
- **为什么不用 STOP + START**：STOP 到 START 之间有**总线空闲期**，其他主机可能插进来抢总线，破坏“**写寄存器→读数据**”的**原子性**；Repeated START 保证中途不被抢占。

**不接上拉电阻会怎样**：SCL/SDA 是**开漏**，只能拉低；高电平靠**外部上拉**。不接上拉 → 总线**永远无法回到高电平**，通信完全失效、逻辑分析仪看到全 0 波形；即使靠 STM32 **内部弱上拉（约 40KΩ）**勉强能跑，**波形边沿极差、速率稍高就失败**。

> 💬 面试金句：**知道 Repeated START，说明你不只是“会用 I2C”，而是“理解 I2C 流程设计的动机”——它保证了“写寄存器→读数据”的原子性。**
> 💬 面试金句：**开漏 + 上拉 = I2C 能实现多主仲裁与从机应答的物理基石；不接上拉总线就回不到高电平，必然失效。**

### ★ 深入：地址读写方向、速度模式、ACK/NACK、多主仲裁（参考题集精华）

**地址与读写方向**：从机 7 位地址 + 最低 bit 为 **R/W**（0=写，1=读）。发送的 8 位地址字节 = `Addr[7:1] << 1 | R/W`。例：地址 `0x50`（1010000），写用 `0xA0`（1010000**0**），读用 `0xA1`（1010000**1**）。能说清“地址左移 1 位再拼 R/W”= 你写过真实 I2C 驱动。

**速度模式**：

| 模式 | 最高速率 | 用途 |
|---|---|---|
| Standard (Sm) | 100 Kbps | 低速传感器 |
| Fast (Fm) | 400 Kbps | EEPROM/加速度计/OLED |
| Fast-mode Plus (Fm+) | 1 Mbps | 更高吞吐 |
| High-speed (Hs) | 3.4 Mbps | 高速 ADC |
| Ultra Fast (UFm) | 5 Mbps | 单向、无 ACK |

**速率由谁决定**：主机发时钟 → 主控；但**上拉电阻**限制上升沿（RC 时间常数），从机可**时钟拉伸**拉低有效速率。

**ACK/NACK**：I2C 无明显错误线，ACK/NACK 就是**逐字节确认**（确认从机在线、数据接收、从机流控）。关键易错点：**读操作最后一个字节必须由主机回 NACK**——若回了 ACK，从机会继续驱动 SDA，导致总线异常（新手经典 bug）。

**多主机仲裁**：I2C 支持多主。多个主机同时发，靠 **SDA 线与 + 逐位比较**仲裁：想发显性(0)的能赢，发隐性(1)又读回 0（被覆盖）的主机**退出**，未输者继续。这正是“开漏+上拉（线与）”的价值。

**时钟拉伸禁用与超时**：从机可随时拉低 SCL（协议合法，**无法完全禁止**）；主机可配 `NOSTRETCH` 位（CR1）不检测拉伸，但可能丢数据。**工程坑**：若从机死机/总线短路无限拉伸 → 主机**永远等下去（总线挂死）**；对策：硬件 I2C 超时（`TIMEOUT`）+ 软件看门狗复位 I2C。

### 常见追问

- START/STOP 怎么定义？——SCL 高时 SDA 跳变：高→低为 START，低→高为 STOP。
- ACK 是谁发的？——接收方（从机）在每字节后拉低 SDA 表示 ACK。
- 为什么时钟拉伸？——从机忙时拉低 SCL 让主机等待，适配慢速从机。
- 为什么用开漏+上拉？——支持线与/多主机仲裁，空闲电平为高。

> 📌 一句话记忆：**I2C：SCL 高时 SDA 跳变定 START/STOP，SCL 高时采样数据，每字节后 ACK；从机可拉低 SCL 时钟拉伸；开漏+上拉。**
