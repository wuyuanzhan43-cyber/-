answer: |
  **栈（Stack）**：由编译器自动管理，用于**局部变量、函数参数、返回地址**，分配/释放顺序先进后出（LIFO）且固定，**大小有限、速度快、无需手动释放**；超限会栈溢出。
  **堆（Heap）**：由程序员手动管理（`malloc`/`free`），**动态大小、灵活**；但要避免**内存泄漏、double free、内存碎片**，多线程/中断下需加锁保护。
  区别核心：**谁管理（自动 vs 手动）、是否连续固定（栈 LIFO vs 堆可增长）、大小与速度（栈小快 vs 堆大慢）、风险（栈溢出 vs 泄漏/碎片）**。
why: |
  栈是“自动、LIFO、有限、快”的临时存储，函数返回即释放；堆是“手动、可增长、灵活、有风险”的持久存储。
  栈溢出常见于**递归过深、超大局部数组/结构体、中断/任务栈分配太小**；堆问题常见于**泄漏、碎片、double free**。
  嵌入式里栈大小常预分配（各任务独立栈），堆要避免长期碎片，很多项目会关闭堆或对关键路径禁用动态分配。

## 深读

### 栈（Stack）

- **自动管理**：调用函数时压栈（参数、返回地址、局部变量），返回时弹栈。
- **LIFO + 连续**：栈方向固定（通常向地址减小），访问快。
- **有限**：每个任务/线程有独立栈（RTOS 里常按任务预分配），超出 → **栈溢出**，表现为：局部变量覆盖/崩溃、栈指针越界、HardFault。
- **典型溢出**：
  - 递归太深（栈帧反复入栈）。
  - 超大局部数组/结构体（如 `char buf[1MB]` 放栈上）。
  - 中断嵌套太深（每层中断用栈）。
  - 任务栈配置不足。

### 堆（Heap）

- **手动管理**：`malloc`/`free`（内核 `kmalloc`、C++ `new/delete`）。
- **可增长、灵活**：大小按需分配。
- **风险**：
  - **泄漏**：`free` 漏了 → 内存慢慢耗尽。
  - **double free / 悬垂指针**：重复释放、释放后用。
  - **碎片**：反复不同大小分配释放，堆被切碎 → 大块分配失败。
  - **并发**：多任务/中断同时操作堆 → 需锁/原子，或使用 TLSF/内存池。

### 对照表

| 维度 | 栈 | 堆 |
|---|---|---|
| 分配者 | 编译器/RTOS | 程序员 |
| 释放 | 自动（函数返回） | 手动 `free` |
| 方向 | 连续、LIFO | 离散、可寻址 |
| 大小 | 有限（预分配） | 可增长（受系统内存限制） |
| 速度 | 快 | 慢（要维护空闲链表） |
| 风险 | 栈溢出 | 泄漏 / 碎片 / double free |

### 嵌入式实践

- **各任务独立栈**：RTOS 里任务栈要预算好（含中断/嵌套余量）。
- **关键路径避免 `malloc`**：实时/确定性要求高时，用**静态分配/内存池**避免碎片与不确定性延迟。
- **栈溢出检测**：栈生长方向哨兵/栈底破坏检查（`-fstack-protector`）、MPU 区域保护。
- **避免超大局部变量**：放栈上的大数组改放堆或静态区。

### 常见追问

- 为什么嵌入式常禁用堆？——碎片 + 分配时间不确定 + 并发问题，对实时/长期运行系统是隐患。
- 栈和堆谁大？——栈小（任务栈 MB 级以内），堆大（可用内存多），但堆要防止碎片。
- 递归为什么危险？——每次递归都压栈，深了就溢出；ARM 上常表现为栈覆盖/崩。

> 📌 一句话记忆：**栈=自动、LIFO、有限、快（溢出）；堆=手动、灵活、有泄漏/碎片（要`free`+防并发）。**
