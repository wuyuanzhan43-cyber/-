## 深读

### 为什么需要对齐

很多 CPU 要求“数据类型必须自然对齐”：`int`（4 字节）的地址要是 4 的倍数。若机器支持非对齐访问，通常也会慢；若不支持，直接触发硬件异常。嵌入式尤其敏感。

### 一个典型结构体

```c
struct S {
  char  c;   // offset 0，占 1 字节
  int   i;   // 需要 4 字节对齐 → offset 4，前面补 3 字节 padding
  short s;   // 2 字节对齐 → offset 8
};           // 成员最大对齐 = 4，末尾再补 2 字节 → sizeof = 12
```

`sizeof(struct S)` 在 32 位默认对齐下 = `12`，而不是 `1+4+2=7`。

### 成员顺序影响大小

```c
struct A { char c; int i; short s; };  // 12 字节
struct B { int i; short s; char c; };  // 8 字节，顺序更紧凑
```

把大对齐的成员放前面、小对齐的放后面，往往能减少 padding，**同样的数据用更少的 RAM**。

### 对齐相关概念

- **自然对齐**：`T` 的对象地址是 `alignof(T)` 的倍数。
- **对齐值（alignment）**：通常等于最宽基本成员的对齐，可用 `_Alignof`/`alignof` 查询。
- **`#pragma pack(n)`**：把对齐改成 n 的倍数（常用于协议头、硬件寄存器结构、文件格式），但**可能降低性能甚至非法访问**，需谨慎。
- **`_Alignas` / `aligned`（编译器扩展）**：显式指定对齐。

### 嵌入式中的实际意义

- **通信协议 / 寄存器映射结构体**：通常用 `__attribute__((packed))` 或 `#pragma pack(1)` 去掉 padding，保证与报文/寄存器字节布局一致。
- **节省 RAM**：优化成员排列，把 padding 降到最低。
- **DMA / 缓存行**：缓冲对齐到缓存行大小能提升一致性访问性能。

### 常见面试追问

- 为什么 `sizeof(struct)` 往往是成员大小之和的“上取整到最大对齐”？——保证“结构体数组”中每个元素都自然对齐。
- 位域（bit-field）不能取地址，且内部布局由编译器决定，跨平台不可移植。

> 📌 一句话记忆：**对齐是为了“一次取到/不越界”，`sizeof` 看“最宽成员对齐”并由此补 padding；重排成员能省内存。**
