  常见陷阱源于**整型提升与混合运算自动转成无符号**：
  - **无符号与有符号混算**：`int` 与 `unsigned int` 运算时，`int` 会**转换（提升）为 unsigned**，负值变成“巨大正数”，导致比较/减法出错。
  - **`unsigned` 减法下溢**：`a-b` 当 `a<b`（无符号）下溢为巨大正数，常导致循环/长度判断错误。
  - **`sizeof` 返回无符号**：`sizeof(..)` 类型是 `size_t`（无符号），`if (sizeof(arr) - 1 > 0)` 在 `sizeof==0` 时下溢。
  - **比较陷阱**：`if (-1 < (int)x)` 若 `x` 为 `unsigned`，`-1` 会转成无符号巨大值，条件为假。
  避免方法：混算时**显式强转**、避免 `unsigned` 减法、用 `size_t` 时小心、用带符号或明确边界、开编译告警（`-Wsign-compare -Wconversion`）。
why: |
  这是 C 最常见的“**看似对、实则错**”的 bug：**编译器按“无符号优先/整型提升”自动转换**，把负数变成巨大正数，让比较、循环、长度边界判断全部出错。嵌入式里长度、位运算、寄存器字段常是 `unsigned`，极易踩坑。

## 深读

### 整型提升与“无符号优先”

- 小整型（`char`/`short`）在运算前**提升为 `int`**（通常）。
- 有符号与无符号同宽度混算 → **有符号转无符号**（C 规则：同等级别下 unsigned 优先）。
- 结果：负 `int` 变巨大 `unsigned`。

### 典型反例

```c
// 1) 比较
unsigned x = 5;
if (-1 < x)   // -1 转成 UINT_MAX，恒为假
// 实际：-1 转无符号 = 4294967295，所以 -1 < 5 是假
```

```c
// 2) 减法下溢
unsigned a = 3, b = 5;
unsigned d = a - b;   // 下溢 → 巨大正数（4294967294）
if (d > 0) { ... }    // 永远真
```

```c
// 3) 长度判断
size_t len = sizeof(arr);
if (len - 1 > 0) ...  // 若 len==0，则 len-1 下溢，判断错误
```

### 避免策略

1. **显式强转**：`(int)a - (int)b`、比较时转为同一符号。
2. **避免 `unsigned` 减法**：先判大小或用有符号中间量。
3. **用有符号 `int` 做长度/索引**，或用 `size_t` 但要防止减 1。
4. **开启诊断**：`-Wsign-compare`、`-Wconversion`、`-Wsign-conversion`。
5. **在位运算/寄存器字段**注意：移位到符号位用 `unsigned`，避免 UB。

### 常见追问

- `int` 和 `unsigned int` 相加结果是什么类型？——`unsigned int`（`int` 被转换）。
- `sizeof` 返回类型？——`size_t`（无符号），所以 `sizeof(x) - 1` 在 `sizeof(x)` 为 0 时下溢。
- 数字 `-1` 转无符号是多少？——取决于位宽（32 位为 `0xFFFFFFFF`）。
- 怎么避免这些坑？——显式类型、避免无符号减法、开编译告警、统一用有符号或 `size_t` 谨慎。

> 📌 一句话记忆：**C 里“无符号优先 + 整型提升”把负数变巨大正数；混算、unsigned 减法、sizeof 下溢都是高频坑，显式强转+告警可避。**
