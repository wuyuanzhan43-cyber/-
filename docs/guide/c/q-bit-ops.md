answer: |
  **位操作**用 `&`、`|`、`^`、`~` 与位移（`<<`、`>>`）对整型按位处理，直接对应硬件寄存器/标志位：
  - 置位：`REG |= (1U << n);`
  - 清位：`REG &= ~(1U << n);`
  - 取反：`REG ^= (1 << n);`
  - 判断某位：`if (REG & (1U << n))`
  - 读某位域：`(REG >> shift) & mask`
  - 写某位域：`REG = (REG & ~(mask<<shift)) | (val<<shift)`。
  **位域（bit-field）**：结构体里按位分配成员（如 `unsigned flag:1; unsigned cnt:3;`），节省内存、封装寄存器/标志；但**布局由编译器决定、不可移植**，且位域成员**不能取地址**，跨端序/跨编译器布局不同。
why: |
  位操作是嵌入式**操作硬件寄存器、状态位、协议字段**的基本功，省 RAM、直接、无函数调用开销。
  位域能把“多个标志/小字段”用更少字节装下，但**牺牲可移植性**：不同编译器/端序对位域在字内的排列不一致，对 MMIO 寄存器、网络/通信协议这类要与外部字节精确对齐的场景，**更推荐用显式掩码+移位**（或 `__packed`+字节序转换），而不是位域。

## 深读

### 常用位操作写法

| 意图 | 写法 |
|---|---|
| 置位 n | `REG |= (1U << n)` |
| 清位 n | `REG &= ~(1U << n)` |
| 取反 n | `REG ^= (1 << n)` |
| 判断 n 是否为 1 | `if (REG & (1U << n))` |
| 读 [msb:lsb] 字段 | `(REG >> lsb) & ((1U << (msb-lsb+1)) - 1)` |
| 写字段值 | `REG = (REG & ~(mask << lsb)) \| (val << lsb)` |

### 位域示例

```c
struct Flags {
  unsigned enable : 1;   // 用 1 位
  unsigned mode   : 3;   // 用 3 位，取值 0~7
  unsigned ready  : 1;
};
```

- 优点：省空间、语义清晰。
- 缺点：**布局由编译器决定**（字内从低字节还是高字节、跨字节怎么排不确定），跨端序/跨编译器**不同**；**不能取地址**、不能对单个位字段 `&`/`|`（要整体读写）；对 sizeof 的影响也要注意。

### 何时用位域、何时用掩码

| 场景 | 推荐 |
|---|---|
| 内部数据结构/内存紧张 | 位域（局部、可接受） |
| MMIO 寄存器 | **显式掩码 + 移位**（需与硬件定义精确对位） |
| 通信/网络/DMA 报文 | **掩码/移位 + 字节序转换**（需严格字节布局） |
| 跨芯片/跨平台交换 | 避免位域，用 `uint8_t`/`uint16_t` + `__packed` + 字节序 |

### 常见的位操作技巧

- 统计 1 个数：`__builtin_popcount`。
- 找最低 1 位：`n & -n`。
- 清掉最低位的 1：`n & (n - 1)`。
- 交换/翻转：`~x`、`x ^ mask`。
- 大小端与位域提醒：位域是**位序**概念，不要与**字节序**混淆。

### 常见追问

- 为什么寄存器赋值要用掩码再或，避免直接 `=`？——避免破坏相邻位域/位；直接 `=` 会把无关位也清零。
- 位域能用在协议头吗？——不建议，因为布局不可移植；协议用定宽整型 + `__packed` + 字节序转换。详见`位域做协议解析（q-bitfield-protocol）`。
- `1 << 31` 有什么隐患？——若 `1` 是 `int`（有符号），左移到符号位是未定义行为；要写成 `1U << 31`。

> 📌 一句话记忆：**位操作直接操作寄存器（置/清/取反/判/读写字段）；位域省字节但不可移植，外部协议用掩码+移位。**
