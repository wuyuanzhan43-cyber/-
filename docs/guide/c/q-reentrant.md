answer: |
  **可重入（reentrant）**：函数能被**多次进入/被打断后再次进入**仍安全——**不依赖全局/静态可变状态、自身数据在栈上/局部**，执行过程不会被并发调用破坏。
  **线程安全（thread-safe）**：函数在**多线程/多任务**并发调用下结果正确，通过**同步（锁/原子/关中断）**保护共享资源。
  区别：
  - **可重入**更强调“**函数本身无共享可变状态**”（纯局部，栈上），是**线程安全的一种**且更强。
  - **线程安全**允许函数内部有共享状态，只要加锁保护即可（但带锁的函数**不一定可重入**——中断里再调用会死锁，如持锁时被打断又进入）。
  常见**不可重入**：用到全局/静态变量（`static` 计数、`errno`、`printf` 的静态缓冲、`malloc` 的堆）、中断与任务共享同一函数、递归中带共享状态。
  保证：**尽量用局部变量/传参**、只读全局用 `const`、共享数据用锁/原子/关中断、**中断里避免调用不可重入函数**。
why: |
  嵌入式里**中断可能随时打断任务**，若任务正在执行一个函数，中断里**又调用同一函数**（可重入问题），或**多任务并发调用**（线程安全问题），共享状态会被破坏 → **数据竞态、错乱**。
  核心答案是“**把可变状态放到栈/局部，或用同步保护共享资源**”。这也是为什么中断里**只用简短、可重入**的函数（如内存操作、置标志），而不调用 `printf`/`malloc`/带锁函数。

## 深读

### 不可重入的典型

```c
int g = 0;
int inc(void){ return ++g; }   // 依赖全局 → 不可重入（并发会竞态）
```

```c
int f(void){
  static int s = 0;            // 静态局部 → 多次调用共享 s → 不可重入
  return ++s;
}
```

### 怎么写成可重入

```c
int inc(int *p){ return ++(*p); }   // 状态由调用方/栈传入 → 可重入
```

- 状态走**局部变量/参数/返回值**，不依赖全局/静态可变状态。

### 可重入 vs 线程安全

- **可重入**：无共享可变状态，天然线程安全（更强前提）。
- **线程安全**：可以有共享状态，但需**锁/原子**保护（如带 mutex 的函数在多任务下安全）。
- **但带锁函数不一定可重入**：若任务持锁执行 `f()`，中断里又调 `f()` 想拿同一把锁 → 死锁。所以**中断里要用可重入**（无锁/局部）版本。

### 嵌入式实践

- 中断处理里用**简短、可重入**（局部变量、内存操作、置标志），避免 `printf`/`malloc`/带锁函数。
- 共享资源用**锁/原子/关中断**保护，临界区短。
- 全局只读用 `const`；可变全局尽量局部化。

### 常见追问

- 可重入和线程安全是一回事吗？——不完全：可重入强调无共享可变状态（更强、更安全）；线程安全可用锁，但带锁函数可能不可重入。
- 为什么中断里不能用 `printf`？——`printf` 有内部静态缓冲、可能带锁，不可重入/不能阻塞，中断里调用会出错或死锁。
- 怎么判断可重入？——看是否读写全局/静态可变状态；只用局部/栈则可重入。

> 📌 一句话记忆：**可重入=无共享可变状态（局部/栈）；线程安全=加锁保护共享资源；中断里要用可重入、简短函数，避免 printf/malloc/带锁。**
