answer: |
  **函数指针**是一个指向**函数**的指针变量，存的是函数入口地址，可通过它间接调用函数。声明如 `int (*fp)(int, void*)`（`*fp` 是函数指针，返回 `int`，参数 `(int, void*)`）。
  核心作用：**把「函数」作为可传的值**——**回调（callback）**：把函数指针传给他人，让对方在某个时机回调你；**跳转表/分发表**：用数组存一组函数指针，避免冗长的 `switch`；**注入策略/可插拔行为**（驱动、排序比较器、事件处理、状态机转移表）。
  注意：函数指针指向的是代码区，**不能**像数据指针那样随意修改；可通过 `typedef` 简化声明；空指针调用会崩溃；可跨不同实现提供同一接口（多态的思想）。
why: |
  函数指针让代码“**把行为当数据传递**”，实现**解耦与复用**：调用方不需要知道具体执行逻辑，只按约定接口调用，正契合驱动/框架/回调的设计。
  嵌入式里：注册中断回调、定时器回调、比较函数（`qsort`/排序）、状态机转移表、驱动 `ops` 结构体——都用函数指针实现“**接口与实现分离**”。理解它就能理解驱动模型里 `file_operations` 这类“函数指针集”的本质。

## 深读

### 声明与调用

```c
int add(int a, int b){ return a+b; }
int (*fp)(int,int) = add;   // fp 指向 add
int r = fp(2,3);            // 通过指针调用 → 5
```

- `int (*fp)(int,int)`：`*fp` 先结合，说明 `fp` 是指针，指向“返回 int、形参 (int,int) 的函数”。
- **`typedef` 简化**：`typedef int (*Op)(int,int);` 之后 `Op fp = add;`。

### 跳转表 / 分发表

```c
typedef void (*Handler)(int);
Handler table[N];           // 存一组函数指针
table[0] = handlerA;
table[1] = handlerB;
// 调用
table[cmd](arg);            // 避免巨型 switch
```

常见于**命令分发、事件处理、状态机转移表**。相比 `switch`，更清晰、易扩展（加新命令只需注册新函数）。

### 驱动里的 ops（函数指针集）

Linux 驱动 `struct file_operations` 就是**一组函数指针**：`open/read/write/release/ioctl...`。内核用统一接口调用不同驱动的实现——这就是“**多态/接口与实现分离**”。

### 回调典型场景

- **中断/定时器回调**：驱动注册一个回调，事件发生时框架调用它。
- **排序比较器**：`qsort(..., compare)` 传入比较函数，定制排序规则。
- **事件/通知**：上层注册回调，底层事件触发时通知上层。

### 常见追问

- 函数指针和普通指针有何不同？——函数指针指向代码段、存的是入口地址，可间接调用；普通指针指向数据。二者类型不同，不能随意互转。
- 怎么避免函数指针崩溃？——调用前判空、确保回调生命周期有效（防悬垂回调）、保持接口一致。
- 函数指针能用来做“多态”吗？——可以，C 语言里常用来模拟 OOP 的虚函数/策略模式。

> 📌 一句话记忆：**函数指针 = “把函数当值传” → 回调/跳转表/驱动 ops；实现“接口与实现分离”。**
