answer: |
  一个可执行程序的内存（运行时）大致分几段：
  - **代码段（.text）**：编译后的**指令**，只读，可放 Flash/只读区。
  - **只读数据（.rodata）**：常量、字符串字面量（有的并入 .text）。
  - **数据段（.data）**：**已初始化**的全局/静态变量，有初值，运行时拷到 RAM。
  - **BSS（.bss）**：**未初始化**的全局/静态变量，运行时**清零**。
  - **堆（heap）**：动态分配（malloc/free），向高地址增长。
  - **栈（stack）**：函数调用/局部变量，向低地址增长（方向因平台而异）。
  布局：代码/只读区在低地址（常只读），然后 .data/.bss（RAM），往上堆+栈相对增长（嵌入式常把 Flash 放代码、RAM 放 data/bss/堆栈）。
  嵌入式里常指定**链接脚本**把各段放到 Flash/RAM，并给**栈/堆**划定区域。

  理解分段才能解释**为什么全局变量初值对、为什么全局变量默认 0（bss 清零）、为什么栈会溢出、malloc 从堆来**。
  嵌入式尤其重要：**代码放 Flash（只读、掉电不丢），.data/.bss/堆栈放 RAM**；栈向低地址、堆向高地址**相对增长**，若相遇就崩（栈溢出/堆溢出）。这是内存规划、栈预算、启动文件（拷 .data/清 .bss）的根因。

## 深读

### 各段速查

| 段 | 内容 | 存放 | 初值 |
|---|---|---|---|
| .text | 指令 | Flash/只读 | — |
| .rodata | 常量/字符串 | Flash/只读 | 只读 |
| .data | 已初始化全局/静态 | RAM(拷入) | 有初值 |
| .bss | 未初始化全局/静态 | RAM | 0（清零） |
| heap | 动态分配 | RAM | — |
| stack | 局部变量/调用 | RAM | — |

### 为什么全局变量默认 0

- `.bss` 段**只记录大小、不存初值**，启动时**清零**，所以未初始化全局/静态变量是 0。
- `.data` 段存初值，启动时要**从 Flash 拷到 RAM**（启动文件/链接脚本负责）。

### 堆与栈的“相向增长”

- 栈通常**向低地址**增长，堆**向高地址**增长，二者在 RAM 里**对向**。
- 若递归/大局部变量用爆栈，或 malloc 用尽堆，可能**栈堆相遇** → 溢出/崩溃。
- 所以**栈大小要预算**（各任务独立栈），堆要防碎片/泄漏。

### 嵌入式内存规划

- **代码/只读**（.text/.rodata）放 **Flash**。
- **.data/.bss/堆/栈**放 **RAM**（RAM 有限，要省）。
- 用**链接脚本（.ld）**定义各段起始/大小与加载/运行地址，启动时把 .data 拷入 RAM、清 .bss、设栈。
- 这就是**裸机/MCU 启动文件**里“拷 data、清 bss、设栈”的根因。

### 常见追问

- 全局变量、静态变量、局部变量分别在哪？——全局/静态在 .data 或 .bss；局部在栈；动态在堆。
- 为什么全局变量能掉电不丢？——不，全局在 RAM，掉电丢；代码/只读在 Flash 才不丢。
- 栈溢出和堆溢出怎么办？——栈：减小局部大数组、控递归、增加栈大小；堆：防泄漏、防碎片、内存池。

> 📌 一句话记忆：**代码/只读放 Flash，.data/.bss/栈/堆放 RAM；.bss 启动清零、.data 启动拷入；栈堆相向增长，相撞即溢出。**
