answer: |
  **联合体（union）**：多个成员**共享同一块内存**，大小 = 最大成员大小，同一时刻只有一个成员有意义（改变一个会覆盖其他）。常用于**“同一内存按不同方式解释”**：
  - **测大小端**：`union { uint32_t u; uint8_t b[4]; }`，看 `b[0]` 是大端还是小端。
  - **寄存器/协议字段拆分**：把一个多字节值按字节/位读取（省移位与强转）。
  - **节省内存**：多个互斥的用途共用一块内存。
  注意：`union` **不保证字节序**（大小端由平台决定），跨端/跨平台解析协议时，**配合显式移位/字节序转换**更可靠；且成员对齐、未在位域时布局由编译器决定。
why: |
  union 的“**同一块内存、不同视角**”特性非常适合嵌入式：**一个 32 位寄存器/报文可按字节或按位域看**，或**判断大小端**，或**多个互斥的状态共用内存（省 RAM）**。
  但 union 的**位域/字节序由编译器与端序决定**，跨平台不可移植；对外部协议（网络、DMA、MMIO）**不要依赖 union 布局**，用显式掩码+移位+字节序转换。

## 深读

### 测大小端

```c
union { uint32_t u; uint8_t b[4]; } t;
t.u = 0x12345678;
if (t.b[0] == 0x12) printf("big-endian\n");
else printf("little-endian\n");
```

- 因为 `u` 和 `b[]` 共享内存，按字节看 `b[0]` 是最高/最低位，从而判断端序。

### 寄存器/报文拆分

```c
union {
  uint32_t word;
  struct { uint8_t en; uint8_t mode; uint8_t irq; } f;
} reg;
```

- 但**位域/成员顺序由编译器决定**（跨端序、跨编译器可能不同），对 MMIO/协议**慎用**。详见`位域做协议解析（q-bitfield-protocol）`。

### 与 struct 的区别

| | struct | union |
|---|---|---|
| 内存 | 各成员**独立**，大小≈各成员之和 | 各成员**共享**，大小=最大 |
| 同时可用 | 所有成员 | 只一个 |
| 目的 | 保存多个字段 | 复用同一块/按不同方式解读 |

### 何时用 union

- **内存复用**：不同阶段用不同结构，省 RAM。
- **多视角查看**：一个值按字节/按位域/按整数读。
- **大小端/字节序判断**。
- **与位域结合做紧凑字段**（但注意可移植性）。

### 常见追问

- union 和 struct 区别？——union 成员共享内存（同时只一个有效），struct 各自独立。
- 用 union 读寄存器可靠吗？——同平台同编译器可，但**跨端序/跨编译器布局不同**，外部协议要用掩码+移位+字节序。
- union 大小？——最大成员大小（加对齐）。

> 📌 一句话记忆：**union=同一内存多视角→测大小端、拆寄存器/报文字段、省内存；但跨端/跨平台不可移植，对外协议用显式移位+字节序。**
