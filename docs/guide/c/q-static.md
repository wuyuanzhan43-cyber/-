answer: |
  `static` 在 C 里主要有三种作用：
  ① **修饰函数内部的局部变量**：让它具有**静态存储期**，生命周期贯穿整个程序，但作用域仍局限于该函数；未初始化时零初始化。常用来做“只初始化一次”的计数/缓存，或闭包式状态。
  ② **修饰文件级/全局变量或函数**：赋予**内部链接（internal linkage）**，只在本编译单元（.c 文件）内可见，外部不可引用。用于实现“模块私有”的数据和辅助函数，避免符号冲突、防止被外部修改。
  ③ （C++ 中）修饰**类的成员**：静态成员属于类而非对象（所有对象共享一份），静态成员函数没有 `this`，只能访问静态成员。C++ 里还有局部 `static`（首次调用时初始化，跨调用持久）+ 线程安全初始化（C++11 magic static）。
why: |
  本质是**存储期**与**链接性**两件事：`static` 让“本该是函数/文件私有的状态”持久存在，同时把可见性收窄到最小范围。
  好处：① 状态安全（模块私有、不被外部误改）；② 避免跨文件的全局变量污染与重名冲突；③ “懒初始化 + 只初始化一次”的语法糖；④ 减少全局命名空间。

## 深读

### 三种作用速查

| 位置 | 作用 | 存储期 | 链接性 | 生命周期 |
|---|---|---|---|---|
| 函数内局部 `static int x;` | 持久局部状态，只初始化一次 | 静态 | 无（块作用域） | 整个程序 |
| 文件级 `static int g;` | 模块私有全局变量 | 静态 | **内部** | 整个程序 |
| 文件级 `static void f()` | 模块私有函数 | — | **内部** | — |
| C++ 类 `static` 成员 | 所有对象共享一份 | 静态 | 类作用域 | 整个程序 |

### 面试常问的“为什么只初始化一次”

```c
int next_id(void) {
  static int counter = 0;   // 仅首次进入时初始化为 0
  return counter++;
}
```

`static` 局部变量在首次到达声明点时初始化，此后跨越多次调用**保持值**。`counter` 每次调用都 +1，不会重新归零。适合做计数器、缓存、单例。

### “静态”不等于“不变”

`static` 和 `const` 是两回事：`static const int N = 10;` = 文件私有且只读；`static` 管存储期/链接性，`const` 管可写性。可以组合。

### C 与 C++ 的区别要点

- **C 中文件级 `static`**：只影响链接性（内部链接）。常见用于“隐藏实现细节”——模块对外只暴露 `extern` 的 API。
- **C++ 中**：
  - 类内 `static` 成员要在类外**再定义**（C++17 起 `inline static` 可以类内定义）。
  - 局部 `static` 在 C++11 起**线程安全**初始化（magic static 使用 guard 变量 + 原子）。
  - 类 `static const` 整型可在类内初始化，用于编译期常量。

### 为什么要“最小可见性”

把不需要对外的函数/变量设成 `static`，能：
- 避免**符号重名冲突**（尤其多人协作、链接多个库时）。
- 让编译器/链接器减少导出符号，便于优化和内联。
- 降低他人误用接口的概率，符合“接口最小化”封装原则。

### 常见追问

- `static` 全局变量和普通全局变量的区别？——**链接性不同**：普通全局是外部链接，可被 `extern` 在其他文件引用；`static` 全局是内部链接，仅本文件可见。
- 局部 `static` 线程安全吗？——C 里不保证；C++11 起局部 `static` 初始化线程安全。
- `static` 能修饰函数参数吗？——不能。

> 📌 一句话记忆：**`static` 变量 = “闭包式持久状态”+“私有可见性”；`static` 函数 = “只有本文件能看到”。**
