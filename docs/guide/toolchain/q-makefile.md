answer: |
  Makefile 的核心是**规则**：`目标: 依赖\n[Tab]命令`。`make` 根据**时间戳**判断目标是否比依赖新，若依赖更新则重新执行命令（增量构建）。
  关键语法：
  - **变量**：`CC=gcc`、`OBJS=a.o b.o`，使用时 `$(CC)`。
  - **自动化变量**：`$@`（目标名）、`$^`（所有依赖）、`$<`（第一个依赖）。
  - **模式规则**：`%.o: %.c` 匹配一类文件。
  - **伪目标**：`.PHONY: clean`，防止与同名文件冲突。
  - **函数**：`$(wildcard ...)`、`$(patsubst ...)` 处理文件列表。
  - **并行编译**：`make -j`。
  - **条件/包含**：`ifdef`、`include xxx.mk` 组织多目录构建。
why: |
  它解决“**只重编变更的部分，避免全量编译**”。嵌入式源码成百上千文件，全量编译耗时；Make 依赖图让增量构建高效，也是**交叉编译固件/内核**的标准构建方式。
  掌握变量、自动化变量、模式规则，就能写出清晰可维护的构建脚本。

## 深读

### 一个经典最小示例

```make
CC      := gcc
CFLAGS  := -Wall -O2
OBJS    := main.o util.o

app: $(OBJS)
	$(CC) -o $@ $^

%.o: %.c
	$(CC) $(CFLAGS) -c -o $@ $<

clean:
	rm -f $(OBJS) app
```

这里：`app` 依赖 `main.o util.o`，目标比依赖新就不重做；`$@`=`app`，`$^`=`main.o util.o`，`$<`=当前 `.c`。

### 关键概念

| 概念 | 含义 |
|---|---|
| 目标 | 要生成的文件（或伪目标） |
| 依赖 | 生成目标所依赖的文件 |
| 命令 | 每行前必须**一个 Tab** |
| 变量/自动化变量 | `$@`目标、`$^`全部依赖、`$<`第一个依赖 |
| 模式规则 | `%.o: %.c` 泛化匹配 |
| 伪目标 | `.PHONY` 声明，避免与文件同名冲突 |
| `-j` | 并行编译提升速度 |
| `include`/`ifdef` | 组合/条件化，多目录构建 |

### 为什么按时间戳增量

`make` 比较“目标文件时间”与“依赖文件时间”：若某个依赖比目标新（被打包改过），就重跑规则。这样一次改动只重编受影响的 `.o`，再重新链接，极大节省时间。

### 嵌入式构建常见用法

- **交叉编译**：`CC=arm-linux-gnueabihf-gcc`、`CFLAGS=-march=armv7-a` 等。
- **config 生成**：常配 `config.mk`/`kconfig`，`include config.mk`。
- **多目录**：`SUBDIRS` + for 循环递归调用，或用 `make -C sub`。
- **依赖自动生成**：`gcc -MM`/`-M` 生成 `.d` 依赖文件，`include` 进来保证头文件变更也触发重编。

### 常见追问

- 为什么命令要 Tab？——Make 规定命令必须 `Tab` 缩进（不能用空格），用空格会报 “missing separator”。
- `.PHONY` 干什么？——声明像 `clean` 这种**没有真实文件**的目标，避免目录里有个叫 `clean` 的文件时被跳过。
- 怎么只重编改动的？——Make 依赖图 + 时间戳；想让头文件变更也触发，就用 `-MM` 生成 `.d` 依赖。

> 📌 一句话记忆：**Makefile = “目标:依赖 + Tab 命令”，按时间戳增量构建；吃透变量、$@/$^/$<、模式规则、.PHONY 即可。**
