answer: |
  **编译四个阶段**：
  ① **预处理**：展开宏、包含头文件（`#include`）、处理条件编译（`#ifdef`），生成“预处理后的源文件”。
  ② **编译**：把预处理结果翻译成**汇编代码**。
  ③ **汇编**：把汇编翻译成**目标文件 `.o`（机器码）**，符号尚未解析（含符号/重定位信息）。
  ④ **链接**：把多个 `.o` 与**库**合并，**解析符号、重定位**，生成最终可执行文件（或固件/共享库）。
  **静态库（`.a`）**：链接时**整体并入**目标文件生成可执行文件；体积大、无运行时依赖、更新需重新链接，利于裸机/固件部署。
  **动态库（`.so`/`.dll`）**：运行时由**动态链接器加载**；体积小、可共享、可升级，但需运行时存在、有加载开销与版本/ABI 兼容问题。
  嵌入式常侧重**静态链接**：体积可控、无运行时依赖、利于固化到 Flash；系统级（如 Linux 用户态）常用动态库省空间、便于升级。
why: |
  分阶段让你知道“不同错误发生在哪一步”：宏/头文件错在预处理，语法错在编译，符号未定义/重复错在链接。
  静态 vs 动态库是“**大小与独立 vs 共享与升级**”的取舍。嵌入式 Flash/RAM 有限，静态链接体积可控且无运行时依赖；但动态库能在多个进程共享、节省内存、便于升级不打全量。

## 深读

### 四个阶段出错误怎么定位

| 阶段 | 工具 | 常见错误 |
|---|---|---|
| 预处理 | `gcc -E` | 宏未定义、头文件找不到 |
| 编译 | `gcc -S` | 语法/类型错误 |
| 汇编 | `as` | 汇编语法错误 |
| 链接 | `ld` | 符号未定义（undefined reference）、重复符号、找不到库 |

### 静态库 vs 动态库

| 维度 | 静态库（.a/.lib） | 动态库（.so/.dll） |
|---|---|---|
| 链接方式 | 链接时整体并入 | 运行时动态加载 |
| 体积 | 大（代码进可执行文件） | 小（代码在库文件） |
| 运行时依赖 | 无 | 需库存在 |
| 升级 | 需重编/重链 | 单独替换库 |
| 共享 | 各进程各一份 | 多进程共享一份内存 |
| 启动开销 | 无 | 有加载/符号查找 |
| 兼容性 | 稳定 | 有 ABI/版本问题 |
| 适合 | 固件/裸机/嵌入式 | 系统用户态、插件化 |

### 嵌入式里的实际取舍

- **裸机/RTOS 固件**：通常**静态链接**成单一固件镜像，无运行时依赖、体积可控、便于固化与校验。
- **嵌入式 Linux 用户态**：系统库（glibc 等）用**动态库**省空间、便于升级；应用也可静态以便部署。
- **交叉编译**：用 `arm-linux-gnueabihf-gcc` 等，把“编译目标”设为目标架构（ARM/MIPS/RISC-V），与“宿主（x86）”区分。

### 常见追问

- 为什么链接会报 undefined reference？——符号声明了但没定义（漏了实现/没链接对应库），或库顺序问题（`-l` 顺序）。
- 静态链接一定更稳吗？——体积大、升级麻烦；动态库可能因版本不兼容而“缺符号”。没有绝对，看场景。
- `.o` 里符号为什么没解析？——编译/汇编阶段只生成机器码与重定位信息，符号地址要链接器统一分配。

> 📌 一句话记忆：**预处理→编译→汇编→链接；静态库=链接时并入（大、独立），动态库=运行时加载（小、共享、能升级）。**
