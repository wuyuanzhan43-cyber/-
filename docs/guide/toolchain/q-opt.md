answer: |
  gcc 常用优化等级（`-O`）：
  - **`-O0`**：不优化，编译快、便于断点/单步调试，变量保持原样（便于看值）。
  - **`-O1`**：基础优化（死代码消除、常量折叠等）。
  - **`-O2`**：常用优化（较好性能，含更多优化；是很多项目的默认）。
  - **`-O3`**：更多激进优化（可能增大体积/内联、改变时序）。
  - **`-Os`**：以**体积**为优先（嵌入式常用，省 Flash/RAM）。
  - **`-Og`**：面向调试的优化（保留可调试性同时适度优化）。
  **`-g`**：生成调试信息（符号），配合 `-O0/-Og` 便于 gdb 调试。
  **与 volatile 关系**：优化会让**编译器缓存变量到寄存器、删减读写、调整时序**；对**MMIO 寄存器、被中断改的变量**必须用 `volatile` 阻止这些优化，否则读到旧值。**高优化等级更容易暴露“忘加 volatile”的 bug**。
why: |
  优化等级是“**性能/体积 vs 可调试性、确定性**”的权衡：`-O0` 好调试但慢，`-O2/-Os` 性能/体积好但更难调试、且更依赖 `volatile`/严格别名等正确性。
  嵌入式**发布**用 `-O2`/`-Os`，**调试**用 `-O0`/`-Og`；优化越高，**编译器偷偷做的“缓存/删减/重排”越多**，所以 MMIO、中断共享变量、指针别名要写得**符合标准**（volatile、restrict、atomic）。

## 深读

### 优化等级对照

| 等级 | 特点 | 用途 |
|---|---|---|
| -O0 | 不优化，变量保留，易断点 | 调试 |
| -O1 | 基础优化 | 折中 |
| -O2 | 常用，性能较好 | 发布默认 |
| -O3 | 更激进（内联/可能变大） | 追求性能 |
| -Os | 体积优先 | 嵌入式省 Flash |
| -Og | 保留可调试性的优化 | 调试+适度优化 |
| -g | 生成调试符号 | 配 gdb |

### -O0 为什么好调试

- 编译不做激进优化，**局部变量仍在栈上**、可随时查看，单步执行与源码对齐。
- 高优化会**把变量放寄存器/删除**，导致 gdb 看不了值、行号错乱。

### 优化与 volatile

编译器优化可能：
1. **寄存器缓存**：把变量读进寄存器，之后不回读内存 → 外部/中断改了但代码仍用旧值。
2. **删减读写**：认为“没人读”就删除赋值。
3. **重排/内联**：调整时序。

对 **MMIO 寄存器、被硬件/中断修改的变量**，必须 `volatile` 阻止这些优化。

### 使用建议

- **调试**：`-g -O0`（或 `-Og`）。
- **发布**：`-O2`（性能）或 `-Os`（体积，嵌入式常选）。
- 高优化前先确保**代码符合标准**（volatile/别名/UB），否则优化会“放大”错误。
- 可用 `-Wall -Wextra` 提前发现未定义/未用等。

### 常见追问

- 为什么 `-O2` 下程序变了？——优化缓存/删减/重排，暴露了未加 volatile、UB、别名问题。
- `-Os` 和 `-O2` 区别？——`-Os` 偏向省代码体积，`-O2` 偏向速度。
- 调试为什么要 `-O0`？——变量保留、可断点、源码对齐；高优化会让变量“消失”或行号错乱。

> 📌 一句话记忆：**-O0/-Og 好调试，-O2/-Os 好性能体积；优化越高越依赖 volatile/正确性，MMIO 与中断共享变量必须 volatile。**
