answer: |
  Linux 进程间通信（IPC）常见方式：
  - **管道/命名管道（pipe / FIFO）**：**单向字节流**，适合父子进程/本地简单传数据；`pipe`（匿名，父子）、`mkfifo`（有名字，可多进程）。
  - **消息队列（SysV/POSIX message queue）**：**有类型、有边界**的消息，按优先级/类型读取。
  - **共享内存（shm）**：多个进程**映射同一块物理内存**，速度最快（零拷贝），但要**配合信号量/锁**同步（shm_open + mmap）。
  - **信号（signal）**：**异步通知**（如中断），不能传大量数据，只发事件/信号（如 `SIGINT`）。
  - **信号量（semaphore）**：用于**互斥/同步**，常与共享内存配合。
  - **Socket（本机 AF_UNIX / 网络）**：统一网络/本机通信接口。
  选型：**大量数据、快 → 共享内存；有边界消息 → 消息队列/管道；事件通知 → 信号；跨机/跨进程标准 → socket**。进程间**地址空间隔离**，所以传数据要**拷贝或共享映射**。
why: |
  进程**地址空间互相隔离**，不能像线程那样直接共享内存，必须通过**内核提供**的 IPC 机制。不同方式权衡“**速度、数据量、是否有边界、是否阻塞、是否需要同步**”：
  - **共享内存快但需同步**（原子/信号量）；
  - **管道/队列**有拷贝但有边界、自动同步；
  - **信号**只做轻量通知。
  **线程**因共享地址空间，IPC 更简单（共享变量+锁）；**进程**因隔离，需要上面这些机制。跨机器则用 socket。

## 深读

### 常见 IPC 对照

| 方式 | 数据 | 同步 | 速度 | 用途 |
|---|---|---|---|---|
| 管道/FIFO | 字节流 | 自动 | 中 | 父子进程、简单传数据 |
| 消息队列 | 有类型消息 | 自动 | 中 | 有边界/多类型 |
| 共享内存 | 原始内存 | 需信号量/锁 | 快 | 大量数据、高吞吐 |
| 信号 | 事件(无数据) | — | 快 | 异步通知 |
| 信号量 | — | 互斥/同步 | 中 | 配共享内存 |
| Socket | 字节流/报文 | 自动 | 中 | 本机/跨机标准 |

### 为什么进程要 IPC，线程不用

- **进程**：独立地址空间、互不干扰，但**不能直接共享变量** → 需要 IPC（拷贝或共享映射）。
- **线程**：共享地址空间 → 直接用共享变量/全局 + 锁。

### 经典选型

- **父子进程传简单数据**：`pipe`。
- **多个无关进程、有边界消息**：消息队列 / FIFO。
- **大块数据高频传输**：共享内存（`shm_open`+`mmap`）+ 信号量同步。
- **轻量事件通知**：`kill`/`sigqueue` 发信号。
- **跨机器/统一标准**：Socket（`AF_UNIX` 本机、`AF_INET` 网络）。

### 常见追问

- 共享内存为什么要同步？——多个进程同时读写同一物理内存，不加锁会竞态/不一致。
- 管道和消息队列区别？——管道是**无类型字节流**（按顺序读），消息队列是**有类型/边界**的消息（可按类型取）。
- 进程和线程 IPC 差异？——线程共享地址空间（直接共享），进程需 IPC 机制（拷贝/映射）。
- 共享内存为什么快？——映射同一物理页，**零拷贝/少拷贝**，省去管道/队列的内核↔用户拷贝。

> 📌 一句话记忆：**IPC 因进程隔离而必需；管道/队列=拷贝+有边界，共享内存=快但需同步，信号=轻量事件，跨机用 socket；线程则直接共享变量。**
