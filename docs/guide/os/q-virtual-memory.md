answer: |
  **虚拟内存**：给每个进程一个**独立虚拟地址空间**，由**页表**把**虚拟页（VA）映射到物理页（PA）**。
  核心机制：
  - **分页**：内存按页（如 4KB）划分；页表记录 VA→PA 与权限。
  - **缺页（page fault）**：访问不在内存的页 → 触发缺页异常 → 从磁盘/文件**调入**（按需加载）。
  - **页面置换**：内存满时选择被换出的页（**LRU** 最近最少使用、FIFO、**Clock** 等）。
  - **写时复制（COW）**：`fork` 共享只读页，写时才复制，节省内存。
  - **共享/映射**：多进程共享同一物理页（共享库、`mmap`）。
  好处：**地址隔离/保护、按需加载、进程虚拟地址大于物理、共享、写时复制**。
why: |
  虚拟内存让“**程序能看到大而连续的地址**、进程互相隔离、按需用内存”。它是**现代 OS 的基石**。
  理解**分页/页表/缺页/置换**才能解释：为什么内存不足会换页（抖动），为什么 `fork` 快（COW），为什么 `mmap` 共享省内存，以及**缺页/置换的性能影响**。与 MMU（硬件）配合，缺页/置换由内核软件处理。

## 深读

### 分页与页表

- 页大小常见 4KB（多级页表减少内存占用）。
- 页表项：物理页号 + 权限（RWX/用户内核）+ 有效位 + 缓存属性。
- **TLB** 缓存最近 VA→PA，减少查页表；上下文切换/TLB 失效需 flush。

### 缺页（按需加载）

- 访问**不在内存**的页 → 缺页异常 → 内核从磁盘/文件/交换空间调入，**返回继续执行**。
- 换页 + 置换：内存满，选一页换出（写回/丢弃），调入所需页。
- **抖动（thrashing）**：频繁缺页/换页，系统性能骤降。

### 页面置换算法

| 算法 | 思想 | 特点 |
|---|---|---|
| FIFO | 先进先出 | 简单、可能 Belady 异常 |
| LRU | 最近最少使用 | 效果好、实现成本高 |
| Clock | 近似 LRU（引用位） | 折中、常用 |
| Optimal | 未来最久不用 | 理想、不可实现（只作对照） |

### 写时复制（COW）与共享

- `fork` 时**共享只读页**，任一进程写才**复制** → 节省内存、`fork` 快。
- `mmap` 共享内存/文件映射，多进程共享同一物理页。

### 常见追问

- 为什么虚拟内存能“超售”？——按需分页 + 缺页 + 置换，同物理页可被多进程共享（COW/共享库）。
- 缺页一定会换出页吗？——不一定；有物理内存就分配，满才置换。
- 为什么 `fork` 快？——COW，先共享只读页，写时再复制。
- LRU 为什么好但难实现？——效果好但维护访问顺序开销大；用 Clock 近似。

> 📌 一句话记忆：**虚拟内存=分页+页表(VA→PA)+缺页按需调入+页面置换(LRU/Clock)+写时复制(COW)；实现隔离/共享/按需/超售。**
