answer: |
  **看门狗（Watchdog）**是一个**独立计时器**，若程序在规定时间内**未被“喂狗”（重载/清除计数值）**，则触发**系统复位**或中断。用于在程序**跑飞/死循环/卡死**时自动恢复系统。
  **使用要点**：
  ① **喂狗位置要合理**——放在“确认系统健康”的关键路径（主循环末尾/关键任务），而非随便一个地方；
  ② 别在**死循环里盲目喂狗**掩盖故障；
  ③ 有**窗口看门狗**：要求喂狗时间落在**给定窗口内**（太早太晚都会复位），防止“反复空转喂狗”；
  ④ 启动时看门狗默认要能安全复位，避免异常持久化；
  ⑤ 喂狗操作要**受控**（不能成为掩盖 BUG 的手段），配合**错误检测/断言**。
why: |
  嵌入式常**无人值守**（汽车、工业、家电），遇到软件 bug 或外部干扰导致**卡死**，最可靠的办法是**硬件看门狗自动复位**，让系统重新跑起来，而不用人等它。
  核心工程智慧是“**在哪里喂狗**”：要在确认“主流程健康、任务按预期推进”的地方喂，这样一旦某处卡死，喂狗就断了，看门狗立刻复位；而不是在任意空闲处喂，那样故障会被掩盖。

## 深读

### 看门狗原理

```
上电 -> 看门狗开始倒计时
       主程序正常运行，定期“喂狗”（重置计数器）
       若主程序卡死/跑飞 -> 喂狗停止 -> 计数到 0 -> 触发复位/中断
```

- **独立看门狗（IWDG/独立时钟）**：独立于主时钟，即使主时钟异常也能复位，更可靠。
- **窗口看门狗（WWDG）**：要求喂狗时间在窗口内（不能太早也不能太晚），防止“循环空转骗过看门狗”。

### 典型场景与优劣

| 类型 | 特点 | 适用 |
|---|---|---|
| 独立看门狗（IWDG） | 独立时钟、可靠 | 无人值守、需要强复位 |
| 窗口看门狗（WWDG） | 要求窗口内喂，防空转 | 需要“检测空转/异常循环” |
| 软件看门狗（任务监控） | 主任务定时喂狗，监控所有任务心跳 | 多任务/RTOS 系统监控谁在跑飞 |

### 在哪喂狗（最关键）

喂狗点要能反映“**系统健康**”，核心不是“有没有喂”，而是“**在哪喂**”。喂错地方，看门狗形同虚设，甚至掩盖故障。

- **不要**在“空闲/idle”里喂——那掩盖了业务卡死。
- **不要**在死循环里**盲目喂**——故障被掩盖。
- **应该**在“确认关键逻辑正确执行到某步”之后喂，如：
  - 主循环末尾（所有任务都过了一遍）。
  - 每个关键任务周期性更新自己的心跳，看门狗任务汇总后再喂。
- **喂狗间隔** < 看门狗超时，且留足够余量，避免误复位。

**几种喂法及后果**：

| 喂法 | 结果 |
|---|---|
| **在空闲/idle 里喂** | 业务任务卡死了，主线程/空闲仍能喂 → **看门狗不触发，故障被掩盖** |
| **在 main 循环最前面盲喂** | 只要循环在跑就喂 → 卡在某一步也照样喂 → **失效** |
| **在“确认关键逻辑执行到某步”之后喂**（如每个周期任务都过了、心跳正常） | ✅ 一旦某任务/步骤卡死，后续喂狗就断了 → **看门狗正常复位** |
| **每个周期任务上报心跳，汇总后再喂**（多任务） | ✅ 能定位“哪个任务没上报”，比单点喂更细 |
| **喂狗间隔太靠近超时** | 一点抖动就误复位（**误复位**） |

**关键结论**：
- **喂狗点要能反映“系统健康”**——放在“确认主流程/关键任务都推进到某步”之后，而不是随便一个“能执行到的地方”。
- **别在空闲处喂**（掩盖卡死）、**别在死循环里盲目喂**。
- **多任务**：各任务上报心跳，看门狗任务汇总后再喂 → 能**发现是哪个任务跑飞**。
- **间隔留余量**：喂狗间隔 < 看门狗超时，但要留足够余量避免误复位。

**那什么时候该复位**：当“喂狗的链断了”（某个关键步骤没走到/某任务没上报心跳）→ 自动复位，恢复系统。这才是看门狗的**正确用途**。

### 使用禁忌（面试常问“坑”）

1. **喂狗太随意** → 掩盖故障，看门狗形同虚设。
2. **喂狗间隔 < 看门狗超时过近** → 轻微抖动就复位（误复位）。
3. **没初始化/没启动看门狗** → 无保护。
4. **复位后状态未处理** → 反复复位（复位循环），要区分“首次上电”与“看门狗复位”。
5. **关中断但喂狗在主循环** → 中断里的死循环可能挡住喂狗（异常时仍会复位，反而是保护）。

### 与软件容错一起用

看门狗是**最后防线**；配合**断言、错误计数、状态机、任务心跳监控**能更早发现并恢复异常，而不必等复位。

### 常见追问

- 为什么嵌入式一定要看门狗？——无人值守，硬件自动复位比人工干预可靠。
- 窗口看门狗为什么能防“空转”？——它要求喂狗点在窗口内（不能太早/太晚），若程序在“错误路径循环”快速喂狗，会因“太早”而复位。
- 看门狗复位和上电复位怎么区分？——读复位标志寄存器（RCC/复位原因），据此做不同初始化。

> 📌 一句话记忆：**看门狗=独立计时器，不喂狗就复位；要点是“在确认健康处喂、别瞎喂”（别在空闲/死循环里喂，会掩盖故障），多任务用心跳汇总再喂；窗口看门狗还能防空转。**
