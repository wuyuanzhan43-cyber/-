answer: |
  **实时性**指系统能在**确定的、可预期的时限内**完成特定任务（响应），关键不是“多快”，而是“**确定性/可预测**”——每次都在规定时间内响应。
  - **硬实时**：错过时限=系统失败（甚至灾难），如安全、飞行控制。必须**保证**。
  - **软实时**：偶尔错过时限影响轻微（如音频、视频），但有最好时限，通常“尽可能快+高概率满足”。
  **常见实时性指标**：
  - **中断延迟**：从硬件事件到进入中断处理的时间。
  - **中断响应/处理时间**：中断处理耗时。
  - **任务切换/上下文切换时间**：切换任务的成本。
  - **调度延迟**：就绪到被调度真正执行的时间（与调度器、抢占、临界区有关）。
  - **抖动（jitter）**：响应时间的**波动**，硬实时尤其看重上限与抖动。
  衡量常看“**最坏情形响应时间**（WCET/WCRT）”，而不仅是平均。
why: |
  实时系统追求“**确定性**”而非“平均速度”。因为安全/控制要求“**最坏情况下也要在时限内**”，所以看**WCET/WCRT、中断延迟、抖动上限**。
  影响实时性的因素：**关闭中断/长临界区**（延迟中断）、**调度策略**（优先级、是否可抢占）、**阻塞操作**（睡眠锁/耗时系统调用）、**缓存/异常**等。实时 RTOS 通常做**优先级抢占 + 短临界区 + 避免不可预测的阻塞**来保证下限。

## 深读

### 硬实时 vs 软实时

| | 硬实时 | 软实时 |
|---|---|---|
| 错过时限 | 系统失败（灾难） | 性能下降，可接受 |
| 例子 | 安全气囊、飞行控制、工业安全 | 音视频、人机交互 |
| 要求 | **必须**保证最坏时限 | 高概率尽快，允许偶尔超标 |

### 关键时延指标

| 指标 | 含义 | 影响 |
|---|---|---|
| 中断延迟 | 事件→进入中断处理 | 关中断/长临界区会拉长 |
| 上下文切换 | 切换任务成本 | 栈/寄存器保存恢复、TLB |
| 调度延迟 | 就绪→真正运行 | 抢占策略、临界区、优先级 |
| 抖动 jitter | 响应波动 | 硬实时关心上限与波动 |

### 为什么“最坏情形”比“平均”重要

实时系统要保证“**每次都来得及**”，所以关心**WCRT（最坏情形响应时间）**与**抖动上限**：平均很快但偶尔超时 = 对硬实时不可接受。分析常用：**最坏执行时间(WCET) + 调度分析**（如速率单调/响应时间分析）。

### 影响实时性的因素与对策

1. **关中断/长临界区** → 拉长中断延迟：**缩短临界区**、分层优先级。
2. **不可预测的阻塞**（睡眠锁/耗时系统调用/动态分配） → 用**非阻塞/固定分配**。
3. **调度策略** → **优先级抢占**，高优先级任务尽快被调度；避免**优先级反转**（用带继承的互斥锁）。
4. **缓存/内存访问** → 确定性与抖动：可锁定、预取、禁止非确定路径。
5. **中断处理过重** → 拆成**上半部分（快）+ 底半部/任务**。

### 嵌入式常谈的“每周期抖动”

控制/音频/传感器采样要求**采样周期稳定**——抖动要小。做法：高优先级任务跑主循环、定时器中断驱动、短临界区、避免被低优先级任务抢占。

### 常见追问

- 实时就是快吗？——不是，是**确定/可预期**：每次都在时限内，而不是“偶尔特别快”。
- 怎么保证硬实时下限？——优先级抢占 + 可抢占调度 + 短临界区 + 可预测资源访问 + WCRT 分析。
- 为什么关中断越长响应越差？——关中断延迟了所有低一级中断，拉长中断延迟与抖动。

> 📌 一句话记忆：**实时性=确定性（每次都在时限内），看 WCRT/中断延迟/抖动；用优先级抢占+短临界区+非阻塞保证下限。**
