  - 可用**临界区**（关中断/禁抢占）避免被更高优先级中断打断。
why: |
  优先级让“**最紧急的（传感器数据、系统时钟、安全）**”优先处理，提升实时性；嵌套让高优先级能**插队**，进一步保证硬实时。
  但嵌套增加**复杂度**：要保证可重入（不能依赖会被破坏的全局状态）、共享数据无竞争、栈预算充足、临界区得当。嵌入式常按“实时性/紧迫度”划分优先级，并精细控制临界区。

## 深读

### 中断优先级怎么定

- **数值越小优先级越高**（NVIC 常见习惯）。
- 可分组：**抢占优先级（可嵌套）** + **子优先级（同抢占级内决定顺序，不嵌套）**。
- 高实时/安全要求 → 高优先级（时钟、保护、数据采集关键路径）；普通 → 低优先级（UI、日志）。

### 嵌套会发生什么

```
H（高）: ... 触发，打断正在跑的 L
L（低）: 正在执行中断处理 → 被 H 打断
        → H 执行完 → 返回到 L 继续
        → 需保证 L 是“可重入/安全”的（共享数据已保护）
```

如果 L 正在改一个共享变量，H 也改它 → 数据竞争。解决：L 在临界区时**临时屏蔽 H 的优先级**（设置 PRIMASK/优先级屏蔽），或 H 里也一样短。

### 可重入与竞态

- **可重入**：函数被多重调用（含被中断打断后再次调用）仍是安全的，不依赖会被破坏的全局状态。
- **临界区**：共享资源访问段用**关中断**（`disable_irq`/`__disable_irq`）或**自旋锁（禁抢占）**，但要**短**。
- 中断里不要用会阻塞的锁。

### 嵌套的代价

- **栈深度**：每层嵌套用一层栈，多级嵌套+大局部变量 → 栈溢出（HardFault）。
- **中断响应不确定性**：嵌套越深、临界区越长，低优先级中断的触发延迟越大。
- 实践：**尽量短的中断处理 + 合理的优先级分层 + 栈余量**。

### 常见追问

- 为什么数值小优先级高？——ARM NVIC 约定，避免混淆。
- 怎么避免嵌套带来的竞态？——关键资源用关中断/自旋锁/临时提升优先级保护，并保持临界区极短。
- 中断嵌套会加深栈吗？——会，嵌套的每层都用栈，要预算。
- 什么情况不该嵌套？——临界区、栈紧张、对延迟敏感一致性的场合，常关嵌套（原子）。

> 📌 一句话记忆：**优先级决定“谁先响应”（数值小=高）；嵌套让高优先级插队，但必须可重入、护共享数据、留足栈、短临界区。**
