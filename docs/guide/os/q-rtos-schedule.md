answer: |
  RTOS 调度器负责**决定哪个任务此刻运行**。常见策略：
  - **优先级抢占式调度**：**就绪队列中优先级最高**的任务运行；高优先级任务一旦就绪，**立即抢占**低优先级任务（preemptive）。
  - **时间片轮转（Round-Robin / time slicing）**：**同优先级**任务**轮流**运行，每个任务运行一个时间片后切到下一个，避免同优先级某个任务独占 CPU。
  - **协作式（cooperative）**：任务**主动让出**（`taskYIELD`/阻塞）才切换，非抢占。
  **任务状态**：运行/就绪/阻塞（等待事件/延时）/挂起（suspend），调度器只调度**就绪**任务。
  FreeRTOS 等常见机制：**优先就绪队列 + 优先级抢占；同优先级用时间片（`configUSE_TIME_SLICING`）**；阻塞（队列/信号量/延时）让出 CPU；**中断可唤醒更高优先级任务触发调度**（`FromISR`）。
why: |
  实时系统的关键是“**高优先级任务及时运行**”，所以用**优先抢占**保证紧急任务优先；同时用**时间片**避免同优先级任务饿死/独占。**阻塞让出 CPU** 让系统在等待时不空转。
  优先级 → 抢占；时间片 → 同优先级公平；阻塞 → 让出。理解这三者就能分析“为什么高优先级不执行、为什么同优先级卡住、为什么调度延迟大”。

## 深读

### 调度策略对比

| 策略 | 规则 | 适用 |
|---|---|---|
| 优先级抢占 | 就绪队列最高优先级先跑，可抢占 | 实时任务（默认常见） |
| 时间片轮转 | 同优先级轮流，各跑一个时间片 | 避免同优先级独占 |
| 协作式 | 任务主动让出才切换 | 简单/资源少 |

### FreeRTOS 调度的关键点

- **就绪链表**按优先级维护；调度器取**最高优先级的就绪任务**运行。
- **抢占**：高优先级任务进入就绪（如中断里 `give` 唤醒）会**触发任务切换**（`portYIELD_FROM_ISR`）。
- **同优先级**：`configUSE_TIME_SLICING=1` 时按时间片轮转。
- **状态切换**：运行→阻塞（等事件/延时）→就绪（事件到）→再运行；挂起需显式。

### 为什么“高优先级不跑/卡住”常见原因

1. **低优先级/中断占了 CPU**：长临界区、关中断、或更高优先级任务持续运行。
2. **优先级反转**（用裸信号量/无继承）。
3. **任务被阻塞（等事件）**：事件一直没来。
4. **时间片/同优先级公平**影响：同优先级轮流，延迟增加。

### 实时性与抖动的来源

- 调度延迟：就绪→真正运行的时间（受临界区、关中断、中断优先级影响）。
- 同优先级时间片：被同级任务分摊，需权衡时间片大小。
- 阻塞/唤醒开销、上下文切换成本。

### 常见追问

- 为什么高优先级任务还要被中优先级任务压？——优先级反转：持锁的低优先级被中优先级抢占，高优先级等锁，需优先级继承。
- 时间片轮转什么时候用？——多个同优先级任务需要公平共享 CPU；否则单高优先级独占。若只有高优先级任务就绪，低优先级不跑（合理）。
- 任务怎么让出 CPU？——调用 `taskYIELD`（让给同优先级/更高优先级）、或进入阻塞（延时/等事件）。

> 📌 一句话记忆：**优先抢占=高级先跑可抢占；时间片=同优先级轮流；阻塞=让出CPU不空转；调度延迟看临界区/关中断/优先级。**
