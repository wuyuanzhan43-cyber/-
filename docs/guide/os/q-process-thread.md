  **线程**是 CPU 调度的基本单位，同一进程内的线程共享该进程的地址空间与资源，但各自有独立的栈与寄存器上下文；线程切换开销更小，但也因共享地址空间而更容易互相影响、需同步。
  区别核心：**资源拥有 vs 调度单元**。进程=资源容器，线程=执行流；进程间切换开销大（要切地址空间/页表），线程间切换只切栈与寄存器（不切地址空间）。
  RTOS 里通常叫**任务（task）**，大体对应“线程”概念：它有自己的栈与优先级，被调度器按优先级抢占式调度。
why: |
  这是“隔离与效率”的权衡。进程隔离性强、容错好但切换成本高；线程轻量、切换快、易共享但要小心并发与崩溃传染。
  嵌入式常因 RAM 有限而选择线程/任务而非多进程：线程共享地址空间省内存，且 RTOS 任务模型天然对应“轻量线程”。但省内存的代价是要用信号量/互斥锁/消息队列管理共享资源。

## 深读

### 类比理解

- **进程** = 一个独立的“公寓”，有自己的一整套家具（地址空间、文件、信号），互相隔开。
- **线程** = 同一公寓里的“多个房间/人”，共用客厅（地址空间/全局资源），但各有各的床（独立栈）。

### 核心区别对照

| 维度 | 进程 | 线程 |
|---|---|---|
| 概念 | 资源分配单位 | CPU 调度单位 |
| 地址空间 | 独立（页表隔离） | 共享（同进程内） |
| 资源 | 独立（文件、信号、…） | 共享（文件、堆、全局变量） |
| 栈 | 独立 | 独立（各自栈） |
| 切换开销 | 大（切地址空间/页表/TLB） | 小（切栈+寄存器，不切 MMU 上下文） |
| 通信 | IPC（管道/消息/共享内存/信号量） | 共享内存 + 锁 |
| 容错 | 一个崩溃不影响其他进程 | 一个线程崩溃往往连带整个进程 |
| 适用 | 强隔离、稳定性优先 | 高并发、低开销、共享数据 |

### 为什么线程更轻

线程切换不需要切换地址空间（保留页表/TLB），只需保存/恢复 **寄存器 + 栈指针 + 一些线程局部状态**，因此上下文切换成本远低于进程切换。这也是高性能网络服务（多线程/线程池）流行的一个原因。

### RTOS 里的“任务”

RTOS（FreeRTOS、RT-Thread、μC/OS）里用**任务/线程（task/thread）**这一概念，并无真正的“进程”。特点：

- 每个任务有独立**栈**（RAM 预算好）和**优先级**。
- 靠**抢占式优先级调度**或**时间片轮转**调度。
- 任务间用**消息队列、信号量、互斥锁、事件组**同步/通信。
- 任务可以有不同的状态：运行/就绪/阻塞/挂起。

### 常见追问

- 一个进程能死掉一个线程吗？——单线程进程里线程即进程主体；多线程进程里线程崩溃通常会终止整个进程（收到信号）。
- 为什么进程要隔离？——稳定性与安全，避免一个模块越权访问另一模块内存。
- 线程共享哪些、不共享哪些？——共享代码段、数据段、堆、打开文件；**不共享栈、寄存器、程序计数器**。

> 📌 一句话记忆：**进程=资源容器（隔离贵），线程=执行流（轻量但要同步）；RTOS 用“任务”近似线程。**
