  CPU 通过**特权级别**区分用户态与内核态（如 ARM 的 User/System 与 SVC、x86 的 Ring3/Ring0）。用户态权限受限，不能直接访问硬件、I/O、内核内存；内核态拥有最高权限，可执行特权指令、访问全部内存与设备。
  从用户态进入内核态的**唯一正规途径是“陷入”**：系统调用（swi/ecall/syscall）、异常、中断。它们触发特权级切换，把控制权交给内核，由内核代表程序访问敏感资源。
  进入内核态的代价：要保存用户现场、切换栈、切换特权级，较慢，因此要**减少系统调用次数、批量操作**（如 read/write 大缓冲、mmap、io_uring/netlink）。
why: |
  这是现代 OS 的**保护与隔离基石**。用户程序不可信，必须被限制在隔离的用户空间运行，不能随便读写内核/外设，否则一个 bug 就会让整机崩溃或被攻击。
  系统调用是“受控的通行证”：程序提出请求，内核在特权级下核验并代做，从而实现安全性、稳定性与可移植性。

## 深读

### 特权级与“陷入”

| 概念 | 说明 |
|---|---|
| 用户态 | 受限执行，不能访问硬件/内核内存 |
| 内核态 | 最高特权，可访问一切 |
| 陷入（trap）/ 系统调用 | 从用户态主动进入内核态的途径 |
| 中断 | 硬件/事件异步打断，特权切换 |
| 异常 | 非法操作（除零、缺页）触发 |

常见指令：ARM `svc`/`swi`、RISC-V `ecall`、x86 `syscall`。

### 系统调用流程（嵌入式 Linux）

1. 用户程序调用 `read()`，进入 libc 封装。
2. 通过特定寄存器传系统调用号与参数，执行 `svc`/`syscall`。
3. CPU 陷入内核，切换到内核栈，进入内核态。
4. 内核按系统调用号查表，执行对应服务（如 `sys_read` → VFS → 驱动）。
5. 返回结果，恢复用户现场，切回用户态。

### 为什么“少调用、批量”更快

每次陷入都要**保存现场 + 切换栈 + 切特权级**，是相对昂贵的操作。所以高性能路径用：

- **更小的系统调用次数**：一次读大块，而非多次读小片。
- **`mmap`/零拷贝**：避免内核↔用户拷贝边界。
- **`io_uring`**：批量提交、异步提交，减少陷入次数。
- **`splice`/`sendfile`**：内核态直接转发数据，减少拷贝。

### 与嵌入式 RTOS 对比

RTOS（FreeRTOS 等）通常**没有严格用户态/内核态**：任务都跑在最高特权级，直接访问硬件。优点是快、简单，缺点是**任务没有隔离**，一个任务越界可能搞挂系统。有些 MCU 用 MPU（内存保护单元）实现折中的分区保护（如 RT-Thread 的部分方案）。

### 常见追问

- 用户态能直接操作寄存器吗？——主流 OS 下不能，要通过系统调用/驱动；裸机开发可以，但那就没有 OS 保护。
- 为什么系统调用比函数调用慢？——函数调用只是压栈跳转；系统调用要特权级切换 + 现场保存恢复。
- 怎么减少系统调用开销？——批量、mmap、io_uring、减少拷贝。

> 📌 一句话记忆：**用户态受局限，靠“陷入（系统调用/中断）”切换到内核态代做敏感操作；(通过减少陷入次数) 才能更快。**
