## 深读

### 一、为什么需要用户态 / 内核态（从原理推导）

把“程序不可信”当成前提：任何用户程序都可能有 bug、可能被攻击，**绝不能让它拥有直接操作硬件与内核内存的权限**。所以 CPU 用**特权级**把执行分为两档：

- **用户态（低特权）**：只能访问自己的地址空间、执行普通指令；碰到硬件/I/O、特权指令就会**触发异常**（而不是成功执行）。
- **内核态（高特权）**：可执行特权指令、访问全部内存与设备，替用户程序做“它自己不该做”的事。

这一隔离带来三件事：
1. **稳定**：用户程序越界/非法访问不会拖垮整机（内核保护）。
2. **安全**：恶意程序无法直接读写内核/他人内存。
3. **可移植**：内核统一抽象硬件，程序不用关心底层细节。

> 引申：这就是为什么 **裸机开发没有这一层**——裸机程序直接最高特权跑，快，但没有保护；而上了操作系统，就必须遵守“用户态受限、内核态代办”的规则。

### 二、图示：特权级与“陷入”

```
用户态(低特权)                    内核态(高特权)
┌──────────────────────┐        ┌──────────────────────┐
│  user process        │        │  kernel              │
│  read/write/...      │        │  sys_read/open/...   │
│  只能访问自己的地址空间 │        │  可访问全部内存/硬件    │
└──────────┬───────────┘        └──────────▲───────────┘
           │ ① 系统调用(svc/syscall)          │
           │ ② 中断(硬件异步)                 │
           │ ③ 异常(除零/缺页)                │
           └────────── 陷入(trap) ──────────┘
                     特权级切换 + 保存现场 + 切栈
```

三条进入途径：**系统调用**（主动）、**中断**（硬件异步）、**异常**（非法操作）。对应指令：ARM `svc/swi`、RISC-V `ecall`、x86 `syscall`。

### 三、系统调用的完整链路

以 `read()` 为例：

```
应用(read) → libc 封装 → 传系统调用号+参数到寄存器 → svc/syscall
  → CPU 陷入内核：保存用户现场、切到内核栈、特权级切换
  → 内核按系统调用号查表(sys_call_table) → sys_read
  → VFS → 具体文件系统 → 驱动 → 取数据到内核缓冲
  → copy_to_user 拷到用户缓冲 → 恢复现场、切回用户态 → 返回 fd/长度
```

**关键点**：从用户态“进内核”只有这条正规路线；直接访问硬件/内核内存会触发保护异常。

### 四、为什么“少调用、批量”更快（原理）

一次陷入的开销 = **保存现场 + 切换栈 + 特权级切换 + 可能缓存/TLB 变化**，远大于一次普通函数调用。所以：

| 手段 | 减少什么 |
|---|---|
| 一次 `read` 大块 vs 多次小读 | 减少陷入次数 |
| `mmap` | 消除内核↔用户的数据拷贝 |
| `io_uring` | 批量提交、异步提交，减少陷入次数 |
| `splice`/`sendfile` | 内核态直转，避免中间拷贝 |

### 五、易错点与常见坑

- **别把“用户态”当成“能直接碰硬件”**：想操作外设/寄存器，必须走系统调用或驱动；裸机才可以直接。
- **别在用户态解引用内核指针**：用户进程拿到内核地址无法访问（隔离），要 `copy_to_user/from_user`。
- **别频繁系统调用**：高频小读小写会拖慢（陷入开销），要缓冲/批量。
- **中断 ≠ 系统调用**：中断是硬件异步打断（可能发生在任意时刻），系统调用是用户主动发起；两者都切特权级，但语义不同。

### 六、常见追问与满分回答

**Q：用户态能直接操作寄存器吗？**
A：主流 OS 下不能。寄存器/硬件属于特权资源，用户态访问会触发保护异常；必须通过系统调用或驱动（内核态）代做。裸机开发可以，但那意味着没有 OS 保护。（加分：MCU 里常用 MPU 做折中分区保护。）

**Q：系统调用为什么比函数调用慢？**
A：函数调用只是压栈+跳转，开销很小；系统调用要**特权级切换 + 保存/恢复用户现场 + 切换栈 + 可能的 TLB/cache 变化**，还要经过内核查表分发。所以要**批量、减少陷入次数**。

**Q：怎么减少系统调用开销？**
A：① 一次读大块；② `mmap` 零拷贝；③ `io_uring`/批量（异步批量提交）；④ `sendfile`/`splice` 内核直转。核心都是“少陷入、少拷贝”。

**Q：中断和系统调用都进内核，区别？**
A：发起方不同——系统调用是**用户主动**请求（同步、有语义）；中断是**硬件异步**打断（时机不定，可能发生在任意上下文）。中断进入的是上下文、不能阻塞；系统调用在用户上下文、可调度。

> 📌 一句话记忆：**用户态受限，靠“系统调用/中断/异常”陷入内核态代做敏感操作；陷入贵（保存现场+换栈+切特权级），所以少调用、批量、mmap/io_uring。**
