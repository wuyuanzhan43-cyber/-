answer: |
  **关键陷阱：** 有符号和无符号混用，**有符号会隐式转成无符号**，导致比较/运算结果出错。
  ```c
  int a = -1;
  unsigned b = 0;
  if (a < b) ...   // false! 因为 a 被转成无符号(0xFFFFFFFF)，反而 > b
  ```
  **整型提升**：较小整数（char/short）参与运算会**提升到 int**；有符号+无符号运算时，**按更大范围/优先级转无符号**。

  **其他坑**：
  - **`for (unsigned i = n; i >= 0; i--)` 死循环**——i 到 0 后再减变成无符号最大值，永远 ≥0。
  - **长度/下标用无符号**，一旦算成负数（如 `b - a` 当 a>b）会变成巨大正数。
  - **错误检测**：比较/相减时先判断符号/大小，避免负转巨大无符号。

  **怎么规避**：**统一用带符号（int32_t）或显式强转**；边界比较用**上限**而非 `>=0`（如 `for i = n; i != 0; i--`）；对长度计算注意别出现负值。
why: |
  嵌入式里**无符号数**（寄存器、长度、地址、计数器）非常常见，和有符号混用时的**陷阱**是**经典面试题 + 真实 bug 来源**。能指出「**有符号被转成无符号导致比较错误 / 死循环 / 巨大值**」，就是 C 语言的严谨底子。

## 深读

### 两个经典 bug
```c
// ① 比较
int a = -1; unsigned b = 0;
a < b  // -1 转成 0xFFFFFFFF，> b → 判断错误

// ② 倒序循环
for (unsigned i = 5; i >= 0; i--)   // 死循环：i 到 0 后减变 0xFFFFFFFF
```

### 怎么规避
- 统一用 `int32_t`（带符号）或显式 `(unsigned)`。
- 倒序用 `for (i = n; i != 0; i--)` 或 `int i = n; i >= 0; i--`。
- 长度/差值计算前确认符号，别让负值转巨大无符号。

### 常见追问
- `sizeof` 返回什么类型？——`size_t`（无符号）。
- 有符号+无符号会怎样？——有符号转无符号，结果按无符号。
- 怎么避免？——统一带符号、边界用上限比较。

> 📌 一句话：**有符号和无符号混用时有符号会转无符号 → 比较/减法出错、倒序循环死循环；用 int32_t 或显式强转、边界用上限。**
