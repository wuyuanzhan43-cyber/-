answer: |
  **Q：你这个手语手套用了双核，是什么架构？为什么核0 采集+推理、核1 通信？为什么用 HSEM 而不是普通互斥锁或关中断？**

  **A（你怎么答）：**
  这是 **AMP（非对称多处理）**——核0、核1 **各自独立跑**、分工不同（核0 做 100Hz 采集 + TFLM 推理，核1 做 BLE/USART 通信），**没有统一 OS 调度**；不是 SMP（共享内存 + 统一调度 + 任务可跑任意核）。

  **为什么这么分**：采样 + 推理是**硬实时、不能被通信阻塞**的；BLE 通信耗时、可能阻塞。若同核，通信阻塞会**抖动采样节拍**。拆两核 = 用**硬件隔离**「实时链路」与「通信链路」，保证 100Hz 采样稳定。

  **为什么用 HSEM**：
  1. **跨核互斥**（普通 OS 锁只管单核）；
  2. **硬件原语、确定性强、不依赖某个核的 OS**；
  3. 比**关整核中断**更精准（不屏蔽整个核的中断，实时性更好）。

  **核间怎么通信**：共享内存 + 同步。我把共享缓冲区做成**环形缓冲**（单生产者单消费者可无锁）+ **内存屏障 / 原子索引**，配合 HSEM 做「缓冲区满/空」门控；并注意**缓存一致性**（AMP 无硬件一致性，用**原子 + 内存屏障 / flush** 避免读到缓存旧值）。

## 深读

### 一句定性
- **AMP**：各核独立 OS/分工（可异构），核间约定通信；用于实时+通用混合，**没统一调度**。
- **SMP**：共享内存 + 统一调度 + 任务可跑任意核；有硬件缓存一致性。

### 为什么用「共享内存 + 环形缓冲 + HSEM」
```
核0(采集/推理)                    核1(通信)
   │  写  ──────────────►  环形缓冲  ◄── 读
   │                                    │
   └── HSEM 上锁/解锁（互斥保护共享区）──►┘
   单生产者单消费者 → 读侧无锁、写侧原子；HSEM 控制「满/空」门控
```

### 缓存一致性（必提）
- 核0 改了共享内存，核1 缓存可能是旧值。
- AMP 无硬件一致性 → 用**原子 + 内存屏障**（`__sync_synchronize` / 硬件 barrier）或**显式 flush/invalidate**。
- **伪共享**：两个核改相邻数据在同一缓存行 → 频繁失效；用**对齐/填充**隔开。
