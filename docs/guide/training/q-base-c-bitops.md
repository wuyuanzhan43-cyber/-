answer: |
  **基本位操作（会写）**：
  - **置位（set bit N）**：`x |= (1 << N)`
  - **清零（clear bit N）**：`x &= ~(1 << N)`
  - **翻转（toggle bit N）**：`x ^= (1 << N)`
  - **判断某位（test bit N）**：`(x >> N) & 1` 或 `x & (1 << N)`
  - **取低 N 位**：`x & ((1 << N) - 1)`

  **位域（bit-field）**：在结构体里按位分配字段，常用于**紧凑、逐字段做协议/寄存器**：
  ```c
  struct Reg { unsigned a : 1; unsigned b : 3; unsigned c : 4; };
  ```
  - 能**按位访问字段**、省内存；但**不可取地址**、**不同编译器位序/边界可能不同（大小端）**、跨平台要谨慎。

  **为什么嵌入式常用**：**寄存器/协议字段**往往按位定义，用位操作或位域去**读/写某几位**，比用整型掩码更清晰；但**位域跨平台要确认位序**（大小端）。
why: |
  寄存器配置、协议字段、状态标志**几乎都是按位**的，所以位操作是嵌入式 C 的日常。**能随手写出置位/清零/翻转/判断**，并能说说**位域的用途与坑（位序/不可取地址/跨平台）**，就是底子过关。

## 深读

### 位操作模板
```c
#define SET_BIT(x, n)  ((x) |=  (1u << (n)))
#define CLR_BIT(x, n)  ((x) &= ~(1u << (n)))
#define TGL_BIT(x, n)  ((x) ^=  (1u << (n)))
#define GET_BIT(x, n)  (((x) >> (n)) & 1u)
```

### 位域的坑
- **不可取地址**（`&reg.a` 不行）。
- **位序**：小端/大端下字段排布可能不同，**协议用位域要确认**。
- **跨平台/编译器**：边界、对齐、填充各平台差异大，**跨平台协议别依赖位域**。

### 为什么 C 语言 CPU 的位带操作
- Cortex-M0/M3 的**位带（bit-band）**把某一位映射到单独可原子的地址，实现**原子置位/清零**（`mcu/q-bit-band`）。
- 位操作加 **volatile/原子/关中断** 才能保证中断/多任务安全。

### 常见追问
- 置位/清零某位怎么写？——`|=` / `&=~`，用 `1<<n` 掩码。
- 位域能取地址吗？——不能；且跨平台位序可能不同。
- 判断某位为 1？——`(x>>n)&1`。

> 📌 一句话：**位操作 = 掩码 + 移位（置位 |=，清零 &=~，翻转 ^=，判断 >>n &1）；位域按位分配但不可取地址、跨平台要小心位序。**
