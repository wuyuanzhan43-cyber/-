answer: |
  **中断上下文（ISR context）**：中断触发时 CPU **暂停当前任务/主循环**，**切换到中断处理**（`ISR`），处理完再回来。
  **中断里只能做「快、原子、不可阻塞」的事**：
  - **能做**：**置标志位**（`volatile`）、**发队列/信号量**（`FromISR` 版）、**读寄存器/清标志**、**入队 workqueue**（异步延迟处理）。
  - **不能做**：**阻塞**（睡眠锁/队列 take）、**长耗时**（会丢中断、破坏实时性）、**`printf`/`malloc`**（不可重入/可能阻塞）、**不可重入函数**、**带锁函数**（会死锁——持锁被中断打断又进来）。

  **为什么**：中断运行在**别人的上下文**、**非任务**，不能调度/睡眠；中断必须**短**（拉长会丢中断、实时性差）。所以标准分工：**ISR 只做快、原子、不阻塞的事，重活丢给任务/主循环**。

  **关键点**：
  - **可重入**：中断里调用函数要**可重入、无共享可变状态**，否则竞态/死锁。
  - **关中断/临界区**：保护共享结构用**关中断/原子**，但要**短**（否则实时性下降）。
  - **FromISR 版**：`xQueueSendFromISR` 等，不能阻塞；若唤醒更高优先级，`pxHigherPriorityTaskWoken` 置位，返回后触发调度。
why: |
  「**中断里能做什么**」是嵌入式 OS/裸机**必考**。核心：**ISR 要短、不阻塞、可重入**，只做**置标志/发事件/读寄存器**，重活丢任务。能说清「为什么不能阻塞/为什么不能用 printf/为什么 FromISR 不阻塞」就懂了中断的边界，也是你框架 workqueue、ISR-主循环分工的根。

## 深读

### ISR 能做 / 不能做
| ✅ 能做 | ❌ 不能做 |
|---|---|
| 置 volatile 标志 | 阻塞(睡眠锁/take) |
| `FromISR` 发队列/信号量 | 长耗时 |
| 读寄存器/清标志 | printf/malloc |
| 入队 workqueue | 不可重入/带锁函数 |

### 经典 ISR-主循环
```c
volatile int flag = 0;
void uart_isr(void){ flag = 1; }        // ISR 只置标志
void main(void){ while(1){ if(flag){ flag=0; process(); } } }  // 主循环处理
```

### 常见追问
- 为什么 ISR 不能阻塞？——ISR 非任务、不能调度/睡眠；阻塞会让系统卡死。
- 为什么不用 printf？——printf 有静态缓冲/可能带锁，不可重入/不能阻塞。
- 丢事件怎么避免？——计数或队列(每事件一个消息)，别用布尔标志。

> 📌 一句话：**ISR 只做「置标志/发事件/读寄存器」(快、原子、不阻塞)，重活丢任务；共享数据用 volatile+原子/关中断+无锁环形缓冲。**
