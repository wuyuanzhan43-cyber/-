answer: |
  **UART**：**异步串行**通信，**无时钟线**，靠**双方约定波特率 + 帧格式**来同步。**帧**：`起始位(0) + 数据位(5~8, 常见8) + 可选校验位 + 停止位(1/1.5/2)`，**LSB 先发**。
  **波特率**：`波特率 = 时钟/分频`，**双方必须一致**，否则采样错位 → 乱码。8N1（8数据+无校验+1停止=10bit）下`115200`约 **11520 B/s**（有效80%）。
  **校验**：奇/偶校验，只能发现**奇数个**翻转；可靠检错用 **CRC**。
  **电平/标准**：
  - **TTL**（3.3/5V）：MCU 直接，短距。
  - **RS-232**（±12V）：长距，需电平转换（MAX232），单端。
  - **RS-485**（差分 A/B）：多点、长距、抗干扰，**半双工**，需方向控制。
  **流控**：软件（XON/XOFF，**别用于二进制**——数据里出现 0x11/0x13 会被误判）、硬件（RTS/CTS，精确可靠）。

  **排查「乱码/丢字节」三板斧**：① **波特率**（时钟/分频，换主频要重算）；② **帧格式**（数据位/停止位/校验两边一致）；③ **电平/接法**（TX↔RX 交叉、TTL/RS232/RS485 匹配）。丢字节 = 接收慢或对端太快无流控/缓冲太小 → 用**中断/DMA + 环形缓冲**、必要时加流控。
why: |
  UART 是嵌入式**最常用**的调试/通信口，**乱码、丢字节**是最常见问题。能说出**帧结构、波特率=时钟/分频、TTL/RS232/RS485 区别、乱码排查顺序、丢字节原因**，就掌握了串口底子——这是每个嵌入式岗几乎必问的。

## 深读

### 一帧与有效吞吐
```
空闲 | S | D0..D7 | P | Stop | —— 8N1 = 1+8+1 = 10bit
```
- `115200 baud / 10 bit ≈ 11520 B/s`（80% 有效）。

### 乱码排查顺序
1. 波特率（时钟/分频，两边一致）
2. 帧格式（数据/停止/校验一致）
3. 电平/接法（TX↔RX 交叉、TTL/RS232/RS485 匹配）
4. 时钟稳定（换主频要重算波特率）

### 丢字节 = 生产和消费速率不匹配
- 接收慢/轮询阻塞读、对端太快无流控、缓冲太小 → 溢出。
- 改：中断/DMA + 环形缓冲，必要时流控。

### 常见追问
- UART 为什么乱码？——波特率/帧格式/电平不一致或接法错。
- 波特率怎么算？——时钟/分频；换主频重算。
- TTL/RS232/RS485 区别？——电平/距离/单双工不同（RS485 差分、半双工需方向控制）。

> 📌 一句话：**UART 无时钟线，靠波特率+帧格式对齐；8N1=10bit 约 11520B/s@115200；乱码先查波特率/帧格式/电平，丢字节是收发速率不匹配→中断+DMA+环形缓冲+流控。**
