answer: |
  **可执行程序运行时内存分几段：**
  - **代码段（.text）**：编译后的**指令**，只读，放 **Flash/只读区**。
  - **只读数据（.rodata）**：常量、字符串字面量。
  - **数据段（.data）**：**已初始化**的全局/静态变量，有初值，运行时**拷入 RAM**。
  - **BSS（.bss）**：**未初始化**的全局/静态变量，运行时**清零**。
  - **堆（heap）**：`malloc/free` 动态分配，**向高地址增长**。
  - **栈（stack）**：函数调用/局部变量，**向低地址增长**（方向因平台而异）。

  **嵌入式关键**：**代码/只读放 Flash**（掉电不丢），**.data/.bss/堆/栈放 RAM**（RAM 有限要省）；**堆栈相向增长，相遇即溢出**。启动时要把 **.data 从 Flash 拷入 RAM、清 .bss、设栈指针**（启动文件/链接脚本干的活）。

  **为什么全局变量默认 0**：未初始化全局/静态在 **.bss** 段，**只记录大小、不存初值**，启动时**清零**。
why: |
  这是嵌入式 C 的最底层基础。理解分段才能解释**为什么全局有初值/默认 0、为什么栈会溢出、malloc 从堆来**、以及**为什么代码放 Flash、数据放 RAM、启动要拷 data 清 bss**（嵌入式裸机启动的根因）。链接脚本、栈预算、内存池都建立在这之上。

## 深读

### 各段速查
| 段 | 内容 | 存放 | 初值 |
|---|---|---|---|
| .text | 指令 | Flash/只读 | — |
| .rodata | 常量/字符串 | Flash/只读 | 只读 |
| .data | 已初始化全局/静态 | RAM(拷入) | 有初值 |
| .bss | 未初始化全局/静态 | RAM | 0(清零) |
| heap | 动态分配 | RAM | — |
| stack | 局部变量/调用 | RAM | — |

### 全局/static/局部在哪
- 全局/静态：`.data` 或 `.bss`；局部（函数内）：**栈**；动态：**堆**。

### 常见追问
- 为什么全局变量默认 0？——在 .bss，启动清零。
- 为什么全局掉电不丢？——不，全局在 RAM，掉电丢；只有代码/只读在 Flash 才不丢。
- 栈溢出 / 堆溢出？——栈堆相向增长；减小局部大数组、控递归、增加栈大小；堆防泄漏/碎片。

> 📌 一句话：**代码/只读放 Flash，.data/.bss/栈/堆放 RAM；.bss 启动清零、.data 启动拷入；栈堆相向增长、相撞即溢出。**
