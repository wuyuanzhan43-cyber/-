answer: |
  **Q：你的边缘 AI 和云端大模型是怎么分工的？整条「训练 → 量化 → 部署」链路讲讲？**

  **A（你怎么答）：**
  **端云协同分工**：
  - **端侧（MCU）**：跑 **TFLM INT8 模型**，做**低算力、小内存、实时**的**识别**——100Hz 采集手势，300 帧滑窗推理，识别出 150 类手势。端侧要的是**快、省、实时**。
  - **云端**：跑 **DeepSeek 大模型**，做端侧做不了的**语义理解/组句**——把识别出的手势词**组织成自然语言**（检测 2.5s 停顿自动断句），输出语音/文字。云端要的是**理解语义、能力强**。
  - **原则**：**「端侧做实时识别、云端做语义组句」各取所长**——这就是端云协同，而不是全端侧或全云端。

  **训练 → 量化 → 部署链路**：
  1. **训练（float32）**：桌面用 TF 训出 float32 模型，验证到目标精度。
  2. **量化（float32 → int8）**：用校准数据统计每层激活范围，定 scale/zero_point（min/max 或 KL），转 INT8（`q = round(real/scale)+zero_point`），必要时 **QAT** 补偿精度。（见项目一量化卡）
  3. **转换导出**：TFLite Converter 导出 `.tflite` 全整型量化，用 **tflite-micro** 编译出 MCU 算子库。
  4. **内存/裁剪**：规划 **tensor arena**（预分配、复用、放片内 RAM），必要时**剪枝**减小体积。（见 `ai/q-tensor-arena`）
  5. **部署验证**：MCU 上跑真实传感器数据，**板级验证**准确率、单帧耗时、内存、CPU 占用。
why: |
  这题考「**你懂不懂端云协同的定位**」+「**全链路是不是真跑通**」。能说清「**端侧做实时识别、云端做语义理解**」的分工、以及「**训练→量化→部署**」各步做什么，就把「会调 API」升级成「理解边缘智能」。注意**诚实**：量化/部署是你做的，云端是调 DeepSeek——说清边界。

## 深读

### 端云协同定位（一句话）
> **端侧要「低算力+小内存+实时」→ INT8 量化；云端要「理解语义」→ 大模型组句；各取所长。**

### 训练 → 量化 → 部署
| 阶段 | 做什么 | 关键点 |
|---|---|---|
| 训练 | float32 模型，桌面验证 | 精度达标 |
| 量化 | float32→int8，定 scale/zero_point | 校准(KL/min-max)、QAT |
| 转换 | TFLite `.tflite` + tflite-micro 算子库 | 全整型量化 |
| 内存/裁剪 | tensor arena 规划、剪枝 | 预分配、放片内 |
| 部署验证 | MCU 板级跑真实数据 | 准确率/耗时/内存/CPU |

### 诚实的边界感
- **你做的**：量化、tensor arena 规划、滑窗推理、板级验证、端侧嵌入式集成。
- **云端的**：DeepSeek API 组句（你调接口 + 做停顿断句）。
- 说清边界，比吹「我训练了云端大模型」更稳。

### 把八股接回项目
答完加一句：「**端侧识别靠 tensor arena 预分配 + INT8 量化，云端只做语义——这套分工保证了实时性和准确性都能要。**」
