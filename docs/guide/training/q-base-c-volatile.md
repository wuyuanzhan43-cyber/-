answer: |
  **volatile 告诉编译器**：该变量的值可能被**控制流之外**（硬件/中断/别的线程）改变，编译器**不能**把它当普通变量优化——**① 不能缓存到寄存器（每次必须真实访问）；② 不能省略对它的读写**。

  **适用**：**内存映射寄存器（MMIO）**（硬件写）、**中断设置的标志位**、**多任务共享且无其它同步机制的标志**、硬件寄存器访问。

  **局限（高频追问）**：
  - **不保证原子性**：`volatile` 的读改写（如 `++`）不是原子的，仍可能被打断。
  - **不提供内存屏障**：CPU 可能乱序执行，`volatile` 不能保证顺序（需 `__sync_synchronize`/`rmb/wmb`/C11 `atomic`）。
why: |
  编译器为提速会把变量缓存到寄存器、并默认它只在代码里被改。一旦**外部（硬件/中断/线程）悄悄改了它**，缓存旧值就是**脏数据**。加 `volatile` = 每次去真实源头取，牺牲优化换正确性。但**它治不了原子性与乱序**——所以在中断/多线程共享时，volatile 只是**开始**，还要配原子/锁/内存屏障。

## 深读

### 编译器在做什么
```c
int x = 0;
while (x == 0) {}   // 若 x 是中断里的标志，编译器可能把 x 读进寄存器后不再读内存 → 死循环
```
- volatile 后每次访问生成真实 load/store。

### 典型场景
| 场景 | 用 volatile? |
|---|---|
| MMIO 寄存器 | ✅ 必须 |
| 中断设置的标志 | ✅ 建议(配屏障/优化) |
| 多线程共享标志 | ⚠️ 不够，要原子/锁 |
| 纯计算局部变量 | ❌ 不必要 |

### 常见追问
- volatile 保证原子吗？——不保证；读改写仍可能被打断。
- volatile 解决乱序吗？——不；需内存屏障或原子。
- 和 C11 atomic 区别？——atomic 同时给原子性+顺序；volatile 只管「别优化」。

> 📌 一句话：**volatile = 「别把它当普通变量省着用，去真实源头读」；但它不保证原子、不提供内存屏障。**
