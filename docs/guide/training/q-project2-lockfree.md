answer: |
  **Q：你封装的「跨平台原子操作库」「MPSC」是怎么回事？为什么用无锁？bufpool 解决什么？**

  **A（你怎么答）：**
  **无锁（lock-free）**：**不用锁（互斥/自旋/关中断），改用原子操作 + 无锁数据结构**保护共享数据。好处：**没有锁的开销、不阻塞、不优先级反转、并发度高、实时确定性强**；代价：**实现复杂、易错（竞态/ABA/内存序）**，所以只在**高性能热路径**用，低频/长临界区还是用锁。

  **原子操作**：**不可被中断的最小操作**（`atomic_add`、`compare-and-swap(CAS)`、`atomic_exchange`），由 CPU/编译器保证（GCC `__atomic_*`、C11 `atomic_*`、或裸 `LDREX/STREX`）。**注意：原子 ≠ 内存序**，多条原子操作的先后顺序要靠**内存屏障**保证。

  **MPSC（多生产者、单消费者）**：一块**环形缓冲/链表**，**多个生产者**（多个中断/任务）往里写，**一个消费者**读。因为**只有一个消费者**，**读侧天然无竞争**（一个游标即可，无锁）；**写侧多生产者用原子（CAS）抢占写指针**。我用于 **CAN 多路报文 → 一个接收任务**、**串口接收**这类「多写单读」场景。

  **bufpool（缓冲池）**：**预先分配固定大小的内存块**，需要时从池取、用后归还，**不用 malloc/free**，**无碎片、分配 O(1)、时间确定**，适合实时/长跑嵌入式（这正是你「性能敏感路径」的底气）。

  **伪共享 + 缓存一致性**：两核/两线程改**相邻数据在同一缓存行** → 互相使对方缓存行失效、性能崩；用**对齐/填充**隔开。多核/DMA 共享内存要用**原子 + 内存屏障**保证看到最新（AMP 无硬件一致性）。

## 深读

### 有锁 vs 无锁
| | 有锁 | 无锁 |
|---|---|---|
| 开销 | 加/解锁、上下文 | 单条原子指令 |
| 阻塞 | 可能阻塞/反转 | 不阻塞、并发高 |
| 确定性 | 受调度影响 | 确定性强 |
| 复杂度 | 低 | 高（竞态/ABA/内存序） |

### CAS 无锁入队（伪代码）
```c
node->next = NULL;
do { node->next = head; } while (!CAS(&head, node->next, node));
// CAS 失败=别人改了 head，重试
```

### MPSC 为什么读侧无锁
- 单消费者 → 读无竞争，只需一个游标。
- 多生产者 → 写侧用原子抢占写指针。
```
生产者A/B/C ──写指针(原子)──► 环形缓冲 ──► 一个消费者(读游标, 无锁)
```

### 笔记：缓冲池 vs malloc
- `malloc`：有碎片、耗时不定、可能在中断/高优先级不可用。
- `bufpool`：预分配、O(1)、无碎片、确定——正是 tensor arena、`c/q-memory-pool` 的同一思想。
