answer: |
  **信号量（semaphore）**：**计数器**，表示**可用资源/事件数量**。`take`（拿，减1）、`give`（给，加1），**无所有权**（任何任务都能 give），**可多次**。用于**资源池**（如 N 个缓冲）、**计数同步**、**事件通知**。用于互斥时**不保证优先级（会触发优先级反转）**。
  **互斥锁（mutex）**：**保护独占资源**，**有所有权**（谁拿必须谁放），且 **RTOS 自带优先级继承**——持有锁的低优先级任务在「高优先级等锁」期间被**临时提级**，尽快释放锁。用于**互斥访问共享资源**，避免优先级反转。

  **怎么选**：**仅保护共享资源 → 互斥锁**（有所有权+继承）；**计数/资源池/事件 → 信号量**。别混用。

  **优先级反转**：高优先级任务等一个被**低优先级**占用的锁，此时**中优先级抢占 CPU** 执行，把持锁的低优先级晾一边 → 高优先级反而等最久。**解决**：**优先级继承**（持锁时临时提级）或**优先级天花板**。
why: |
  「**信号量 vs 互斥锁**」是嵌入式 OS 必考。核心：**互斥锁有所有权 + 优先级继承（防反转）；信号量无所有权、只计数**。再能讲清**优先级反转+继承**，就真正理解了 RTOS 同步，也知道你为什么**该用互斥锁保护共享资源**。

## 深读

### 语义对比
| | 信号量 | 互斥锁 |
|---|---|---|
| 用途 | 计数/资源/事件 | 保护独占资源 |
| 所有权 | **无** | **有**(谁拿谁放) |
| 优先级 | 不保证(会反转) | **继承** |
| 举例 | 资源池、事件计数 | 共享外设/数据结构 |

### 优先级反转三步
```
H > M > L：L 拿锁 → H 等锁被阻塞 → M 插队抢占 → H 久等
解决：互斥锁优先级继承(把 L 临时提级) 或 天花板
```

### 常见追问
- 为什么用互斥锁不用信号量保护资源？——互斥锁有所有权+优先级继承，信号量会反转。
- 优先级反转怎么解决？——优先级继承 / 天花板。
- 信号量能当互斥用吗？——能但会反转、无所有权，不建议。

> 📌 一句话：**信号量=计数/事件(无所有权、会反转)；互斥锁=独占资源(有所有权+优先级继承)；反转用继承/天花板救。**
