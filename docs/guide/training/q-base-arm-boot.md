answer: |
  **大小端（Endianness）**：**多字节数据在内存里的存放顺序**。
  - **小端（little-endian）**：**低字节放低地址**（如 `0x1234` 存为 `34 12`），x86/ARM Cortex-M 默认小端。
  - **大端（big-endian）**：**高字节放低地址**（`12 34`），网络字节序、部分协议。
  - **关键**：**协议/寄存器字段、跨平台数据**必须统一字节序，否则解析错（用 `htonl/ntohl` 或手动字节序转换）。内存里读出来可能和你直觉相反。

  **ARM Cortex-M 启动过程**（上电复位）：
  1. **复位后从 `0x0000_0000` 读**：前 4 字节 = **初始栈指针 MSP**，紧接着是 **复位向量（程序入口地址）**。
  2. 由**异常向量表**跳到启动代码（`Reset_Handler`）。
  3. **启动代码**：**拷 .data 从 Flash 到 RAM、清 .bss、设栈**、再进 `main`。（`startup_xxx.s` + 链接脚本负责）
  4. **异常向量表**：整张表存**各异常/中断入口地址**（复位、NMI、HardFault、SVCall、PendSV、SysTick、外设 IRQ 等）。

  **异常（exception）**：ARM 用**异常机制**处理中断/错误。Cortex-M：**向量表存入口地址**；触发后**压栈（现场保存）**、跳向量、处理、`BX LR` 返回。**NVIC** 管理外设中断的使能/优先级/嵌套。

  **启动过程/异常向量表/大小端**是 ARM 底子，直接关系到**为什么能跑起来、中断怎么进、数据会不会解析错**。能说清 **复位读栈针+复位向量 → 拷 data 清 bss 设栈 → main**、**向量表存入口地址**、**小端低字节在低地址**，就懂了 MCU 的地基（也是你框架移植、启动配置的基础）。

## 深读

### 大小端
```
0x1234 以小端存(地址从低到高): 34 12   ← 低字节在低地址
0x1234 以大端存:               12 34   ← 高字节在低地址
```
- Cortex-M/x86 默认小端；网络字节序=大端。

### Cortex-M 启动
```
0x00000000: 初始 MSP(栈指针)
0x00000004: 复位向量(入口地址) → Reset_Handler
Reset_Handler: 拷 .data(Flash→RAM)、清 .bss、设栈 → main
```

### 异常向量表
- 存各异常/中断入口地址；触发后压栈→跳向量→处理→返回。

### 常见追问
- 大小端是什么/怎么转？——高低字节存放顺序；用 htonl/ntohl 或手动。
- 启动为什么先拷 data 清 bss？——.data 初值在 Flash 需拷 RAM、.bss 需清零（见内存布局）。
- 异常向量表存什么？——各异常/中断的入口地址。

> 📌 一句话：**小端=低字节在低地址；Cortex-M 启动=读栈针+复位向量→拷 data 清 bss 设栈→main；异常向量表存各中断入口地址。**
