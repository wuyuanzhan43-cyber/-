answer: |
  **Q：你框架里的「完成量（completion）」和信号量有什么区别？「workqueue」解决什么问题？**

  **A（你怎么答）：**
  **完成量（completion）**：一种**「一次性/单次完成事件」**的同步原语——消费者 `wait` 阻塞，直到生产者 `complete` 一次才唤醒。区别计数信号量（可多次 give/take），完成量表达 **「某件事做完了」的一次性事件通知**，用完即弃。典型：**等一个异步任务结束**。

  **workqueue（工作队列）**：把**耗时/非紧急**的处理，从**中断/高优先级上下文**，**延迟到普通任务上下文**串行执行。ISR 里**只入队一个 work**（快、不可阻塞），主任务慢慢处理。

  **和其它原语的选型**：
  - **互斥锁**：保护**独占资源**（有所有权 + 优先级继承）。
  - **信号量**：**计数**的资源/事件（可多次）。
  - **完成量**：**一次性完成通知**（wait 一次 complete 一次）。
  - **队列**：**传数据** + 同步（可带 payload）。
  - **workqueue**：**异步/延迟执行**（把任务挪到另一个上下文），是**执行机制**不是同步原语。

  **为什么用**：**缩短中断时间**（ISR 只入队）、**防阻塞**（ISR 不能阻塞）、**解耦**（生产者不关心消费者何时/怎么处理）、**复用 + 保证顺序**。
why: |
  这题考「**同步原语会不会选**」。能区分**完成量（一次性）vs 信号量（计数）**、**workqueue 是把重活从中断挪到任务**，就懂「**中断只做快、原子、不阻塞的事，重活延迟到任务**」这条嵌入式铁律——和 `os/q-isr-main-coop` 一脉相承。

## 深读

### 完成量 vs 信号量
| | 完成量 | 信号量 |
|---|---|---|
| 语义 | 一次性事件通知 | 资源/事件计数 |
| 计数 | 1 次用完 | 可多次 |
| 典型 | 等异步任务结束 | 资源池、事件计数 |

### workqueue 解决什么（图）
```
中断/高优上下文                    workqueue(任务上下文)
  只入队一个work ──► 延迟执行 ──► 处理耗时逻辑(可阻塞)
  (ISR 立刻返回, 不丢实时性)        (慢慢做)
```

### 中断处理链条（串起四个概念）
```
ISR: 快/原子/不阻塞 → 只 置标志 / 发事件 / 入队
   ▼
任务/主循环: 阻塞等待 → 取事件/解队列 → 处理业务(可阻塞)
```
> 这条「分工」线 = `os/q-isr-main-coop` + `os/q-task-comm` + `os/q-freertos-queue-src` 一起讲的主线。
