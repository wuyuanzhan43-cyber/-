answer: |
  **I2C**：**两根线**（SCL 时钟 + SDA 数据），**主从、半双工、可寻址**（每设备有地址），**支持多主、多从**；速率中等（100k/400k/1M+）。**开漏 + 上拉**（线与），**起始/停止/ACK** 时序。适合**多设备共享总线**（传感器、EEPROM、RTC）。
  **SPI**：**四根线**（SCLK/MOSI/MISO/CS），**主从、全双工**（同时收发）；速率高，**无寻址**（靠 CS 片选选择设备）；时序由 **CPOL/CPHA**（时钟极性/相位）决定。适合**高速/大数据**（Flash、LCD、SD）。
  **UART**：**两根线**（TX/RX），**异步、点对点**、靠波特率；速率、无时钟线；适合调试/简单点对点。

  **怎么选**：要**多设备共享/寻址**→I2C；要**高速全双工**→SPI；要**简单点对点/调试**→UART。

  **I2C 时序要点**：**起始（SCL 高时 SDA 下降沿）→ 地址(7位+读写位)→ ACK → 数据 → 停止（SCL 高时 SDA 上升沿）**。读最后字节发 **NACK**（告知结束）；从机可用**时钟拉伸**（SCL 拉低）造让主机等待。
  **SPI 时序**：**CPOL**=时钟空闲电平，**CPHA**=采样在第一个/第二个边沿。主从必须 `CPOL/CPHA` 一致，否则读错。
why: |
  I2C/SPI/UART 是嵌入式**最常用的三种板级总线**。能说清**各自线数、主从、全双工/半双工、是否有寻址、速率**，以及**怎么选**，是**总线底子**；再加 **I2C 起始/ACK/NACK、时钟拉伸、SPI 的 CPOL/CPHA**，就是过关。这也是你外设驱动和协议底子的基础。

## 深读

### 对比表
| | I2C | SPI | UART |
|---|---|---|---|
| 线数 | 2(SCL/SDA) | 4(SCLK/MOSI/MISO/CS) | 2(TX/RX) |
| 主从 | 多主多从 | 一主多从 | 点对点 |
| 双工 | 半双工 | **全双工** | 全双工 |
| 寻址 | **有** | 无(靠CS) | 无 |
| 速率 | 中 | **高** | 低-中 |
| 典型 | 传感器/EEPROM | Flash/LCD/SD | 调试/模块 |

### I2C 时序
```
起始(SCL高,SDA↓) → 地址+R/W → ACK → 数据 → 停止(SCL高,SDA↑)
读最后字节发 NACK；从机时钟拉伸
```

### SPI 时序 CPOL/CPHA
- CPOL：空闲电平；CPHA：采样边沿。主从需一致。

### 常见追问
- I2C 和 SPI 区别？——I2C 2线/寻址/半双工/中速；SPI 4线/全双工/高速/无寻址。
- 为什么 I2C 用开漏+上拉？——多设备线与，避免推挽短路。
- SPI 为什么比 I2C 快？——全双工、无寻址、速率更高。

> 📌 一句话：**I2C=2线/多主/半双工/可寻址/开漏+上拉；SPI=4线/一主/全双工/高速/靠CS；UART=点对点/异步/靠波特率；多设备选I2C、高速全双工选SPI。**
