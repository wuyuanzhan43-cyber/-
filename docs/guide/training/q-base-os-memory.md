answer: |
  **栈（stack）**：**函数调用/局部变量**用，**每个任务独立栈**，由编译器自动管理（入栈/出栈），**快、自动、无碎片**；但**有大小限制**（栈溢出会崩），局部大数组/递归会爆栈。
  **堆（heap）**：**`malloc/free` 动态分配**，程序手动申请/释放，**灵活**；但**有碎片、耗时不定、可能在中断/高优先级上下文不可用**、需手动释放（否则泄漏）。

  **动态 vs 静态分配**：
  - **动态**：运行期 `malloc`，灵活但**有碎片、耗时不确定、可能失败**。
  - **静态**：**编译期固定**（全局/静态/预分配缓冲），**无碎片、时间确定、内存可预测**；适合**实时/安全/长跑**场景，但**不够灵活、费内存**。

  **内存池（memory pool）**：**预先分配固定大小内存块**，需要时从池取、用后归还，**不用 malloc/free**——**无碎片、分配 O(1)、时间确定**，实时嵌入式常用。

  **栈预算**：每任务独立栈，要含局部变量、调用深度、中断余量；栈太小→栈溢出（`configCHECK_FOR_STACK_OVERFLOW` 可检测）。
why: |
  「**栈 vs 堆、动态 vs 静态**」是嵌入式**内存管理的根**。能说清**栈自动/快/有上限、堆灵活/有碎片/耗时不定**、以及**为什么实时/长跑用静态分配或内存池**（无碎片、确定），就理解了为什么 MCU 里要**少用 malloc、多用预分配/内存池**——这也是你 **tensor arena、bufpool、任务栈预算** 的共同底层。

## 深读

### 栈 vs 堆
| | 栈 | 堆 |
|---|---|---|
| 管理 | 编译期自动 | 手动 malloc/free |
| 速度 | 快 | 慢(不定) |
| 碎片 | 无 | 有 |
| 大小 | 有上限(会溢出) | 受限 |
| 适用 | 局部/调用 | 动态、长生命周期 |

### 为什么实时/嵌入式少用 malloc
- 碎片、耗时不定、可能在中断/高优先级不可用、易泄漏。
- → 用**静态分配/内存池**（预分配、O(1)、无碎片、确定）。

### 常见追问
- 为什么推荐静态分配/内存池？——无碎片、时间确定、内存可预测。
- 栈溢出怎么办？——减小局部大数组、控递归、增加栈大小。
- 内存池 vs malloc？——池免碎片、O(1)；malloc 灵活但有碎片。

> 📌 一句话：**栈=自动/快/有上限；堆=malloc 灵活/有碎片/耗时不定；实时长跑用静态分配或内存池(无碎片、确定)；任务要预算栈。**
