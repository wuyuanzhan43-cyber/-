answer: |
  **保存内容**：任务上下文切换保存的是"**让该任务未来能在任意时刻精确恢复**"的完整 CPU 现场，组织成一个**上下文帧（context frame）**放在任务栈上：
  1. **硬件压的异常帧**：`R0–R3/R12/LR/PC/xPSR`（进入 PendSV 时硬件自动压栈）。
  2. **手动保存的寄存器**：`R4–R11`（被调用者保存寄存器，FreeRTOS 移植层汇编手动压入）。
  3. **可选浮点扩展帧**：使能 FPU 且使用浮点时的 `S0–S15/FPSCR`。
  4. **任务栈顶本身**：切换后 SP 指向栈顶，栈顶就是"当前上下文帧"的起始。

  **保存在哪里**：保存在**该任务自己的私有栈（PSP 指向的任务栈）**，**并非整体拷贝**——而是通过"一次 PendSV 异常进出 + 手动压/弹 R4–R11"把现场组织在栈上。**栈顶位置记录在 TCB 的 `pxTopOfStack` 字段**（它必须是 TCB 第一个成员，因为移植汇编直接按首地址读它）。

  **切换**：选到新任务后，从新任务 TCB 读 `pxTopOfStack` → `PSP = pxTopOfStack` → 恢复栈上寄存器（弹 R4–R11、硬件弹 8 字）→ `BX LR` 用 `EXC_RETURN` 选出正确栈与模式 → 从新任务被切出的位置继续。**不拷贝任务栈，只换指针 + 压/弹寄存器**。
why: |
  容易被问懵的是"任务上下文到底存哪儿"。答案不是"存到一个全局数组"，而是"**存在每个任务自己的栈上，TCB 用 pxTopOfStack 记住栈顶**"。这样：
  - **恢复是按指针完成的**：切到哪个任务，就把 `PSP` 设成哪个任务 TCB 的 `pxTopOfStack`，然后弹栈。
  - **每个任务的现场是独立的、可达的**：各任务栈互不干扰，调度器只需维护"当前是哪个任务"（`pxCurrentTCB`）。
  - **为何 R4–R11 必须手动存**：它们是被调用者保存寄存器，编译器函数级保护不足以覆盖多级嵌套调用；只有 RTOS 在切换时把它们压到栈上，任务才能完整复原。
  这解释了 FreeRTOS「**两阶段切换**」：内核层记账（把任务挪到目标链）+ 移植层汇编（压/弹寄存器、换指针）。

## 深读

### 一个任务栈上的上下文帧（示意）

```
任务栈(PSP 指向) ── 向低地址增长
┌──────────────────────────────┐
│ ... 任务运行中的局部变量/调用栈 │
├──────────────────────────────┤
│ R4..R11     ← FreeRTOS 手动压 │ ← 上下文帧起点
│ S0..S15/FPSCR（可选浮点）     │
├──────────────────────────────┤
│ R0                          │ ← 硬件压的异常帧(进入 PendSV 时)
│ R1                          │
│ R2                          │
│ R3                          │
│ R12                         │
│ LR(EXC_RETURN)              │
│ PC(被切出的下一条)          │
│ xPSR                        │
└──────────────────────────────┘
         ▲ pxTopOfStack 指向这里（TCB 第一个成员）
```

### 上下文帧 vs TCB（"要恢复的寄存器"与"调度元数据"分开）

| 类别 | 内容 | 存在哪 |
|---|---|---|
| **上下文帧（要恢复）** | 8 字异常帧 + R4–R11 + 可选 FPU | **任务自己的栈上** |
| **栈顶锚点** | `pxTopOfStack` | TCB（必须是第一个成员） |
| **调度元数据** | 优先级、状态节点 `xStateListItem`/`xEventListItem`、任务名、栈基址/大小、入口 | TCB |

### 为什么 `pxTopOfStack` 必须是 TCB 第一个成员

移植层上下文切换汇编（如 `vPortPendSVHandler`）会：
```asm
LDR R0, =pxCurrentTCB   ; 当前任务 TCB 地址
LDR R1, [R0]            ; pxCurrentTCB -> R1
STR R0, [R1]            ; 把各寄存器保存/恢复到栈，最终把(新)栈顶直接写进 TCB 首字段
```
它**不按结构体字段名、不偏移**，直接假设 `TCB 首地址` 就是 `pxTopOfStack`。所以 **pxTopOfStack 必须放第一位**——这是移植层汇编的硬约定。

### 常见追问

- **Q：任务切换时会不会把任务栈整个拷贝一份？**
  A：不会。只把当前任务的现场**压到它自己的栈**、把新任务的栈顶指针从它 TCB 读出来设为 `PSP`，然后弹栈恢复。是"**换指针 + 压/弹寄存器**"，不是拷贝。

- **Q：为什么 R4–R11 要手动保存而不用硬件？**
  A：硬件异常帧只含 R0–R3/R12/LR/PC/xPSR（调用者保存寄存器 + 控制流）。R4–R11 是**被调用者保存寄存器**，编译器只保证"单个函数调用内"被保护，任务可能跨多层函数调用，所以必须由 RTOS 在切换时完整压/弹。

- **Q：两个任务上下文帧会不会互相覆盖？**
  A：不会。每个任务用**自己的栈（PSP 各自独立）**，上下文帧在各自栈的栈顶。`pxCurrentTCB` 维护"当前是谁"，`pxTopOfStack` 记各栈顶，互不重叠。

> 📌 一句话记忆：**任务上下文保存＝硬件 8 字 + R4–R11(+可选浮点)组成上下文帧，放在该任务自己的栈上，栈顶由 TCB 首成员 pxTopOfStack 记住；切换＝换指针(PSP=新任务pxTopOfStack)+压/弹寄存器，不拷贝栈。**
