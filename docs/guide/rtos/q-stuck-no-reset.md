answer: |
  **看门狗没复位 ≠ 系统健康**。要么**看门狗没被正确触发**，要么**卡死点不在喂狗链上**。先判断"卡在哪一层"，再对症。

  **可能原因**：
  1. **看门狗没启动/被关**：忘了 `IWDG` init，或喂狗路径被禁用。
  2. **喂狗点选错**：在 **Idle 任务/中断/主循环最前**喂狗——业务或某任务卡死时仍能喂，掩盖故障。
  3. **卡死发生在喂狗链之外**：卡在 **ISR / 关中断段 / `vTaskSuspendAll` 期间**——此时喂狗主路径断了；或卡的是**另一个任务**，而喂狗链路（只喂主任务）仍能成。
  4. **看门狗超时设太长 / 误喂**：超时前又有一次喂狗，或超时时间远大于"卡死→必复位"的期望。
  5. **调度器/中断停但某处仍在喂**：优先级/中断配置问题导致调度停，但空闲或某中断仍喂狗。

  **排查方法**：
  1. **确认看门狗在跑**：检查 IWDG 使能、独立时钟、喂狗调用；读**复位原因寄存器（RCC）**看是否曾复位。
  2. **判断卡死层级**：**整个系统停**（无 tick、无中断、调度停）还是**单任务卡**（调度仍转、其它任务动）。
  3. **看卡死点在不在喂狗链上**：卡在 **ISR/关中断段**（喂狗断）还是**某任务**（喂狗仍能跑）。
  4. **SWD 暂停当前执行**：连调试器 `halt` → 看 **当前 PC、`pxCurrentTCB`、任务状态**，判断卡在哪个函数/行。
  5. **看 tick 是否还转**：`xTickCount` 是否递增——停 = 调度/中断停；看 `SysTick`/`xPortSysTickHandler` 是否进。
  6. **任务统计**：`vTaskList`/`vTaskGetRunTimeStats` 看各任务 **CPU 占用、状态（BLOCKED/SUSPENDED/READY）**——是否某任务占满 CPU、是否陷入死等。
  7. **逐级禁用**：合掉某些中断/任务，**二分定位**。
why: |
  这题是 Q18（看门狗配合 RTOS）的**反向**：看门狗应该兜底，但它没动作，说明**
  - **"卡死"不在喂狗链上**：喂狗点被设在"卡死路径之后/旁路"（Idle、ISR、循环最前）才会继续喂。**喂狗点必须选在"关键任务推进点"**，否则卡在别处照喂。
  - **看门狗可能压根没跑**：配置/初始化遗漏、超时过长、或喂狗逻辑被优化掉。
  所以排查的核心是**"区分卡死层级 + 定位卡在哪个上下文 + 确认喂狗链是否被绕过"**——用调试器、tick、任务统计去"看到"系统卡在哪里，而不只是"感觉它死了"。

## 深读

### "卡死但没复位"的可能性树

```
系统看起来卡死, 但看门狗没复位
 ├─ 看门狗本身没跑
 │    ├─ 忘了 IWDG init / 独立时钟没启
 │    ├─ 喂狗被禁用/优化掉
 │    └─ 超时设太长(还没到就新一轮)
 ├─ 卡死在喂狗链之外
 │    ├─ 卡在 ISR / 关中断段(vTaskSuspendAll/关中断太持久)
 │    ├─ 调度停(tick停)但某中断仍喂狗
 │    └─ 卡的是"别的任务", 喂狗链(只喂主任务)仍成
 └─ 卡死点能绕过喂狗
      └─ 喂狗选在 Idle/中断/循环最前 → 业务卡死照喂
```

### 排查清单（症状→定位）

1. **读复位原因**（RCC_CSR / `__HAL_RCC_GET_FLAG`）：看是电源/看门狗/软复位，曾否复位。
2. **`vTaskList`**：各任务状态、优先级、栈。看**哪任务占满 CPU（READY/RUNNING 常驻）**或**SUSPENDED 卡死**。
3. **`xTickCount` 是否递增**：停 = tick/调度停了。查 **SysTick 是否还进**、是否**关中断太久**。
4. **调试器 `halt`**：看当前 `PC`、`pxCurrentTCB`、`LR`；反查在哪个函数哪一行。
5. **逐级关中断/任务**：二分定位，找出"关掉哪个就恢复"。

### 常见追问

- **Q：为什么看门狗"触发不了"卡死？**
  A：因为**喂狗链没断**——喂狗点设在了卡死路径之外（Idle/中断/循环最前），或看门狗没正确使能。所以**喂狗点要反映"系统健康"**，否则卡在别处照样喂。

- **Q：怎么区分"系统真死"和"某任务卡死"？**
  A：看**有没有其它任务/中断在动**——`vTaskList`、tick 是否递增、调试器暂停后看 `pxCurrentTCB`。若调度仍转只是某任务卡 = 单任务卡死；若 tick 停 = 调度/中断停（更严重）。

- **Q：卡在 ISR 里，看门狗为什么也不复位？**
  A：若**看门狗喂狗在任务层**、而**卡在 ISR（死循环/长时间持锁）**，喂狗任务跑不到 → 超时应复位。若还没复位，通常是**看门狗超时太长** 或 **看门狗在 ISR 里也被喂**（错）。得去**看门狗配置 + 喂狗点**。

> 📌 一句话记忆：**卡死但看门狗不复位＝看门狗没跑(忘显能/超时太长/喂狗被禁用)或卡死在喂狗链外(ISR/关中断段/别的任务)或喂狗点选错(Idle/循环最前掩盖业务卡死)；排查＝读复位原因+看tick是否递增+vTaskList看任务状态+调试器halt看PC/pxCurrentTCB+逐级禁用二分定位。**
