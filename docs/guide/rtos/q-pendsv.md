answer: |
  **PendSV 是 Cortex-M 上一个"可挂起的系统服务异常"，FreeRTOS 用它来执行任务上下文切换。** 作用一句话：**它是"真正切换任务"的载体，用优先级最低 + 可挂起，把"该不该切"和"什么时候切"解耦。**

  关键特性：
  1. **优先级最低**：可以设成比任何中断都低，因此**不可能抢占正在运行的 ISR**。中断里若触发切换，只会**挂起（PEND）PendSV**，等所有 ISR 处理完、回到任务态才真正切换——**保证不在中断上下文里切换任务**。
  2. **可挂起（pending）**：通过写 `SCB->ICSR` 的 `PENDSVSET` 位置位挂起，**无需立即执行**，适合作为"软调度请求点"。
  3. **切换实现**：在 PendSV 处理器（`vPortPendSVHandler`）里完成——保存当前任务 R4–R11、更新 `pxCurrentTCB`、调 `vTaskSwitchContext` 选新任务、恢复新任务寄存器、`BX LR` 返回。

  触发来源：`portYIELD()`（任务态主动让出）、`portYIELD_FROM_ISR()`（中断里请求切换）、SysTick 中断里判定"时间片到/延时常量到期"后挂起 PendSV。配套的 **SVC** 负责**启动第一个任务**。
why: |
  为什么不用普通中断做切换？因为普通中断可能**抢占另一个正在执行的 ISR**，这等于"在中断上下文里切任务"，违反"中断里不能调度"的纪律，会破坏现场、引发不可预期错误。
  PendSV 用**最低优先级**保证：它总是在**所有高优先级 ISR 结束后（回到任务态）**才执行，从而：
  - **中断里里只做"标记挂起"**（`PENDSVSET`），不在中断里切。
  - **切换动作被延迟到安全时刻**（CPU 空下来），不打断实时 ISR。
  所以 FreeRTOS 的"上下文切换"其实是"**内核决定切（记账 + 挂起 PendSV）→ 等安全时刻 → PendSV 里真的切（压/弹寄存器）**"，这是个"**两阶段切换**"。PendSV 就是第二阶段的执行者。

## 深读

### PendSV vs SVC vs SysTick 的分工

| 异常 | 优先级 | 作用 |
|---|---|---|
| **SysTick** | 可配置（常为中等） | tick 时基：周期触发，驱动延时/超时/时间片判断，可挂起 PendSV |
| **PendSV** | 最低 | **任务上下文切换**的实际执行者 |
| **SVC** | 固定较高 | **启动第一个任务**（首次调用调度器时触发） |

### 触发路径（何时挂起 PendSV）

```
[任务态]  调 vTaskDelay/阻塞/挂起/portYIELD()
            → 内核把任务挪到目标链表(记账)
            → 置位 PENDSVSET 挂起 PendSV（请求切换）

[中断态]  SysTick 中断到期 / 某 FromISR 唤醒高优先级任务
            → portYIELD_FROM_ISR() 置位 PENDSVSET（只标记，不立即切）
            → 等当前 ISR 结束、回到任务态才真正切换

[安全时刻] 所有更高优先级中断处理完 → PendSV 进入
            → 保存当前任务现场 → 选新任务 → 恢复新任务现场 → 返回
```

### 为什么"最低优先级"是关键

- 若 PendSV 优先级不是最低，它可能**抢在某 ISR 之前执行** → 在中断上下文切换任务 → 破坏"中断里不切换"的原则。
- 设成最低，保证它**永远等到所有高优先级中断结束**才执行，**延迟吸收**了中断请求，让切换发生在"任务态"这个安全窗口。

### `portYIELD_FROM_ISR` 与 `portYIELD` 的区别

| 宏 | 调用位置 | 作用 |
|---|---|---|
| `portYIELD()` | 任务上下文 | 立即请求调度（挂起 PendSV） |
| `portYIELD_FROM_ISR()` | ISR 内 | 只**挂起 PendSV 做标记**，等 ISR 结束后再切；返回值告诉是否发生了切换 |

### 常见追问

- **Q：为什么 FreeRTOS 不直接调用切换函数，而是挂起一个异常？**
  A：直接用函数切换会被更高级中断打断、也可能在中断里执行。挂起 PendSV 把切换**延迟到安全时刻**（无更高优先级中断、处于任务态），且保存/恢复寄存器是**架构相关操作**，放到异常（移植层汇编）里最干净。

- **Q：SVC 和 PendSV 怎么配合？**
  A：**SVC** 在系统**首次调度**（`vTaskStartScheduler` 里触发 SVC）时把第一个任务的现场准备好并启动；**PendSV** 负责后续所有**任务间切换**。二者都是 Cortex-M 的系统服务异常，分工不同。

- **Q：如果没有 PendSV 会怎样？**
  A：切换要么在中断里做（违反纪律、易崩），要么延迟到调度器手动调用（无法高效响应"中断唤醒高优先级任务"）。PendSV 让"中断里请求切换"成为低开销的"记一笔，稍后切"。

> 📌 一句话记忆：**PendSV＝优先级最低、可挂起的系统服务异常，是 FreeRTOS 真正执行上下文切换的地方；中断里只挂起(PENDSVSET)不立即切，等所有 ISR 结束回到任务态才切——把"该切"与"何时切"解耦；SVC 负责启动第一个任务。**
