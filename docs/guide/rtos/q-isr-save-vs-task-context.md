answer: |
  二者都是"**保存现场**"，但动机、对象、保存位置、是否回到原处完全不同：

  **中断现场保护**：由**异步事件**（外部中断/异常）触发，是**被动响应**。Cortex-M **硬件自动压栈**最小集（R0–R3/R12/LR/PC/xPSR，8 个字，可选 FPU）到**当前正在用的栈**（未处理异常时是 MSP；已在任务态用 PSP）。ISR 结束后**原路返回被打断的那一条指令**——同一个地方。它是"**临时借道**"，可被更高优先级中断**嵌套**，保存/恢复围绕一次 ISR 的进出。

  **任务上下文切换**：由**调度器主动决策**（时间片到、高优先级任务就绪、主动让出、进入阻塞）触发。**移植层汇编（PendSV 处理器）**把**完整上下文**（硬件 8 字 + R4–R11 + 可选 FPU 状态）保存到**该任务私有的栈（PSP）**，并由 **TCB 的 `pxTopOfStack` 记住栈尾**。切出 A、切进 B，"移形换位"，返回的是**任务各自被切出的那个位置**。

  **一句话**：中断现场保护是"**借当前上下文去响应异步事件，做完回到原地**"；任务上下文切换是"**把任务 A 的完整状态封存到自己的栈，换任务 B 上来**"。前者回到原处、可嵌套、硬件代劳；后者跨任务、不可嵌套、内核+汇编协同。
why: |
  很多简历写"熟练 STM32 和 FreeRTOS"的候选人，被问到这一题就在这里硬撑——把"中断保存现场"和"任务切换保存上下文"当成一回事。区别的核心不是"保不保存寄存器"，而是**保存是为了什么、存到谁的栈、会不会回到同一个地方**：
  - **保存动机**：中断是为了响应异步事件、做完还要回到原地；任务切换是为了"调度"，把 A 封存、让 B 上。
  - **保存对象与位置**：中断压到**当前栈（MSP/PSP）**；任务切换压到**被切出任务的私有栈（PSP），由 TCB 指向**。
  - **回到哪**：中断回到**原处**；任务切换回到**各自被切出的点**。
  - **嵌套性**：中断可嵌套（可重入）；任务切换不可嵌套（PendSV 优先级最低，切到一半不被打断）。

## 深读

### 一图看懂：一个中断 + 一次任务切换里发生了什么

```
任务 A 运行（使用 PSP 指向自己的栈）
  │
  ├─[外部中断来了]──────────────────────────────────────────
  │   硬件自动压栈 R0-R3/R12/LR/PC/xPSR → 当前栈(MSP/PSP)
  │   进入 ISR（现场保护：为的是"做完回到原地"）
  │   中断里置标志 / 发队列(FromISR) / 短处理
  │   硬件自动弹栈 → 回到被中断的那条指令（同一处）
  │
  └─[调度器决定切换]───────────────────────────────────────
       PendSV 触发(最低优先级)
       汇编保存 R4-R11(硬件压的 8 字也在栈上) → 任务 A 的栈
       pxCurrentTCB 指向任务 B
       汇编恢复任务 B 的 R4-R11 + 硬件 8 字
       bx r14 → 从任务 B 被切出的位置继续（不同处）
```

### 关键区别表

| 维度 | 中断现场保护 | 任务上下文切换 |
|---|---|---|
| 触发者 | 异步事件/异常（被动） | 调度器主动决策 |
| 保存内容 | 最小集：R0–R3/R12/LR/PC/xPSR（硬件自动） | 完整集：上述 8 字 + R4–R11 + 可选 FPU |
| 由谁保存 | 硬件自动压栈（软件只补浮点等） | 移植层汇编（PendSV 处理）+ 内核记账 |
| 保存到哪 | 当前正在用的栈（MSP 或 PSP） | 被切出任务的私有栈（PSP），TCB 指向 |
| 返回位置 | 被打断的**同一处** | 各自被切出的位置（可能不同任务） |
| 可嵌套 | **可**（可被更高优先级中断打断） | **不可**（PendSV 最低优先级，切到一半不被打断） |
| 目的 | 响应异步事件后恢复执行 | 调度：把 A 封存、换 B 上 |

### 为什么"Cortex-M 自动压栈"让人容易混淆

Cortex-M 进异常时**硬件**就把 8 个字压上去了，所以中断现场保护"几乎不用写保存代码"。而任务切换里 FreeRTOS 还要**手动补 R4–R11**。于是很多人以为"上下文保存=硬件自动做了"。实际：
- 中断现场保护：硬件压 8 字就够，ISR 返回由硬件弹 8 字。
- 任务切换：硬件压 8 字（这部分其实也是基于"借异常(PendSV)进出"完成的）+ FreeRTOS 手动压 R4–R11，缺一不可。

### 常见追问

- **Q：为什么任务切换一定要保存 R4–R11？**
  A：R4–R11 是非叶函数会用到的**被调用者保存寄存器（callee-saved）**，C 编译器约定跨调用保留；硬件自动压栈只压了 R0–R3/R12/LR/PC/xPSR（**调用者保存**的一半），剩下的 R4–R11 必须由 RTOS 在切换时手动保护，否则任务恢复时寄存器数据就丢了。

- **Q：中断现场保护可嵌套，任务切换为什么不可？**
  A：中断是硬件事件，天然可重入；任务切换如果被再次切换打断，会破坏"正在切换中"的不变式。所以用**优先级最低的 PendSV** 来做切换——它不会抢在正在运行的中断前面，保证切换独占、原子。

- **Q：能不能用普通中断做任务切换？**
  A：不建议。普通中断可能打断另一个正在执行的 ISR，导致在中断上下文里切换任务（违反"中断里不可调度"）。PendSV 最低优先级，总是等所有 ISR 结束后（回到任务态）才真正切换。

> 📌 一句话记忆：**中断现场保护＝借当前上下文响应异步事件，硬件压 8 字，回原处、可嵌套；任务上下文切换＝调度器封存任务 A 完整状态到其栈、换任务 B，汇编压 R4–R11，回各自切出点、不可嵌套。**
