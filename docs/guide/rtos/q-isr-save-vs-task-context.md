answer: |
  二者本质都是"**保存寄存器现场**"，但**动机、保存对象、栈位置、是否回原处、可否嵌套**完全不同。

  ### 中断现场保护：临时借道，回原处
  - 由**异步事件（外部中断/异常）**触发，是**被动响应**。
  - Cortex-M **硬件自动压栈**一个**最小异常帧**（`R0–R3/R12/LR/PC/xPSR`，8 字，可选 FPU 扩展帧）到**当前正在用的栈**——未进异常时用 **PSP**（线程态），已在异常/裸机用 **MSP**。
  - 返回用 **`EXC_RETURN`**（LR 特殊值）决定"从哪个栈弹、是否浮点、回哪种模式"，**原地回到被中断的那条指令**。
  - **可嵌套**：更高抢占优先级中断可打断当前 ISR，每次嵌套都压一帧。

  ### 任务上下文切换：移形换位，跨任务
  - 由**调度器主动决策**（时间片到/高优先级任务就绪/主动让出/阻塞）触发。
  - 由**移植层汇编（`vPortPendSVHandler`）**把**完整上下文**（硬件 8 字 + `R4–R11` + 可选浮点）压到**该任务私有栈（PSP）**，栈顶记录到 **TCB `pxTopOfStack`**。
  - 切出 A、切进 B，**返回的是各自被切出的位置**（可能不同任务）。
  - **不可嵌套**：用**最低优先级 PendSV** 保证切到一半不被打断，原子。

  ### 一句话
  **中断现场保护 = 借当前上下文响应异步事件，硬件压 8 字，回原处、可嵌套；任务上下文切换 = 调度器把任务 A 的完整状态封存到其栈、换任务 B，汇编压 R4–R11，回各自切出点、不可嵌套。**
why: |
  简历写"熟练 STM32/FreeRTOS"的候选人常在这道题硬撑，因为把"中断保存现场"和"任务切换保存上下文"混为一谈。区别不在"保不保存寄存器"，而在于**保存为了什么、存到谁的栈、会不会回到同一个地方**：
  - **动机**：中断是响应异步事件、做完回到原地；任务切换是调度，把 A 封存、让 B 上。
  - **保存对象/位置**：中断压到**当前栈（MSP/PSP）**；任务切换压到**被切出任务的私有栈（PSP），由 TCB `pxTopOfStack` 指向**。
  - **回到哪**：中断回**原处**；任务切换回**各自切出点**。
  - **嵌套性**：中断可嵌套（可重入）；任务切换不可嵌套（PendSV 最低优先级）。

## 深读

### 一图看懂：一个中断 + 一次任务切换里发生了什么

```
任务 A 运行（用 PSP 指向自己的栈）
  │
  ├─[外部中断来了]──────────────────────────────────────────
  │   硬件自动压栈 R0–R3/R12/LR/PC/xPSR → 当前栈(线程态=PSP)
  │   LR ← EXC_RETURN; IPSR ← 异常号; 切 handler mode/MSP
  │   进入 ISR（现场保护：为的是"做完回到原地"）
  │   中断里置标志 / 发队列(FromISR) / 短处理
  │   BX LR(EXC_RETURN) → 硬件弹 8 字 → 回到被中断那条指令(同一处)
  │
  └─[调度器决定切换]───────────────────────────────────────
       内核记账(挪链)+ 置位 SCB->ICSR.PENDSVSET
       PendSV 进入(最低优先级, 没更高中断才执行)
       汇编保存 R4–R11(硬件压的 8 字已在栈上) → 任务 A 栈
       更新 pxCurrentTCB 的 pxTopOfStack → 指向新栈顶
       vTaskSwitchContext(): 位图+CLZ 选最高就绪 → 更新 pxCurrentTCB
       恢复任务 B 的 R4–R11 + 硬件 8 字
       bx lr(EXC_RETURN) → 从任务 B 被切出的位置继续(不同处)
```

### 关键区别表

| 维度 | 中断现场保护 | 任务上下文切换 |
|---|---|---|
| 触发者 | 异步事件/异常（被动） | 调度器主动决策 |
| 保存内容 | 最小集：R0–R3/R12/LR/PC/xPSR（硬件自动） | 完整集：上述 8 字 + R4–R11 + 可选 FPU |
| 由谁保存 | 硬件自动压栈（软件只补浮点/编译器补 callee-saved） | 移植层汇编（PendSV）+ 内核记账 |
| 保存到哪 | 当前正在用的栈（MSP 或 PSP） | 被切出任务的私有栈（PSP），TCB 指向 |
| 返回位置 | 被打断的**同一处** | 各自被切出的位置（可能不同任务） |
| 可嵌套 | **可**（需可重入、保护共享数据） | **不可**（PendSV 最低优先级，切到一半不被打断） |
| 目的 | 响应异步事件后恢复执行 | 调度：把 A 封存、换 B 上 |

### 寄存器/源码级：为什么"SVC/PendSV 进出"恰好构成一次上下文帧

Cortex-M 进**任何异常**（含 PendSV）都会**硬件自动压 8 字**。所以 FreeRTOS 的上下文切换其实是"**借一次 PendSV 异常进出**"来"**顺手**"完成部分现场保存：

- **硬件自动压**（进 PendSV 时）：R0–R3/R12/LR(EXC_RETURN)/PC/xPSR。
- **汇编手动补**（`vPortPendSVHandler` 里 `stmdb r0!,{r4-r11}`）：R4–R11。
- 退出用 `bx r14`（EXC_RETURN），硬件弹回 8 字。

因此**任务上下文=硬件帧+手动帧**，两者叠加才是"完整现场"。而**纯中断**（不是任务切换）只用到**硬件帧**即可，R4–R11 由编译器/ISR prologue 按需保存。

### 为什么 R4–R11 必须由 RTOS 手动保存

- 按 **AAPCS**，`R0–R3/R12` 是 **caller-saved（调用者保存）**，`R4–R11` 是 **callee-saved（被调用者保存）**。
- 硬件自动压栈只压了 **caller-saved 半集 + 控制流**；`R4–R11` 是被调用者保存，编译器只保证"**单个函数内**"被保护。任务可能**跨多层函数调用**，所以必须由 RTOS 在切换时整压整弹。

### 工程场景：现象 → 根因 → 对策

- **症状**：短任务能跑，但"频繁切任务/中断多"时数据偶发互洗、HardFault。
- **根因**：混淆两类现场——用了"只保护 8 字"的临界/中断思路去保护**任务级现场**（R4–R11 没保存），或反之在**不满足上下文切换**的地方当任务切换做。
- **对策**：**临界区/中断只关中断/basepri + 不碰任务现场**；**任务切换交给 PendSV + 组装完整帧**；不要把"关中断"当"任务切换"使。

### 进阶追问链

1. **Q：为什么任务切换要用 PendSV 而不用普通中断？** → 普通中断可能抢占另一个 ISR（在中断上下文切任务，违反纪律）；PendSV 最低优先级，永远等所有 ISR 结束、回任务态才切。
2. **Q：中断现场保护里 `LR` 存的是什么？还能用吗？** → 存的是 `EXC_RETURN`（0xFFFFFFF9/0xFFFFFFFD…等），不是普通返回地址；ISR 里想拿"被打断处的返回地址"要从异常帧读。
3. **Q：任务切换保存的现场和中断现场会不会叠？** → 会：进 PendSV 硬件先压 8 字，汇编再压 R4–R11，二者组成同一任务的一个完整上下文帧（在任务栈上）。
4. **Q：线程态 vs 处理器态（handler mode）切换时栈指针怎么变？** → 线程态用 PSP（任务栈），handler mode 用 MSP（中断/内核栈）；`EXC_RETURN` bit2 决定返回时用哪个。
