answer: |
  裸机是**单线程 main 循环 + 中断**；RTOS 是**多任务 + 调度 + 中断 + 临界区**。移植最大的坑源于"**单线程没有的竞争，多任务有了**"。清单如下：

  1. **中断里不能阻塞/调普通 API**：裸机 ISR 能做的事，RTOS 里要改用 **`FromISR` 版**（`xQueueSendFromISR`…），把**重活/解析**移到任务；中断数据用**队列/环形缓冲/DMA** 传给任务（见 Q17）。
  2. **共享数据加保护**：全局变量/状态在裸机无竞争，RTOS 多任务 = 共享资源要**互斥锁/关中断/原子/队列**（见 Q16）；中断共享标志保持 `volatile`。
  3. **非重入函数/库**：`strtok`/`localtime`/`malloc`/`snprintf` 等可能非线程安全 → 用**可重入版本**（`strtok_r`/`localtime_r`）或**互斥锁**包起来。
  4. **延时/忙等**：裸机 `delay_ms`/`HAL_Delay` 是**忙等**；RTOS 里改用 **`vTaskDelay`/`vTaskDelayUntil`**（让出 CPU），别在任务里忙等"卡死"其它任务。
  5. **中断优先级裁切**：用 **`configMAX_SYSCALL_INTERRUPT_PRIORITY`** 划界——高优先级中断不调 RTOS API；**SysTick/PendSV** 优先级设对。
  6. **栈/堆**：各任务有自己的栈；把**大局部数组/递归**权衡；`malloc/free` 可能线程安全 → 用**内存池/堆锁**；调 `configTOTAL_HEAP_SIZE`（heap_4 等）。
  7. **初始化顺序**：外设/时钟在 **`vTaskStartScheduler` 之前** init；**创建任务**后再启动调度器；**别在主循环里建任务**。
  8. **"轮询"改"事件驱动"**：主循环 `while(flag)` 死等改成**任务阻塞等待**（队列/事件/信号量）；标志位由中断置位、任务检查（带临界区）。
  9. **看门狗改心跳**：裸机 main 循环喂狗 → RTOS 用**任务心跳汇总**（见 Q18）。
  10. **实时性/优先级**：保证**高优先级任务及时响应**，避免**优先级反转**（用互斥锁）。
why: |
  移植最容易踩的坑是"**裸机单线程的假设被 RTOS 打破**"：
  - **竞争**：裸机同一时刻只有一个执行流，全局变量随手用；RTOS 多任务会**并发写**，必须加保护。
  - **重入**：裸机 ISR 与主循环"串行"，函数可重入性不重要；RTOS 下多任务同时进同一函数 → **非线程安全**库出问题。
  - **阻塞/调度**：裸机 `delay`/忙等只是"占 CPU"，RTOS 里忙等会**饿死其它任务、破坏实时**，必须改成阻塞让出。
  - **中断语义**：裸机 ISR 能随便做；RTOS 里 ISR **不能阻塞/切调度**，改用 `FromISR` + 任务接管。
  一句话总结：**把裸机的"主循环+ISR"拆成"多个任务 + 事件驱动 + 临界区保护"，并尊重"中断不阻塞、共享要加锁、延时用任务、栈堆按任务规划"。**

## 深读

### 裸机 vs RTOS 迁移对照表

| 维度 | 裸机 | RTOS 做法 |
|---|---|---|
| 执行模型 | main 循环 + ISR | 多任务 + 调度器 + ISR |
| 延时 | `delay_ms`/`HAL_Delay`（忙等） | `vTaskDelayUntil`/`vTaskDelay`（让出） |
| 共享状态 | 无竞争 | **互斥/关中断/原子** |
| ISR 处理 | 可做较多 | 只"存+FromISR通知"，重活入任务 |
| 共享缓冲 | 直接读写 | 队列/环形缓冲/DMA |
| 非重入库 | 无碍 | 用 `_r` 版本或加锁 |
| 看门狗 | main 喂 | 任务心跳汇总 |
| 栈/堆 | 进程级 | 每任务独立栈 + heap 管理 |

### 关键踩坑点

- **`HAL_Delay` 留在任务里**：会**忙等**、饿死其它任务、不能真正让出 CPU。改成 `vTaskDelay`。
- **`while(flag)` 等待中断**：原裸机"等标志"搬进任务会**死等/占 CPU**；改成**阻塞等**（`xQueueReceive`/`xEventGroupWaitBits`/信号量 take）。
- **回调/库函数被多任务同时调用**：加锁或用可重入版本，避免**数据竞争**。
- **在中断里发普通信号量/队列**：必须用 `FromISR` 版；否则断言/崩溃。

### 源码级：`HAL_Delay` vs `vTaskDelay` 的本质区别

```c
// HAL_Delay: 忙等(裸机) —— 占 CPU, 不让调度
void HAL_Delay(uint32_t Delay) {
  // 纯 while 轮询 tick, 任务被切走就"假延时"
}
// vTaskDelay: 挂起当前任务, 进入延时列表, 让出 CPU
void vTaskDelay(TickType_t xTicksToDelay) {
  // 把 pxCurrentTCB 放进延时链 -> 等 xTickCount 到期 -> 唤醒
  // 期间调度器可跑其它任务
}
```
- 裸机 `HAL_Delay` 依赖"主循环还在转"；RTOS 里任务忙等会让**调度器认为 CPU 忙**，饿死更紧急任务。

### 移植七步法（实践建议）

1. 盘点**共享资源**，逐一定保护策略。
2. 把所有**中断里的重活**移出，改成"ISR 存 + 队列/通知 + 任务处理"。
3. 把**主循环逻辑**拆成**若干任务**，明确优先级与周期。
4. 把**忙等/Delay** 改**阻塞延时**。
5. **外设 init 放调度器启动前**，任务创建好后再 `vTaskStartScheduler`。
6. 确认**堆/栈配额**，用**内存池**替换不安全的 `malloc`。
7. **看门狗与错误处理**（断言/栈溢出钩子）一并接入。

### 工程场景

- **症状**：移植后任务乱跑/卡死/数据互洗；延时不准；某任务饿死。
- **根因**：忙等 `HAL_Delay`、共享数据没加锁、非重入库多任务共用、中断里用普通 API。
- **对策**：逐个替换忙等为阻塞延时；共享加锁；非重入函数用 `_r` 版或加锁；中断用 `FromISR`。

### 进阶追问链

1. **Q：为什么裸机里 `HAL_Delay` 能用，RTOS 里不行？** → 裸机单线程，忙等只占自己 CPU；RTOS 里任务忙等会**饿死更低优先级任务**、不把 CPU 让给调度，破坏实时。改用 `vTaskDelay`（挂起任务、让调度）。
2. **Q：非线程安全的库函数怎么办？** → 用**可重入版本**（`strtok_r`、`localtime_r`），或**加互斥锁**，或改成**把数据交给任务处理**（避免多任务共享缓冲）。
3. **Q：中断里原来的处理逻辑搬不动怎么办？** → **拆两段**：ISR 只做"最短地收数据 + 置标志/FromISR 通知"，慢速解析/运算/上报放任务；或用 **DMA** 搬运，ISR 只通知完成。
4. **Q：`malloc` 在多任务共享环境安全吗？** → FreeRTOS 默认 heap 实现（heap_1~5）**不是线程安全**，需用**内存池/或加锁包 `pvPortMalloc`**；或在**任务创建时一次性分配**、运行期不 `malloc`。

> 📌 一句话记忆：**裸机转RTOS＝把"主循环+ISR"改"多任务+事件驱动+临界区"：中断用FromISR、共享加锁、延时用vTaskDelay让出、非重入库可重入/加锁、外设init在调度器前、堆栈按任务规划、看门狗改心跳、规避优先级反转；别再留HAL_Delay忙等和while(flag)。**
