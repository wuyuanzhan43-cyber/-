answer: |
  中断响应流程是**硬件自动完成大部分现场保护**的。以 Cortex-M 为例，进入中断后硬件自动做的关键几步：

  1. **判定**：NVIC 判断该中断是否使能、优先级是否允许抢占（更高抢占优先级则**嵌套**）。
  2. **自动压栈现场（关键）**：硬件自动把 **`R0–R3`、`R12`、`LR`、`PC`、`xPSR`** 这 **8 个字**压到当前栈指针上，形成**基础异常帧**；若启用 FPU 且异常时使用浮点，还自动压入 `S0–S15/FPSCR` 扩展帧（受 **lazy stacking** 控制）。
  3. **读向量表取入口**：从**向量表**读出该中断对应的 **Handler 入口地址**（`SCB->VTOR` 指向；`__ISR` 异常向量）。
  4. **更新关键寄存器**：把 **`LR` 设置为 `EXC_RETURN`**（编码返回到哪个栈/模式/是否浮点），更新 **`IPSR`**（记录当前异常号），处理器切到 **handler mode、使用 MSP**，进入 ISR。
  5. **ISR 执行**（短、原子、可重入，必要时用 `FromISR` API）。
  6. **异常返回**：`BX LR`，硬件按 `EXC_RETURN` **弹栈**恢复 8 字（及浮点帧）、还原被中断现场。

  ### 一句话
  **硬件自动保存的"现场"＝8 字异常帧（R0–R3/R12/LR/PC/xPSR，可选浮点扩展帧），压到当前栈；用 `EXC_RETURN` 记住怎么回来；向量表决定跳到哪个 Handler。**
why: |
  追问"现场保护谁来做"时要能讲清**硬件已经把最小集自动压好**了，ISR 里几乎不用写保存代码——这是 Cortex-M 与老架构（软件保存全部寄存器）的重大差异。
  关键是**把这 8 字和"谁负责 R4–R11"分开**：硬件只保**caller-saved + 控制流**（R0–R3/R12/LR/PC/xPSR），`R4–R11` 由编译器/RTOS 补；硬件用 `EXC_RETURN` 记录"返回到哪个栈、是否浮点、什么模式"。

## 深读

### 中断响应全流程（硬件自动）

| 步骤 | 硬件动作 | 说明 |
|---|---|---|
| 1 判定 | NVIC 判使能/优先级 | 决定能否抢占当前上下文（**可嵌套**） |
| 2 压栈 | **自动压 8 字**（R0–R3/R12/LR/PC/xPSR）到当前栈 | 可选：FPU 扩展帧（S0–S15/FPSCR） |
| 3 取向量 | 从**向量表**读 Handler 地址 | `SCB->VTOR` 指向向量表；异常号→入口 |
| 4 切态 | LR←`EXC_RETURN`，IPSR←异常号，切 handler mode/MSP | 为返回记"路标" |
| 5 执行 | 跳转 ISR | 短、原子、可重入 |
| 6 返回 | `BX LR`，按 `EXC_RETURN` 弹栈恢复 | 回到被打断处 |

### 向量表与`VTOR`

- **向量表**：`词表[异常号] = 入口地址`，含复位、NMI、HardFault、SVC/PendSV/SysTick、及各外设中断。
- **`SCB->VTOR`**：向量表基址（默认 0x08000000 等）；重定位（如把向量表放进 RAM）会改这里。
- 响应异常时，硬件用**当前异常号**作为索引，从向量表取入口跳转。

### 硬件自动保存的寄存器（8 字）与为何必须保存

| 寄存器 | 为何必须 |
|---|---|
| `PC(R15)` | 保存"回到哪条指令" |
| `xPSR` | 保存条件码/状态位 |
| `LR` | 存 `EXC_RETURN`（"怎么走"的路标） |
| `R0–R3/R12` | 调用者保存寄存器 + 临时寄存器，给 ISR 用 |

- 其余（R4–R11）由编译器/RTOS 保护。

### 工程场景

- **症状**：ISR 返回后，被中断函数的局部变量/返回值变乱。
- **根因/排查**：`EXC_RETURN` 配错（回到错误栈/模式）、或向量表基址错（跳到错 Handler）、或嵌套/共享数据未保护。
- **对策**：确认 `VTOR` 正确、`EXC_RETURN` 由硬件自动维护（勿手动改 LR）、ISR 里遵守"短 + 不共享未保护数据 + 用 FromISR"。

### 进阶追问链

1. **Q：为什么不把 R4–R11 也自动压了？** → 压 8 字已够回到现场并恢复状态；R4–R11 由编译器/RTOS 在需要时保存，硬件只压"最小可恢复集"，避免每个中断都扛 12+ 字。
2. **Q：`EXC_RETURN` 一定存在 LR 里？会覆盖吗？** → 进异常时硬件把它写到 LR；ISR 里若调用子函数，IR/LR 会被子函数改写（用入栈保护）。返回用"异常返回时的 LR"（压栈保存），否则用错值。
3. **Q：向量表放 RAM 和放 Flash 的区别？** → 放 Flash 掉电不丢、但不可运行时修改；放 RAM 可动态重定位（如做**动态中断回调**），但也可能被写坏。`SCB->VTOR` 指向之。
4. **Q：中断嵌套时，异常帧压在哪？** → 每次嵌套都压到**同一 MSP**（handler mode 用 MSP），逐层压 8 字；返回逐层弹回。

> 📌 一句话记忆：**中断响应＝NVIC判定→硬件自动压8字(R0–R3/R12/LR/PC/xPSR, 可选浮点×lazy stacking)到当前栈→读向量表(VTOR)取入口→LR=EXC_RETURN、IPSR=异常号、切handler mode→执行ISR→BX LR按EXC_RETURN弹栈恢复；R4–R11由编译器/RTOS补。**
