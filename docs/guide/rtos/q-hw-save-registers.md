answer: |
  中断响应流程是**硬件自动完成大部分现场保护**的。以 Cortex-M 为例，进入中断后硬件自动做的关键几步：

  1. **判断与响应**：NVIC 判断该中断是否使能、优先级是否允许抢占（更高抢占优先级则嵌套）。
  2. **自动压栈现场（关键）**：硬件自动把 **`R0–R3`、`R12`、`LR`、`PC`、`xPSR`** 这 **8 个字**压到当前栈指针上，形成**基础异常帧**；若启用 FPU 且异常时使用浮点，还自动压入 `S0–S15/FPSCR` 扩展帧。
  3. **读向量表取入口**：从**向量表**读出该中断对应的 **Handler 入口地址**（中断向量）。
  4. **更新关键寄存器**：把 **`LR` 设置为 `EXC_RETURN`**（编码返回到哪个栈/模式/是否浮点），更新 **`IPSR`**（记录当前异常号），处理器切到 **handler mode、使用 MSP**，进入 ISR。
  5. **ISR 执行**（短、原子、可重入，必要时用 `FromISR` API）。
  6. **异常返回**：`BX LR`，硬件按 `EXC_RETURN` **弹栈**恢复 8 字（及浮点帧）、还原被中断的现场。

  **一句话**：硬件自动保存的"现场"＝**8 字异常帧（R0–R3/R12/LR/PC/xPSR，可选浮点扩展帧）**，压到当前栈；用 `EXC_RETURN` 记住怎么回来。
why: |
  面试追问"现场保护谁来做"时，要能讲清**硬件已经把最小集自动压好**了，ISR 里几乎不用写保存代码。这是 Cortex-M 与老架构（如 M0 以前的软件保存全部寄存器）的重大差异。
  关键是**把这 8 字和"谁负责 R4–R11"分开**：硬件只保**调用者保存寄存器 + 控制流**（R0–R3/R12/LR/PC/xPSR），`R4–R11` 由编译器/RTOS 补；硬件用 `EXC_RETURN` 记录"返回到哪个栈、是否浮点、什么模式"，返回时按它弹栈。

## 深读

### 中断响应全流程（硬件自动）

| 步骤 | 硬件动作 | 说明 |
|---|---|---|
| 1 判定 | NVIC 判断使能/优先级 | 决定能否抢占当前上下文（**可嵌套**） |
| 2 压栈 | **自动压 8 字**（R0–R3/R12/LR/PC/xPSR）到当前栈 | 可选：FPU 扩展帧（S0–S15/FPSCR） |
| 3 取向量 | 从**向量表**读 Handler 地址 | 向量表：每个异常号→入口 |
| 4 切态 | LR←`EXC_RETURN`，IPSR←异常号，切 handler mode/MSP | 为返回记"路标" |
| 5 执行 | 跳转 ISR | 短、原子、可重入 |
| 6 返回 | `BX LR`，按 `EXC_RETURN` 弹栈恢复 | 回到被打断处 |

### 硬件自动保存的寄存器（8 字）

```
R0, R1, R2, R3    ← 调用者保存寄存器(caller-saved)
R12               ← 临时寄存器(调用者保存)
LR(R14)           ← 存 EXC_RETURN(不是普通返回地址)
PC(R15)           ← 被打断处下一条指令地址
xPSR              ← 状态寄存器(条件码/中断标志等)
```

- 这些是**能让程序精确恢复执行**的最小集。`PC` 存"回到哪"，`xPSR` 存"状态位"，`LR` 存"用 EXC_RETURN 怎么走"。

### 谁保存 R4–R11

`R4–R11`（被调用者保存寄存器）**不在**硬件自动帧里。它们由：
- **中断内**：编译器在 ISR prologue 里按 AAPCS 按需保存；
- **任务切换**：FreeRTOS 移植层汇编在 PendSV 里手动保存/恢复。

### 常见追问

- **Q：为什么硬件只保存 8 个字而不是全部？**
  A：8 字足以回到被打断处并恢复状态。caller-saved（R0–R3/R12）由调用方保护，callee-saved（R4–R11）由编译器/RTOS 保护——分工明确，硬件只需管"控制流 + 参数/状态"。

- **Q：返回时怎么知道用哪个栈、是否要恢复浮点？**
  A：看 `EXC_RETURN`（存于 LR）。它的低 4 位编码：bit2 选 MSP/PSP、bit4 是否含浮点帧、bit3 返回 handler/thread mode。`BX LR` 时硬件据此弹栈。

- **Q：中断响应流程里，向量表起什么作用？**
  A：向量表是"异常号 → Handler 入口地址"的映射表（含复位、NMI、HardFault、PendSV、SysTick、各外设中断等）。硬件响应异常时从向量表取入口跳转，这就是"中断向量"。

> 📌 一句话记忆：**中断响应＝NVIC 判定 → 硬件自动压 8 字(R0–R3/R12/LR/PC/xPSR，可选浮点)到当前栈 → 读向量表取入口 → LR=EXC_RETURN、切 handler mode → 执行 ISR → BX LR 按 EXC_RETURN 弹栈恢复。**
