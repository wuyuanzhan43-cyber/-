answer: |
  **共享资源**（全局变量、外设、环形缓冲、文件句柄等）被**两个以上任务/中断并发访问**时，会有**竞争条件（race condition）**——尤其是"**读-改-写（RMW）**"或"**并发写**"这类操作，结果取决于执行先后，无法复现、难调。保证一致性要按"**临界区长度**"和"**是否需要继承**"选手段：

  | 手段 | 适用 | 注意 |
  |---|---|---|
  | **互斥锁（Mutex）** | 较长临界区 / 资源独占 | 带优先级继承；持锁别做慢活 |
  | **关中断** `taskENTER_CRITICAL` | **极短**临界区 | 屏蔽中断（basepri）；禁在里阻塞 |
  | **挂起调度器** `vTaskSuspendAll` | 不关中断但禁切换 | ISR 仍运行；长链表/序列保护 |
  | **原子操作/无锁** | 单字读写、标志位 | `LDREX/STREX`、位带、内存屏障 |
  | **队列/消息传递** | 转移数据所有权 | 避免"共享写"，改"传递" |
  | **任务通知/事件组** | 同步点而非数据保护 | 不是"锁"，别误用 |

  ### 关键原则
  1. **最小化共享面**：能用局部变量/参数就别用全局；尽量"算完再一次性写"。
  2. **临界区最短**：锁/关中断里**绝不阻塞、不做慢活**（打印/解析/外设长操作）。
  3. **锁顺序一致**：多个锁按**固定顺序获取**，防止**死锁**；避免嵌套锁。
  4. **识别"读-改-写"**：`count++`、`flag=flag|x` 这类都需要保护，只读无需锁。
  5. **可重入/线程安全**：避免在函数里用共享的 static 缓冲，改用传入缓冲。
why: |
  竞争条件的本质是**操作不是原子的**：任务的"读"可能被切换打断，另一个任务"写"到一半，再切回来继续——中间状态就错了。嵌入式里共享资源到处是（全局状态、外设寄存器、FIFO），所以"**要不要保护、怎么保护**"是常考点。
  - **为什么有时用关中断、有时用互斥锁**：**临界区越短越该关中断**（开销小、无继承需求、但屏蔽所有中断影响实时）；**临界区较长**才用**互斥锁**（可让其它任务等待、带继承、但引入阻塞）。
  - **为什么尽量无锁**：锁开销（上下文切换/阻塞/反转）不小；**单字 RMW** 用**原子指令**即可。
  - **为什么锁序要一致**：多个任务不同顺序申请多把锁 → **死锁**（互相等对方）。
  这一题给的是"**选型 + 纪律**"，比单背一种锁更能拿高分。

## 深读

### 竞争条件示例：`count++` 不是原子的

```
任务A: 读 count
        [被切换] ← 任务B 读 count、写 count (改了)
        [切回] 任务A 写 count (覆盖B的修改)  → 丢了一次计数
```
- 解决：把 `count++` 放进**临界区**（关中断/互斥）或用**原子**（`ldrex/strex`，Cortex-M3+ 支持）。

### 源码/指令级：原子操作（LDREX/STREX）

```c
__asm volatile (
  "ldrex r1, [%0]\n"      // 独占读
  "add   r1, r1, #1\n"
  "strex r2, r1, [%0]\n"  // 独占写; 若期间被改则失败(r2!=0)
  "teq   r2, #0\n"
  "bne   ..."             // 失败则重试
);
```
- **LDREX/STREX（独占访问）**用于**单个字**原子读改写；若期间被其它写打断，`STREX` 失败需重试。
- `strex` 失败重试 loop, 适合**短且高频**的计数/标志。

### 选型速查

| 场景 | 推荐 |
|---|---|
| 极短、多任务/中断抢一个计数或标志 | 关中断 / `taskENTER_CRITICAL` |
| 稍长、需要"独占+继承" | **互斥锁** |
| 一次性搬数据、避免共享写 | **队列/消息** |
| 单字读改写、高频 | **原子指令**（`LDREX/STREX`、位带） |
| 保护一长串链表/序列、不能关中断太久 | **`vTaskSuspendAll`（挂起调度器）** |
| 只读不写 | 【无需锁】 |

### 源码级：`vTaskSuspendAll` 的"挂起调度器"语义

- 用**全局计数 `uxSchedulerSuspended`**：`vTaskSuspendAll()` ++，`xTaskResumeAll()` --。
- 挂起期间**中断照常运行**，但**任务不切换**（任务就绪/唤醒被暂存，`ResumeAll` 时统一处理）。
- 适合保护一长串"不能被打断但又希望 ISR 不丢"的操作；不会像 `taskENTER_CRITICAL`（basepri）那样把硬实时中断也关掉。

### 工程场景

- **症状**：多任务写同一全局计数/状态，偶发丢更新/值错乱；或多个锁互相等（死锁）。
- **根因**：未保护的 RMW；或加锁顺序不一致导致死锁。
- **对策**：RMW 用临界区/原子；多锁**固定顺序**、避免嵌套；能队列转移所有权就转移；用 `vTaskSuspendAll` 保护长链表。

### 进阶追问链

1. **Q：什么时候用关中断，什么时候用互斥锁？** → 极短且需与中断/任务互斥 → 关中断（`taskENTER_CRITICAL`，开销小）；较长、需等待与继承 → 互斥锁。关中断能屏蔽中断但不能等；互斥锁能等但有阻塞/反转成本。
2. **Q：为什么 `vTaskSuspendAll` 能保护而不用关中断？** → 它不关中断（ISR 照跑），只是禁止任务切换（`uxSchedulerSuspended`）。适合保护一长串"不能被打断但又希望 ISR 不丢"的操作，不会拖大中断延迟。
3. **Q：怎么避免死锁？** → 固定加锁顺序、避免嵌套锁、加锁超时/一次性申请；或尽量只用一把锁、缩短持锁时间。
4. **Q：`LDREX/STREX` 和位带都能做原子，区别？** → `LDREX/STREX` 是**独占访问**（多核/中断安全，需配对、失败重试）；**位带**（Cortex-M 特有）把**单个位**映射成可原子读写的词，适合**单个标志位**，但只对本位，不跨位/跨核。

> 📌 一句话记忆：**共享资源一致性＝按临界区长度选型：极短用关中断/basepri，较长用互斥锁(继承)，挂起调度器(vTaskSuspendAll/uxSchedulerSuspended)保护长序列，单字用原子(LDREX/STREX、位带)，大数据用队列转移所有权；纪律：最小共享面、临界区最短、锁序一致、识别读改写、可重入。**
