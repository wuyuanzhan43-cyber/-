answer: |
  **关键：这是两个不同维度，不能直接比大小。**
  - **中断优先级**是**硬件异常等级**（NVIC 配置），决定"哪个中断**优先响应/能否嵌套抢断其它中断**"；
  - **任务优先级**是**调度器软件等级**（TCB 的 `uxPriority`），决定"哪个任务**优先得到 CPU**（在就绪任务里）"。

  但从"**谁先跑、谁能打断谁**"的现实语义看：**中断永远优先于任务**。因为中断是**异步硬件事件到紧急响应**——只要中断被使能且发生，处理器**立即脱离任务调度进入 ISR**，即使任务优先级再高也会被打断。仅有"关中断/临界区"能把中断暂时挡在门外。

  **冲突时的处理规则（三层）**：
  1. **中断 vs 任务**：中断**绝对优先**，任务随时可能被中断抢占。任务与中断共享数据时，任务侧必须用**关中断（`taskENTER_CRITICAL`/`portSET_INTERRUPT_MASK`）**或 `vTaskSuspendAll` 保护临界区，否则会被中断打断造成竞态。
  2. **中断 vs 中断**：由 NVIC **抢占优先级**决定，更高抢占优先级中断可**嵌套**打断低优先级 ISR（子优先级只定同抢占级下的先后）。
  3. **能否在中断里用 RTOS API**：由 **`configMAX_SYSCALL_INTERRUPT_PRIORITY`** 划界——**优先级数值低于等于它（更紧急）的中断不能调用任何 FreeRTOS API**，只能做纯硬件、极短处理；**优先级数值高于它（没那么紧急）的中断可用 `FromISR` API**。
why: |
  这一题考的是"**别把中断优先级和任务优先级混在一起比**"。很多人答"中断比任务高"，其实只对了一半——它们根本不在一个维度：中断是**硬件抢占**，任务是**软件调度**。
  真正要处理的是**三类冲突**：
  - **任务被中断打断**（临界区被破坏）→ 用**关中断/挂起调度器**保护；
  - **中断里不能阻塞/不能切任务** → 只用 `FromISR` API、标记 + `PendSV` 延迟切换；
  - **该中断能不能碰 RTOS 内核** → `configMAX_SYSCALL_INTERRUPT_PRIORITY` 划出安全区。
  顺带注意**数值方向**：STM32 抢占优先级**数值小=高**，FreeRTOS 任务优先级**数值大=高**，方向相反，特别容易说反。

## 深读

### 中断优先级 vs 任务优先级：两个维度

| 维度 | 中断优先级 | 任务优先级 |
|---|---|---|
| 归属 | 硬件（NVIC） | 软件（调度器，TCB `uxPriority`） |
| 决定什么 | 哪个中断**先响应**、能否**嵌套** | 哪个就绪任务**先运行**、能否**抢占** |
| 数值方向 | **小 = 高**（STM32/Cortex-M） | **大 = 高**（FreeRTOS） |
| 是否打断任务 | 是，**任何中断都优先于任何任务** | 只影响任务之间 |

### 现实语义：为什么"中断永远优先于任务"

- 中断是**硬件异步事件**，处理器一旦收到且 NVIC 放行，就**立刻暂停当前任意执行流（含任何任务）进入 ISR**。
- 所以**任何任务（哪怕最高优先级）都可能被任一使能的中断打断**——这是"任务临界区必须关中断/挂起调度器"的根本原因。

### 三层冲突处理

```
[层1] 中断 vs 任务：中断绝对优先
      → 任务侧用 taskENTER_CRITICAL(关中断/basepri) 或 vTaskSuspendAll(挂起调度) 保护
      → 中断侧不用会阻塞的 API，只 FromISR

[层2] 中断 vs 中断：NVIC 抢占优先级决定嵌套
      → 更高抢占优先级可打断当前 ISR；子优先级只定先后(不嵌套)

[层3] 能否用 RTOS API：configMAX_SYSCALL_INTERRUPT_PRIORITY 划界
      → 比它更紧急(数值更小)的中断：不许调用任何 FreeRTOS API，只做纯硬件/极短
      → 比它不紧急(数值更大)的中断：可用 FromISR API
```

### 优先级分组的坑（STM32）

- 用 `NVIC_PriorityGroupConfig` 把优先级总位数（4 位）分成**抢占+子优**两级。
- **抢占优先级**决定**能否嵌套**（数值小=高）；**子优先级**只在同抢占级里**定先后**，不嵌套。
- 不同任务/中断里**分组要一致**，否则嵌套行为混乱。

### 常见追问

- **Q：为什么说中断"比任务高"不完全对？**
  A：中断优先级是硬件抢占等级，任务优先级是软件调度等级，**维度不同**。从"能否打断任务"看中断优先；但从"能否在中断里调度/阻塞"看，中断反而**受限**（不能阻塞、不能切）。所以准确说法是"中断能抢占任务，但中断里不能做任务的事（调度/阻塞）"。

- **Q：`configMAX_SYSCALL_INTERRUPT_PRIORITY` 干什么用？**
  A：为"**能用 FreeRTOS API 的中断**"划最高优先级界限。比它更紧急的中断（数值更小）**运行时会被临界区屏蔽**，因此**禁止调用 RTOS API**，只做纯硬件/极短处理；这样内核临界区与调度器不会被打断。

- **Q：任务里怎么访问被中断共享的数据？**
  A：短则**关中断**（`taskENTER_CRITICAL`），长则**挂起调度器**（`vTaskSuspendAll`），或在任务间用**队列/互斥/任务通知**传递；绝不要在临界区里做会阻塞的操作。

> 📌 一句话记忆：**中断优先级(NVIC,小=高)与任务优先级(TCB,大=高)是两维度；中断可抢占任何任务，但中断里不能阻塞/切任务；任务侧用关中断/挂起调度保护，configMAX_SYSCALL_INTERRUPT_PRIORITY 划出哪个中断能用 RTOS API。**
