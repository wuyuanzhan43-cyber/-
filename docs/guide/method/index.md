# 备考与方法论

> 除知识点外，面试同样是“信息组织”与“表达”的比拼。这里给几条可执行的方法。

## 核心建议

1. **先骨架后肉**：先把「C/OS/Linux/驱动/ARM/总线」这根主线串起来，再逐题填“为什么”。
2. **每题讲三层**：一句话结论 → 3 点展开 → 一个例子。面试官问“为什么”时按这三层递进。
3. **能手撕就手撕**：反转链表、内存对齐 sizeof、位操作、单链表、快慢指针等，练到能写。
4. **把“为什么”当考点**：多数追问都藏在“为什么”里（为什么 volatile、为什么对齐、为什么信号量会反转）。
5. **结合项目讲故事**：八股是“地基”，用你做过的一个具体项目（移植、驱动、功耗、BUG 排查）把知识点串成故事，是最稳的加分项。

## 一个万能答题框架（STAR 变体）

- **结论先行**：直接给答案（1 句）。
- **展开**：总分总的 2–3 个要点。
- **例子/数据**：报一个实测或项目细节。
- **边界/坑**：主动提“但要注意…”，体现深度。

## 高频“为什么”自查

- 为什么 volatile 不能保证原子性？
- 为什么内存要对齐？
- 为什么设备树能实现“一内核多种板卡”？
- 为什么信号量做互斥会反转而互斥锁不会？
- 为什么中断里不能阻塞？
- 为什么 DMA 仍要完成中断？

> 每一题在本手册都有对应「为什么」章节，建议背熟后再自测一遍。
