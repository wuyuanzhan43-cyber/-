answer: |
  RT-Thread 的**线程间通信**主要有：**消息队列（`rt_mq`）、邮箱（`rt_mb`）、信号（`rt_signal`）**，另有线程事件/环形缓冲等。

  ### 消息队列（`rt_mq`）
  - 传递**定长消息**（每个消息大小固定，容量可多条），`rt_mq_create/init`、`rt_mq_send`（队尾）/`rt_mq_send_urgent`（队首）/`rt_mq_recv`（可带 `RT_WAITING_NONE`/超时）。
  - **带拷贝**：发送时把消息**拷入**队列存储区，接收时拷出——安全、FIFO、支持多生产者/多消费者。
  - 中断里可 `rt_mq_send`（ISR 安全）。

  ### 邮箱（`rt_mb`，RT-Thread 特色，轻量）
  - 传递**一个 32 位字**（可作指针/小整数），`rt_mb_create/init`、`rt_mb_send`/`rt_mb_recv`。
  - **无拷贝**、内存开销小、**更快**；适合“**传一个地址/小值**”，把大数据放共享区只传指针。
  - 中断可 `rt_mb_send`/`rt_mb_send_wait`（ISR 安全）。

  ### 信号（`rt_signal`，RT-Thread 特色，类似 Unix 信号）
  - 内核/线程发给**指定线程**的**异步通知/打断**（`rt_thread_kill`/`rt_signal_send`），线程里用 `rt_signal_install` 注册处理函数、`rt_signal_unmask` 屏蔽。
  - 用于“**线程被外部/内核异步打断**”（如 Ctrl+C、异常通知），不适合常规数据搬运。

  ### 怎么选
  - **传递“数据/多字节/FIFO/保序”** → 消息队列（拷贝、安全）。
  - **传“一个指针/小整数、要快省”** → 邮箱（无拷贝、单字）。
  - **异步通知某个线程** → 信号。
why: |
  这一题考“**RT-Thread 通信对象怎么选**”，核心是**邮箱与消息队列的区别**（容易混）：
  - **消息队列**是“**数据信箱**”：定长、多条、FIFO、**拷贝**——能传**真实数据且保序、多人读写**，代价是拷贝与队列管理。
  - **邮箱**是“**单字信箱**”：**只传一个 32 位值**、**无拷贝、更快更省**——适合“**传个指针/状态码**”，大数据放共享区只传地址；但不能传任意长度、不能存多条大消息。
  - **信号**是“**异步打断**”：本质是“通知/打断某个线程”，不是常规数据搬运，语义更像 Linux 信号。
  理解了“**队列要拷贝、邮箱单字不拷贝、信号是通知**”，就能答对“RT-Thread 用哪个传数据”。

## 深读

### 三种通信对比

| 维度 | 消息队列 | 邮箱 | 信号 |
|---|---|---|---|
| 载荷 | 定长消息(任意大小) | 一个 32 位字 | 无(只是通知) |
| 拷贝 | 有(拷入/拷出) | **无** | / |
| FIFO/多条 | ✅ 容量>1, 保序 | 可多条(单字) | / |
| 多消费者 | ✅ | 单接收线程 | 单接收线程 |
| 中断里 | ✅ `rt_mq_send` | ✅ `rt_mb_send` | 部分 |
| 典型 | 传传感器帧/命令 | 传指针/状态码 | 异步打断处理 |

### 无拷贝邮箱的价值

```c
// 邮箱: 只拷一个 word, 很快
rt_err_t rt_mb_send(rt_mailbox_t mb, rt_ubase_t value);
rt_err_t rt_mb_recv(rt_mailbox_t mb, rt_ubase_t *value, rt_int32_t timeout);
// 用法: 把大数据放共享区, 只传其指针(地址)给接收线程
```
- 适合**低频、传地址/小值**的场景；高频大数据仍应结合**共享缓冲/环形缓冲/DMA** 防吞。

### 中断里“安全用哪些 IPC”

| 中断里可用 | 说明 |
|---|---|
| `rt_sem_release` | 唤醒等待信号量的线程 |
| `rt_mq_send` | 把消息投进队列 |
| `rt_mb_send` | 把单字投进邮箱 |
| `rt_event_send` | 置事件标志 |
| ❌ `rt_mutex_take`/`rt_sem_take`/`rt_mq_recv`(阻塞) | 会阻塞，中断里禁止 |

### 工程场景

- **症状**：中断收数据要传任务，消息队列拷贝开销大、或邮箱传大数据时读不到。
- **根因/对策**：**传真数据**用消息队列；**传“指向共享区的大数据”**用邮箱（只传指针）或**DMA+环形缓冲**；别在中断里 `take`/阻塞。

### 进阶追问链

1. **Q：消息队列和邮箱怎么选？** → 传“多字节/保序/多人读写/需拷贝隔离”用消息队列；传“一个指针/小整数、要快省、无拷贝”用邮箱；大数据用邮箱传指针 + 共享缓冲。
2. **Q：为什么邮箱比消息队列快？** → 邮箱只拷一个 `rt_ubase_t`（单字、无拷贝、无队列元素管理），消息队列要拷定长消息 + 维护队列存储；所以邮箱内存省、更快，但只能传单字。
3. **Q：邮箱能传大数据吗？** → 本质只传一个 word。大数据可“**把数据放共享区，用邮箱传其指针**”，但要保证共享区访问一致性（互斥/环形/单生产者），否则又回到数据竞争。
4. **Q：信号（rt_signal）和普通 IPC 区别？** → 信号是**异步打断/通知**某个线程（注册处理函数、可屏蔽），像 Unix 信号；普通 IPC（队列/邮箱）是“发数据/同步”，语义不同。信号不适合高频数据流。

> 📌 一句话记忆：**RT-Thread 通信＝消息队列(rt_mq: 定长、多条、FIFO、拷贝，传真数据) / 邮箱(rt_mb: 单32位字、无拷贝、快省，传指针/小值) / 信号(rt_signal: 异步打断/通知某线程)；中断里用 rt_sem_release/rt_mq_send/rt_mb_send/rt_event_send，绝不用 take/阻塞版；大数据用邮箱传指针+DMA/环形缓冲。**
