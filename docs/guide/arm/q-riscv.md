answer: |
  **RISC-V** 是一种**开源、精简、模块化**的指令集（ISA），与 ARM 的区别在于**更精简、无历史包袱、指令少、可扩展**；指令用**统一的编码**，系统寄存器用 **CSR（控制和状态寄存器）** 访问（ARM 用协处理器/内存映射）。

  **特权级（Privilege Level）**：三种模式，
  - **M 模式（Machine）**：最高特权，可访问全部 CSR、控制底层；**裸机/无 OS 或 RTOS 常跑在 M 模式**。
  - **S 模式（Supervisor）**：跑操作系统内核（Linux），需要 **MMU** 支持虚拟内存。
  - **U 模式（User）**：跑用户程序（应用）。
  - 层级从高到低：**M > S > U**；只有配了 MMU 才能跑 S 模式的 Linux。
  关键 **CSR**：`mstatus`（状态）、`mtvec`（异常/中断入口地址）、`mcause`（异常原因）、`mepc`（异常返回地址）、`mhartid`（硬件线程 ID，多核用它区分）。

  **中断/异常**：RISC-V 有**统一的异常入口（trap）**，处理器跳到 `mtvec` 指向的地址处理；`mcause` 记录原因，`mepc` 保存返回地址。比 ARM 更少的外设中断控制器差异（但具体芯片可能用 PLIC/CLINT 等）。

  **沁恒青稞 V4（WCH RISC-V 内核）**：沁恒自研的 RISC-V 内核，广泛用于其 MCU（如 **CH32 系列**）。「**双核**」指**一个芯片集成两个 RISC-V 核心**，可**异构分工**（如核0 跑实时采集/推理、核1 跑通信），核间靠**共享内存 + 硬件信号量（如 HSEM）** 通信——这就是**AMP（非对称多处理）** 落地。
  **双核场景**：一个核跑**裸机/RTOS（实时、确定性）**，另一个跑**通信栈/上层**。两核各自独立，靠**共享内存 + 信号量/邮箱** 协作，互不阻塞对方实时节拍。
why: |
  你简历写「熟悉 **RISC-V（沁恒青稞V4 双核）**」，但很多面试默认问 ARM（STM32），所以你必须能**对比 RISC-V 与 ARM**，并说清**你的双核是什么架构**。
  关键点：**M/S/U 特权级 + CSR + 统一 trap 入口**是 RISC-V 的三个抓手；**双核 = AMP + 共享内存 + 硬件信号量**则直接对应你项目一的 HSEM。能把「RISC-V 基础」和「你的双核项目」打通，就从「会用芯片」升级成「懂架构」。

## 深读

### 一、RISC-V vs ARM（对比表）

| 维度 | RISC-V | ARM（Cortex-M） |
|---|---|---|
| 授权 | **开源**，可自由扩展 | 商业授权 |
| 指令 | **精简、模块化、可选扩展**（M/A/F/D/C 等） | Turbo/Thumb（Cortex-M 用 Thumb） |
| 寄存器 | 32 个 GPR（RV32），编号统一 | 同类，但名字/用法略有差异 |
| 系统寄存器 | **CSR**（`mstatus/mtvec/mcause`…） | CPU 寄存器/协处理器/内存映射 |
| 特权级 | **M/S/U** | Cortex-M 无 OS 级（Handler/Thread 模式） |
| 中断 | 统一 **trap** 入口，机制更简单 | 异常向量表 + NVIC |
| 扩展 | 可加扩展指令（向量、位操作等） | 相对固定 |

### 二、特权级与「哪个核跑什么」

- **M 模式**：跑**裸机/RTOS**（如你核0 的采集+推理）。
- **S 模式**：跑 **Linux**（需要 **MMU** 做虚拟内存）。
- **U 模式**：跑用户程序。

> 所以**「我的双核哪个跑 Linux 哪个跑裸机」** 一下就能对上：**有 MMU 的核（S 模式）跑 Linux，没 MMU 或裸机核（M 模式）跑实时任务**。这正好对应 **AMP**（各核独立 OS、异构分工）。

### 三、关键 CSR（背这几个就够）

| CSR | 作用 |
|---|---|
| `mstatus` | 处理器状态（中断使能、特权级等） |
| `mtvec` | **异常/中断入口地址**（陷阱后跳到这） |
| `mcause` | 异常原因编号 |
| `mepc` | 异常返回地址 |
| `mhartid` | 硬件线程 ID（**多核用这个区分是哪个核**） |

### 四、双核怎么通信（对应你项目一的 HSEM）

```
核0(实时采集/推理)                    核1(通信/BLE)
        │                                 │
        │ 写共享缓冲区                        │
        ├── HSEM 硬件信号量 上锁/解锁 ────────►│
        │◄── HSEM 释放/通知 ───────────────┤
        │  (互斥保护共享内存)                │
        │                                 │
        └── 共享内存(环形缓冲, 单写单读) ─────┘
```

- **HSEM（硬件信号量）**：专用硬件互斥原语，**核间**做互斥用，比「普通 OS 锁」更**贴近硬件、确定性强、不依赖某个核的 OS**。
- 配合**共享内存 + 环形缓冲 + 内存屏障**：**单生产者单消费者**可**无锁**；需保证**缓存一致性**（AMP 无硬件一致性，要用**原子 + 内存屏障 / flush**）。

### 五、常见追问与满分回答

**Q：RISC-V 和 ARM 区别？**
A：RISC-V **开源、精简、可扩展、指令少、用 CSR + 统一 trap**；ARM 商业、指令更丰富、用协处理器/内存映射 + 异常向量表。Cortex-M 无 M/S/U 特权级概念，RISC-V 有 M/S/U 三层。

**Q：你的双核是什么架构（SMP 还是 AMP）？**
A：**AMP（非对称多处理）**——两核**各自独立跑**、分工不同（核0 实时采集推理、核1 通信），**没有统一 OS 调度**；核间靠**共享内存 + HSEM 硬件信号量**协作。（SMP 才是共享内存 + 统一调度 + 跨核。）

**Q：为什么用 HSEM 不用普通互斥锁/关中断？**
A：① 跨核互斥；② **硬件原语、确定性强、不依赖某核的 OS**；③ 比**关整核中断**更**精准**（不屏蔽整个核的中断，实时性更好）。

**Q：哪个核跑 Linux、哪个跑裸机？**
A：**有 MMU（S 模式能力）的核跑 Linux**，**无 MMU 的核（M 模式）跑裸机/RTOS**——这就构成 AMP 的**异构**。

> 📌 一句话记忆：**RISC-V=开源精简可扩展，M/S/U 特权级 + CSR + 统一 trap 入口（mtvec/mcause/mepc）；双核=AMP 异构（一个跑 Linux 一个跑裸机），核间共享内存+HSEM 硬件信号量+内存屏障。**
