answer: |
  **MMU（内存管理单元）**：**虚拟地址→物理地址转换** + 内存保护（页表，多级），用于 **Cortex-A**（跑 Linux/多进程），实现**虚拟内存、隔离、按需分配、共享**；粒度是**页**（页表）。
  **MPU（内存保护单元）**：**只做区域访问保护**，**不做地址转换**；按**区域**（如 8–16 个区域）设置**访问权限**（读/写/执行、特权/用户、缓存属性），用于 **Cortex-M**（裸机/RTOS），防止任务/中断越界访问，保护关键内存。
  **区别**：
  - MMU：转换+保护（页），适合需要虚拟内存/多进程的 Cortex-A/OS。
  - MPU：仅保护（区域），适合 Cortex-M/RTOS 做**内存分区/安全**（隔离栈、只读代码、外设区、禁止执行数据区）。
why: |
  **MMU vs MPU 的取舍是“地址转换+保护（强、复杂）” vs “仅保护（轻、简单）”**：
  - 跑 **Linux/多进程**（需要虚拟内存、地址隔离）→ **MMU**（Cortex-A）。
  - **裸机/RTOS**（不需要虚拟内存，但要防越界/做安全分区）→ **MPU**（Cortex-M）。
  嵌入式安全：用 MPU 把**代码、栈、数据、外设**分成不同权限区域，实现**内存隔离/安全**（如防止栈溢出破坏、防止执行数据区、保护关键数据），是功能安全/RTOS 内存保护的重要手段。

## 深读

### 对照

| | MMU | MPU |
|---|---|---|
| 功能 | 地址转换 + 保护 | 仅保护（无转换） |
| 粒度 | 页（页表） | 区域（数量少） |
| 用于 | Cortex-A / OS | Cortex-M / 裸机 RTOS |
| 用途 | 虚拟内存/隔离/按需 | 内存分区/保护/安全 |
| 开销 | 大（页表/TLB） | 小（少量寄存器） |
| 例 | Linux 多进程 | 隔离栈/只读代码/禁执行数据 |

### MPU 常见用法（Cortex-M）

- 把 **Flash（代码/只读）** 设为只读、**可执行**。
- 把 **栈** 设为可读写（禁执行），防栈溢出/注入。
- 把 **外设寄存器区** 设为特权访问。
- 设置**执行不允许（XN）** 的数据区，防栈/堆执行攻击。
- 区域可以**重叠**（重叠区域由**编号更大的区域**覆盖，即后定义/编号大的生效）。

### MMU 常见用法（Cortex-A）

- 页表映射 VA→PA，实现虚拟内存、进程隔离。
- 页面级**权限**（用户/内核、读/写/执行）。
- 按需分页、共享库、COW、`mmap`。

### 常见追问

- MMU 和 MPU 区别？——MMU 做地址转换+保护（页），MPU 只做区域保护（无转换）。
- 什么时候用 MPU？——Cortex-M/RTOS 做内存分区/安全，不需要虚拟内存。
- MPU 能防栈溢出吗？——能，把栈设为受限区域，越界触发异常。
- 为什么 MMU 给 Linux？——需要进程隔离/虚拟内存/按需，MMU 提供。

> 📌 一句话记忆：**MMU=地址转换+保护(页, Cortex-A/OS, 虚拟内存/隔离)；MPU=仅区域保护(Cortex-M/RTOS, 内存分区/安全, 无转换)。**
