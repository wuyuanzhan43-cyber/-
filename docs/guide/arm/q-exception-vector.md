## 深读

### 一、为什么要有“向量表”（从原理推导）

CPU 要对外部事件（中断、异常、复位）做出反应，但**发生在哪一刻是不确定的**。所以 CPU 规定：**每种异常都有固定的入口地址**，把这些入口按顺序排成一张表——**异常向量表**。发生某类异常时，CPU **自动跳到对应槽位**，再跳到处理函数。这解决了“不知道中断何时来、来了去哪”的问题。

- 每个槽位通常放一条 `ldr pc, =handler`（或 `b handler`），跳到真正的处理函数。
- 表中每项 **4 字节**（ARM 指令宽度），从上电地址开始。
- **向量表是“入口地图”**：给你一个固定的跳转点，而不需要在 CPU 里硬编码每个 handler。

### 二、图示：异常向量表布局

```
地址(基址+偏移)   内容
0x00000000  Reset(复位)          ← 上电从这里开始
0x00000004  Undefined Instruction
0x00000008  SWI/SVC(软中断/系统调用)
0x0000000C  Prefetch Abort
0x00000010  Data Abort
0x00000014  (保留)
0x00000018  IRQ(普通中断)
0x0000001C  FIQ(快速中断)
        ↑每项 4 字节；基址由 VBAR/重映射决定
```

### 三、启动流程（从复位到 C 世界）

```
上电复位 → 从复位向量(0x00)取指 → 进入特权模式(SVC)
   → 1. 设栈 SP(当前模式)
   → 2. 拷贝 .data(Flash→RAM)
   → 3. 清零 .bss
   → 4. 初始化时钟/外设/MMU
   → 5. bl main(进 C 世界)
```

- **为什么第一步建栈**：C 语言需要栈（局部变量、函数调用），不设好栈就调用函数会崩。
- **为什么拷 .data、清 .bss**：C 规定已初始化全局变量要有初值（.data 拷入）、未初始化的为 0（.bss 清零），否则全局变量是垃圾值。
- **为什么特权模式**：启动代码要初始化硬件、建 MMU、写寄存器，只能在特权态做。

若跑 Linux：`UBoot → 内核汇编(head.S/stext)：建页表/MMU → start_kernel(C)`。

### 四、向量表为什么可以“重定位”

- 默认向量表在 `0x00000000`（Flash）。
- 用 **VBAR**（向量基址寄存器）重定位到 RAM 或高地址，便于**运行时改中断例程**、**升级固件**、或避开只读区域。
- Cortex-M 还通过 `SCB->VTOR` 重定位向量表。

### 五、易错点与常见坑

- **向量表没放对地址**：启动后中断/异常不触发、或跳到错误地方 → 卡死。
- **每个槽漏写跳转**：进异常后停在表里反复执行（死循环），而不是进 handler。
- **启动没建栈就调函数**：C 代码一调用就崩（栈未初始化），要先设 SP。
- **忘了清 .bss/拷 .data**：全局变量初值不对（垃圾值）。
- **中断里用错模式/影子寄存器**：现场没保存好，返回错乱。

### 六、常见追问与满分回答

**Q：为什么复位后是特权模式？**
A：因为启动代码要做特权操作（初始化硬件、建 MMU、写控制寄存器），用户态做不了；所以复位进入 SVC 管理等特权模式。（加分：等所有初始化完成，必要时再降级到用户态跑应用。）

**Q：为什么进 C 世界前要清 .bss、拷 .data？**
A：C 运行环境要求：已初始化的全局/静态变量有正确初值（.data 从 Flash 拷到 RAM），未初始化的为 0（.bss 清零）。否则全局变量是垃圾值，程序一开始就错。

**Q：FIQ 和 IRQ 区别？**
A：FIQ 优先级更高、有**更多影子寄存器**（可少保存现场、响应更快），适合硬实时/高优先级；IRQ 是普通中断，可被 FIQ 打断，需要保存更多现场。

**Q：向量表每个槽为什么是 4 字节、放 `ldr pc,=handler`？**
A：ARM 指令固定 4 字节；放一条跳转指令，把固定的入口“转发”到真正的处理函数（避免每个 handler 都必须是短指令，也便于模块化）。

> 📌 一句话记忆：**向量表=异常/中断的“入口地图”（固定偏移、4 字节跳转）；上电走复位向量→特权模式→建栈→拷data→清bss→进C；向量表可用 VBAR 重定位。**
