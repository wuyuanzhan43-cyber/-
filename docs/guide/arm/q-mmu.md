answer: |
  **MMU（内存管理单元）**是 CPU 里负责**虚拟地址→物理地址转换**与**内存保护**的硬件单元。它据**页表（page table）**把程序看到的**虚拟地址（VA）**映射到实际**物理地址（PA）**。
  作用：
  ① **地址映射**：给每个进程独立的虚拟地址空间，把它们映射到物理内存/外设，实现隔离。
  ② **内存保护**：按页设置权限（可读/可写/可执行、用户态/内核态），非法访问触发缺页/异常。
  ③ **按需分配/页式管理**：配合缺页异常，实现虚拟内存、共享内存、写时复制等。
  ④ **MMIO 映射**：把外设寄存器映射进地址空间，用户态/驱动用普通指针访问硬件。
  现代 ARM 用 **两级/多级页表（如 Armv7 两级、AArch64 四级）** 页表项含物理页号、权限、可缓存属性等；并配合 **TLB** 缓存最近的地址翻译，**cache** 缓存数据。
  没有 MMU 的 MCU（Cortex-M）通常直接访问物理地址，用 MPU（内存保护单元）实现有限的区域保护。
why: |
  MMU 是“**让多进程安全共享、高效虚拟化物理内存**”的基石。没有它，程序只能见到物理内存，无法做到地址隔离、按需分配与保护，一个进程就能把系统搞崩。
  对驱动而言，MMU 把**物理地址**映射为**虚拟地址**（ioremap/kmap），让内核统一用虚拟地址访问内存与外设。理解 VA↔PA 与页表层次，是内核内存管理、DMA、缓存一致性的基础。

## 深读

### VA → PA 转换

程序用虚拟地址，MMU 查页表得到物理地址：

```
VA  ──页表查找──▶ PA
  [虚拟地址]       [物理地址]
   + 权限/属性     + 物理页号、缓存属性
```

多级页表（AArch64 为 4 级：TCR/TTBR → T0/T1 页表）降低页表内存占用，只映射需要的页。

### 分页与页大小

- 常用页大小 4KB（也有 64KB/2MB 大页，减少 TLB 压力）。
- 每页一个页表项（PTE）：物理页号 + 权限（RWX）+ 用户/内核 + 缓存策略 + 有效位。
- **TLB**：缓存最近 VA→PA 翻译，避免每次都查页表；遇到上下文切换/改映射要 flush（`tlbi`/`__flush_tlb`）。

### 内存保护

- 内核空间 vs 用户空间：通过页表项的“用户态允许位”区分，用户态访问内核地址 → 缺页/权限异常。
- 数据/指令执行保护：NX（不可执行）位，防止堆栈执行注入攻击。

### MMIO（外设映射）

- 外设寄存器地址用 **ioremap/`__ioremap`** 映射成一个虚拟地址（`ioremap`），驱动就能 `readl/writel` 访问。
- 注意用 `__raw_` / `ioremap` 配合统一内存序，避免编译器/CPU 优化；往往还要 `memremap`/`devm_ioremap_resource`。

### MMU vs MPU

| 单元 | MMU（Cortex-A 等） | MPU（Cortex-M 等） |
|---|---|---|
| 功能 | VA→PA 转换 + 保护 | 仅区域保护，无地址转换 |
| 页表 | 多级页表 | 区域寄存器（数/十几块） |
| 用途 | 多进程虚拟内存 | 简单 RAM/Flash 分区保护 |

### 常见追问

- 为什么虚拟内存能“超卖”？——按需分页 + 缺页 + 页面置换（LRU 等），同一物理页可被多个进程共享（共享库、写时复制 COW）。
- 进程切换为什么要 flush TLB？——不同进程的 VA→PA 映射不同，TLB 缓存旧翻译；也可用 ASID 避免全 flush。
- 驱动里怎么访问物理寄存器？——`ioremap` 得到虚拟地址后用 `readl/writel`。

> 📌 一句话记忆：**MMU 靠页表把 VA 映射到 PA 并提供保护；TLB 缓存翻译、ioremap 映射外设；Cortex-M 用 MPU 只做区域保护。**
