answer: |
  **大端（Big-Endian）**：把多字节数据的**高位字节放在低地址**（“大头/最高位在前”）。
  **小端（Little-Endian）**：把**低位字节放在低地址**（“小头/最低位在前”）。
  例如 `0x12345678` 存到地址 `0x1000`：
  - 小端：`78 56 34 12`（低地址存低位）
  - 大端：`12 34 56 78`（低地址存高位）
  大部分 ARM/x86 默认**小端**；网络标准采用**网络字节序（大端）**；嵌入式在**跨端通信、协议解析、寄存器/Flash 布局**时必须显式处理字节序，常用 `__builtin_bswap16/32`、`htons/ntohl`、`be16toh` 等转换。
why: |
  不同 CPU/协议对“多字节数字在内存里怎么排”约定不同。若不转换，同一份数据在不同端序的机器上就会被读成不同数值，导致**协议解析错误、结构体/寄存器错位、Flash/文件损坏**。
  嵌入式里常把“**异构芯片之间、MCU 与 PC 之间、网络报文**”的字节序统一起来（如固定用网络字节序大端），在发送/接收时做显式转换，避免隐式错误。

## 深读

### 直观记忆

```
内存地址递增 →  0x1000  0x1001  0x1002  0x1003
小端:            78      56      34      12      (低位在前)
大端:            12      34      56      78      (高位在前)
```

数字 `0x12345678`：`12` 是最高位（MSB），`78` 是最低位（LSB）。

### 为什么有的是小端

- **小端**：低位在低地址，转成 16/32 位时**移位/取低位**更顺手，与 x86/多数 ARM 的指令实现契合，性能好。
- **大端**：人类阅读与网络报文更直观（高字节在前），网络协议（TCP/IP）约定网络字节序为大端。

### 在代码里怎么判断/测试

```c
int x = 0x12345678;
unsigned char *p = (unsigned char*)&x;
if (*p == 0x12) printf("big-endian\n");
else             printf("little-endian\n");
```

### 何时必须处理

| 场景 | 为什么 |
|---|---|
| 跨芯片/跨端通信（MCU↔PC、异构 SoC） | 端序不一致会读错数值 |
| 网络报文（socket、TCP/UDP） | 网络字节序是大端，需 `htons/ntohl` |
| 二进制文件/Flash 镜像 / 固件格式 | 固定字节序才可移植/兼容 |
| 共享内存 / 结构体跨进程、跨端 | 必须统一或逐字段转换 |

### 常用转换函数

- **POSIX/网络**：`htons`、`htonl`、`ntohs`、`ntohl`（host↔network，network=大端）。
- **Linux**：`be16toh`/`be32toh`、`le16toh`、`htobe16`/`htole16`。
- **编译器内置**：`__builtin_bswap16/32/64`。
- **DIY**：手写字节交换或用 union。

### 常见追问

- 大小端和位的顺序（bit order）区别？——大小端按**字节/字**划分；比特序在**串行总线/位域**里另说，别混淆。
- 为什么网络用大端？——历史与可读性，RFC 规定网络字节序为大端。
- 端序对结构体对齐有影响吗？——没有，端序讲“字节排列”，对齐讲“地址对齐”；但跨端传输结构体时两者都要小心。

> 📌 一句话记忆：**大端=高字节在低地址（`12 34`），小端=低地址存低位（`78 56 34 12`）；跨端/网络通信务必显式转换。**
