  **ARM（32 位）寄存器**：
  - **R0–R15**：通用寄存器；**R13=SP**（栈指针）、**R14=LR**（保存返回地址）、**R15=PC**（程序计数器）。
  - **CPSR**（当前程序状态寄存器）：条件标志（N/Z/C/V）、中断屏蔽（I/F）、模式位、Thumb 位。
  - **SPSR**（备份状态寄存器）：进入异常时**保存被中断的 CPSR**，恢复时用。
  **工作模式**：User（用户）、FIQ、IRQ、SVC（管理，复位/系统调用进入）、ABT（数据中止）、UND（未定义）、System（系统，与 User 同寄存器组但特权）。
  **要点**：**异常切模式**，进入时**自动保存 CPSR→SPSR_<mode>、返回地址→LR_<mode>**，且每种异常使用**不同的影子寄存器（banked）**（LR、SPSR、部分通用寄存器），避免互相覆盖。
  **AArch64（64 位）**：X0–X30 + SP + PC + 状态（NZCV）+ 特权级 **EL0–EL3**（用户/内核/虚拟化/固件）。

## 深读

### ARM 32 位核心寄存器

| 寄存器 | 作用 |
|---|---|
| R0–R12 | 通用寄存器（可作参数/局部） |
| R13 (SP) | 栈指针 |
| R14 (LR) | 返回地址（BL 时保存） |
| R15 (PC) | 程序计数器 |
| CPSR | 状态：条件位/中断屏蔽/模式位 |
| SPSR | 备份 CPSR（异常进入时保存） |

### 工作模式

| 模式 | 说明 |
|---|---|
| User | 用户态，权限受限 |
| FIQ/IRQ | 中断（快速/普通），各有影子寄存器 |
| SVC | 管理（复位/系统调用） |
| ABT/UND | 数据中止/未定义 |
| System | 与 User 同寄存器但特权 |

- 异常进入时**切换到对应特权模式**，获得**独立 LR/SP/SPSR**（影子寄存器），处理完恢复。

### 异常时的自动保存

- 进入异常：`CPSR → SPSR_<mode>`、返回地址 `→ LR_<mode>`、`PC → 向量`、模式切换。
- 返回：`MOVS PC, LR` / `SUBS PC, LR, #4`（IRQ 因流水线差 4）/ 用 `LDM`/`RFE` 恢复并弹栈。
- **栈**：各模式有**独立栈**（`SP_<mode>`），避免中断/任务栈冲突。

### AArch64 与特权级

- 64 位用 X0–X30、SP、PC，状态在 NZCV 等。
- 特权级 **EL0/EL1/EL2/EL3**（用户/内核/虚拟化/固件），级别高 → 权限大。

### 常见追问

- 为什么异常要保存 CPSR 到 SPSR？——恢复现场时需要还原被中断处的状态。
- 为什么各模式有不同 LR/SP？——避免中断处理破坏被中断任务的栈/返回地址。
- Cortex-M 与 Cortex-A 模式差异？——M 只有线程/处理两态（简单）；A 多模式，配合 MMU 跑 Linux。

> 📌 一句话记忆：**ARM32 核：R0-15(SP/LR/PC)+CPSR/SPSR；多工作模式(User/SVC/IRQ/FIQ...)，异常切模式并自动存 CPSR→SPSR、返回→LR；各模式独立栈。**
