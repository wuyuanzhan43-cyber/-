## 深读

### 进入异常（硬件自动）

1. `SPSR_<mode> = CPSR`
2. `LR_<mode> = 返回地址`（流水线导致偏移）
3. `PC = 异常向量`
4. 切到特权模式（换栈 `SP_<mode>`）

### 各类异常的返回地址偏移

| 异常 | LR 对应 | 返回修正 |
|---|---|---|
| IRQ/FIQ | LR-4 | `SUBS PC,LR,#4` |
| SVC/SWI | LR | `MOVS PC,LR` |
| Prefetch Abort | LR-4 | 需重取 |
| Data Abort | LR-8 | 具体看原因 |
| Reset | — | 重新启动 |

- **为什么 IRQ 是 LR-4**：ARM 流水线预取，进入 IRQ 时 PC 已在 L+8，LR 存的是 L+4，返回需 `-4`。

### 现场保护/恢复

```asm
stmdb sp!, {r0-r12, lr}   ; 压栈保护现场
... 处理 ...
ldmia sp!, {r0-r12, pc}^  ; 弹栈恢复+返回(^=恢复SPSR到CPSR)
```

- 压栈保存**用到的寄存器**，弹栈恢复；`^` 让 SPSR 恢复进 CPSR。
- 也可用 `RFE`/`MOVS PC,LR` 等。

### Cortex-M 的简化

- **硬件自动压栈**一部分寄存器（R0-R3、R12、LR、PC、xPSR）到当前栈。
- **向量化**：直接跳向量表中的 handler。
- **EXC_RETURN**：`LR` 存特殊值（0xFFFFFFFx），返回时由硬件恢复现场并据标志选栈。
- 处理函数必须**可重入、短**。

### 常见追问

- 为什么 IRQ 返回要 LR-4？——ARM 流水线预取，进入时 LR=返回地址+4。
- SPSR 干什么？——保存被中断的 CPSR，恢复现场时还原。
- 为什么要保存现场（压栈）？——异常可能用到通用寄存器，保存以免破坏被中断任务的状态。
- Cortex-M 为什么要硬件自动压栈？——省去手动保存，快速、错误少。

> 📌 一句话记忆：**异常=存 CPSR→SPSR、返回→LR、PC→向量、切特权模式；处理时压栈现场；返回用 MOVS/SUBS PC,LR 或 LDM^ 恢复；注意 IRQ 用 LR-4。**
