answer: |
  **环形缓冲区**：用**固定大小数组 + 头（写/入队）尾（读/出队）索引**实现，索引**回绕**（取模），用于**FIFO 数据缓冲**。
  核心：
  - **入队**：写到 `head` 位置，`head = (head+1) % N`；**出队**：读 `tail`，`tail = (tail+1) % N`。
  - **判定空/满**：`head == tail` 为空；留一个空位（`(head+1)%N == tail` 为满）或用计数/标志区分满。
  - **单生产者-单消费者**时，可用**无锁**（只要各自只改自己的索引，配合内存屏障）。
  - 优点：**O(1)** 读写、无动态分配（无碎片）、复用固定缓冲。
  常用于**串口收发、音频、DMA、网络、日志**等数据流缓冲。
why: |
  它解决“**一边在产生、一边在消费，且速度不匹配**”的数据流问题：用固定数组回绕复用，**无需频繁搬移、无动态内存碎片**，且能实现**无锁**（单写单读），非常契合嵌入式**中断/任务与主循环**之间的数据交接（如串口中断收数据，任务/主循环取走处理）。

## 深读

### 概念图

```
[ _ | _ | D | D | _ | _ ]     head=3(写), tail=1(读)
          ^tail    ^head
```

### 常用实现要点

```c
typedef struct {
  uint8_t buf[N];
  volatile uint16_t head;   // 写索引（生产者）
  volatile uint16_t tail;   // 读索引（消费者）
} ring_t;

int ring_empty(ring_t *r){ return r->head == r->tail; }
int ring_full(ring_t *r){ return (uint16_t)(r->head + 1 - r->tail) % N == 0; }
int ring_put(ring_t *r, uint8_t c){
  if (ring_full(r)) return -1;   // 满
  r->buf[r->head] = c;
  r->head = (r->head + 1) % N;
  return 0;
}
int ring_get(ring_t *r, uint8_t *c){
  if (ring_empty(r)) return -1;  // 空
  *c = r->buf[r->tail];
  r->tail = (r->tail + 1) % N;
  return 0;
}
```

### 关键点

- **回绕**：索引取模（`% N`），或用 `& (N-1)`（N 为 2 的幂更快）。
- **区分满/空**：常用的“留一空位”法最简单（上面 `ring_full` 用“相差 1”判满）；也可用计数/标志/填充值，但“留空位”最防歧义。
- **单写单读无锁**：生产者只改 `head`，消费者只改 `tail`，各自在**自己的位置读写**，配合 `volatile`（防编译器缓存）与必要的内存屏障/关中断即可做到无锁（尤其 `head`/`tail` 用 `volatile`，且在中断与任务之间用关中断保护更稳）。

### 嵌入式典型应用

- **串口/UART 收发**：中断里 `ring_put`，任务/主循环 `ring_get` 处理。
- **DMA/ADC**：DMA 写缓冲（或半满/全满中断），再读出处理。
- **音频/网络**：固定大小缓冲循环回放/发送。
- **日志**：循环写最近 N 条。

### 为什么比“搬移”好

- 读/写 **O(1)**，不搬移元素。
- 数组固定 → **无动态内存碎片**，内存可预测。
- 单写单读 → **无锁**，实时性与确定性好。

### 常见追问

- 为什么要留一个空位？——避免 `head==tail` 既表示空又表示满的歧义；留一空位是经典做法。
- 单生产者单消费者能保证无锁吗？——可以，只要各自只改自己的索引、用 `volatile` 加内存屏障/关中断保护，避免编译/CPU 乱序导致读到不一致。
- 容量/N 为什么常用 2 的幂？——可用 `& (N-1)` 代替 `% N`，更快。
- 满/空怎么判比较稳？——留空位法最稳；用计数器也行但要配合索引一致性判断。
