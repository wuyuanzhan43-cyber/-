answer: |
  数组：**内存连续、支持 O(1) 随机访问**，但插入删除为 O(n)（要搬移元素），大小固定（或需动态扩容）；
  链表：**内存不连续、不能随机访问**，访问第 k 个需 O(n)，但插入/删除只需改指针 O(1)（已知位置时），大小灵活。
  嵌入式取舍：数据量小、需频繁随机访问→数组/静态数组；需频繁增删、大小动态、节点分散→链表；有实时/确定性要求时，**静态分配**更受欢迎（避免动态内存碎片与不确定性）。
  单链表反转经典题：用三个指针 `prev/curr/next` 迭代，遍历一次把每个节点的 `next` 反向，O(n) 时间 O(1) 空间；也可递归，但递归有栈深度风险。
why: |
  两者是「连续存储+随机访问」与「离散存储+指针跳转」的根本权衡。数组靠偏移算地址，链表靠指针找下一个。
  嵌入式里为什么偏爱数组/静态分配：避免 malloc/free 导致的内存碎片与不确定性延迟，内存是按地址连续映射的，数组行为更可预测、对 DMA/缓存友好。

## 深读

### 复杂度对照

| 操作 | 数组 | 链表 |
|---|---|---|
| 随机访问 | O(1) | O(n) |
| 尾部插入 | O(1)（均摊，需扩容） | O(1)（若持有尾指针） |
| 中部插入/删除 | O(n)（搬移） | O(1)（已知节点，改指针） |
| 查找 | O(n) | O(n) |
| 内存 | 连续、紧凑、预分配 | 每节点+指针开销，分散 |

### 单链表反转（手撕模板）

```c
struct Node *reverse(struct Node *head) {
  struct Node *prev = NULL, *curr = head, *next;
  while (curr) {
    next = curr->next;   // 先保存下一个
    curr->next = prev;   // 反向
    prev = curr;         // 前移 prev
    curr = next;         // 前移 curr
  }
  return prev;           // 新的头
}
```

要点：**三指针**、循环里**先保存 next** 再改 `curr->next`，否则断链。

### 嵌入式为什么更常用“数组/静态分配”

1. **无内存碎片**：动态 `malloc/free` 在长期运行中会导致堆碎片，实时系统可能因分配失败而崩溃。
2. **确定性**：静态数组访问时间稳定，适合实时/硬实时约束。
3. **缓存/DMA 友好**：连续内存对缓存行、DMA 传输更高效。
4. **可预测性**：大小在上电前就确定，便于预算 RAM。

### 什么时候还是用链表

- 数据量、数量**不可预估**，且增删频繁（如动态任务链表、就绪队列）。
- 常常需要**头插/尾插/删除任意节点**。
- 配合**内存池/静态分配**的链表，可兼顾“灵活”与“无碎片”。

### 相关高频变种

- **快慢指针**：找链表中点、判断环（Floyd 判环）。
- **合并两个有序链表**：双指针 + 哨兵。
- **循环队列 / 环形缓冲区**：用数组 + 头尾索引，嵌入式串口/音频缓冲常用。

> 📌 一句话记忆：**数组赢在“随机访问与连续内存”，链表赢在“灵活增删与动态大小”；嵌入式多选数组/静态分配，链表配内存池。**
