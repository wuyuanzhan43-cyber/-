answer: |
  **三次握手（建立连接）**：客户端与服务端**确认双方都能收发**、同步序列号。
  1. 客户端发 **SYN**（同步，含初始序列号）。→ `SYN_SENT`。
  2. 服务端回 **SYN+ACK**（确认收到的 SYN，并同步自己的序列号）。→ `SYN_RCVD`。
  3. 客户端发 **ACK**（确认）。→ 双方 `ESTABLISHED`。
  为什么三次：**确认双方的发送/接收能力 + 同步序列号**。两次不够（服务端无法确认客户端能收自己的 SYN）；四次浪费。
  **四次挥手（释放连接）**：因 TCP 是**全双工**，需**双方各自**关闭。
  1. 主动方发 **FIN**。→ `FIN_WAIT1`。
  2. 被动方回 **ACK**。→ `FIN_WAIT2`（主动方）。
  3. 被动方数据发完，发 **FIN**。→ `CLOSE_WAIT`/`LAST_ACK`。
  4. 主动方回 **ACK**。→ `TIME_WAIT`（等待 2MSL），彻底关闭。
  为什么四次：**双向分开关闭**——一方 FIN 只表示“我发完了”，对方可能还有数据要发，所以另一方也要 FIN。
  状态机：`LISTEN → SYN_SENT → SYN_RCVD → ESTABLISHED → FIN_WAIT1/2 → TIME_WAIT/CLOSE_WAIT → CLOSED`。
why: |
  这是**可靠连接的建立/关闭协议**，也是网络面试“必考”题。三次握手保证**同步序列号、双方确认可达**，避免“失效的连接请求”误导服务器；四次挥手体现 **TCP 全双工**，双方各自关闭。
  理解它才能定位**连接建立慢、TIME_WAIT 堆积、半关闭/CLOSE_WAIT 泄漏**等 socket 服务器常见问题（嵌入式网络、上位机、板端通信都适用）。

## 深读

### 三次握手（为何三次）

```
客户端                    服务端
  |---- SYN(seq=x) ------>|
  |<--- SYN+ACK(seq=y,ack=x+1) ----|
  |---- ACK(ack=y+1) ---->|
```

- 第一次：客户端说“我想连，seq=x”。
- 第二次：服务端确认“收到你的 seq，我的 seq=y”。
- 第三次：客户端确认“收到你的 seq”，连接建立。
- **两次不够**：无法确认客户端能收到服务端的 SYN（第三次 ACK 用于确认双方收发都 OK），并同步序列号；**第三次也消耗一个包**避免“失效请求”重传误导。

### 四次挥手（为何四次）

```
主动方                         被动方
  |---- FIN --------------->|
  |<--- ACK ----------------|
  |<--- FIN ----------------|  (对方数据发完后再 FIN)
  |---- ACK --------------->|
主动方进入 TIME_WAIT(2MSL) 后关闭
```

- TCP **全双工**：一方的 FIN 只表示“自己不再发”，另一方仍可发（或还没发完）。
- 所以：一方 FIN + 对方 ACK，再对方 FIN + 已方 ACK，共四次。
- **TIME_WAIT**：主动关闭方等待 2MSL，保证最后的 ACK 重发与旧报文失效，避免新连接被旧报文干扰。

### 状态机速记

`LISTEN`（监听）→ 建立时 `SYN_SENT`/`SYN_RCVD` → `ESTABLISHED` → 关闭时 `FIN_WAIT1/FIN_WAIT2`、`CLOSE_WAIT`、`LAST_ACK`、`TIME_WAIT` → `CLOSED`。

### socket 服务器常见问题

- **TIME_WAIT 堆积**：大量短连接主动关闭方遗留，可用 `SO_REUSEADDR`/调优。
- **CLOSE_WAIT 泄漏**：进程没正确 `close()`（对方发 FIN 但本地没关），常见于**没处理对端断开**。
- **连接建立慢**：可能与握手/拥塞/超时有关。

### 常见追问

- 为什么三次不是两次/四次？——两次无法确认双方收发+同步序号；四次浪费（第二次可顺带同步）。
- 为什么四次挥手？——全双工，双方各自关闭；一方 FIN 不代表对方也发完。
- TIME_WAIT 干什么？——等 2MSL，保证最后 ACK 与旧报文失效。
- 半关闭（close_wait）怎么排查？——看应用是否处理了对端 FIN 并 close 套接字。

> 📌 一句话记忆：**三次握手=同步序号+确认双方可达；四次挥手=全双工各自关闭；TIME_WAIT=等 2MSL 防旧报文干扰新连接。**
